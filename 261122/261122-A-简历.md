### 大模型智能体复杂任务长程规划技术研究（上海市专项，2025SHZDZX025G07） | 硕士研究生 | 2026.03 – 2026.10

#### 项目一：函数级编程任务合成与等价性 verifier 构建
**项目背景**：编程 Agent 的 SFT、RL 与评测都需要大量可执行、可自动判分的任务；由模型自造题时，期望输出也由模型预测，非平凡函数的期望值错误无法核查。项目从 210 余个开源 Python 仓库抽取约 4.6 万个函数，为每个函数合成以参考实现为基准的判分测试与自然语言规格，产出 1.4 万条逐条经沙箱验证的任务，测试一次执行通过率由 58% 提升至 74%；任务供项目三的函数级 RL 阶段与评测使用。本人负责等价性判分与依赖切片两个模块，参与插桩采集与多轮反馈生成的实现。  
**参考实现作 oracle 的等价性判分**：测试不写字面期望值，只断言候选实现与参考实现在同一组输入下的返回值、异常类型与消息一致，替代由模型预测期望输出的写法，消除期望值写错造成的误判。每条新测试先在参考实现上执行，未通过即判为测试自身缺陷并拦截，拦截约 7%；同批 800 个函数对照，抽检缺陷率由 28% 降至 1.9%。  
**语句依赖图与调用图的依赖切片**：从目标函数出发，在语句级依赖图上收集被引用的定义，再用 PyCG 调用图补全跨文件调用，只把执行闭包交给合成模型，替代整仓或整文件供给，去掉同名无关函数的干扰。切片深度取 3 层，96.5% 的函数无缺失符号；合成上下文均值由约 2.4 万 token 降至约 9.6 千 token。  
**运行时插桩的真实调用样本采集**：在目标函数上挂 hook，记录真实调用的入参（展开默认值）、返回值、类型与调用者，超长值保留首尾各 90 字符，随合成请求附上最近几条记录，使测试输入取自真实调用，替代模型凭直觉构造的典型输入。有副作用的函数不启用采集；开启后边界输入覆盖相对提升约 20%，一次执行通过率再提升 2pp。  
**执行报错与未覆盖分支的多轮反馈**：一次生成难以同时满足可执行与覆盖率，改为逐轮只处理未达标函数：执行报错时回传异常栈与出错行，覆盖不足时回传未覆盖分支的位置与条件表达式，引导模型针对具体路径补用例。终止条件为分支覆盖率与达标函数占比均不低于 0.8；覆盖率达标率由首轮 45% 提升至第三轮 87%。  
**docstring 与已通过测试的规格提炼**：规格不照抄 docstring，改为以 docstring、签名与已通过的等价测试为材料重写，测试验证过的边界与异常行为直接成为规格中的示例与约定。任务包对模型只暴露签名与规格，判分测试隐藏；训练与评测集按仓库维度切分，并过滤与公开基准重叠的仓库，避免模型凭记忆源码得分。

#### 项目二：仓库级编码 Agent 长轨迹的失败归因与增强蒸馏 SFT
**项目背景**：仓库级编码任务要求 Agent 按整库规格在空工作区从零实现一个 Python 库，单条轨迹上百轮工具调用、常触发 context compaction；低质轨迹进入 SFT，会让模型学到连续写改不验证、未执行测试即宣告完成两类行为。项目对团队采集的 2,700 余条轨迹做导出校验、失败归因与过程监督、压缩恢复两类增强，在 Qwen3-32B 上蒸馏 SFT 后，盲改次数下降 38%、接口签名错位率下降 62%、工具报错率减半，checkpoint 作为项目三的 RL 起点。本人负责过程监督注入与压缩恢复样本合成，参与轨迹导出、失败归因与配比实验。  
**stream-json 轨迹的消息聚合与配对校验**：rollout 日志按 stream-json 逐块输出，同一轮的思考、文本与多次工具调用分散在多条记录里，直接转换会产生重复轮次与孤立的工具结果。导出时按 message id 合并同轮内容块，为全部消息重建全局索引，再校验每个 tool_call id 与返回结果一一对应，校验失败的轨迹整条剔除，约占 3%；后续归因与注入都依赖该索引定位到具体轮次。  
**失败断言到出错动作的三层归因**：低分轨迹只看总分无法区分环境问题与模型行为问题。先从判分输出取失败断言与报错位置，再沿全局索引回溯最后一次改动该文件的 Write 或 Edit，定位引入错误的轮次，最后归入九类失败模式，按出现频率与命中样本均分两列统计。归因显示自测与判分验证方式不一致覆盖几乎全部低分轨迹；未完成类出现次数少，但命中样本均分不足一成。  
**关键决策点的过程监督注入**：在成功轨迹的完成宣告、报错转修复、测试执行等九类决策点前置写入一段英文状态回顾，只写已完成什么、还差什么，不给操作指令，让模型学会判断任务状态，替代逐轮打结构化阶段标签。完成宣告点必注入，其余按调和平均式预算与最小间隔分配，平均每条 3 至 4 处，注入只改 content、不动 tool_calls 配对；训练后宣告完成前未执行任何测试的轨迹占比由 23% 降至 9%。  
**九段摘要模板的压缩恢复样本合成**：压缩后的模型常凭记忆直接编辑文件，或反复重读同一批文件。合成时在累积约 5 万 token 后、紧邻下一次重读或测试的轮边界切分，后段上下文改由九段有损摘要重建，覆盖主要诉求、文件与代码段、错误与修复、待办与下一步，恢复引导要求先确认再修改，且不得出现压缩、摘要等自指词。一批 130 余段样本工具调用配对零错位，学生最长盲改由约 8 轮降至约 4 轮。  
**增强样本配比扫描与长序列蒸馏 SFT**：学生全参 SFT，YaRN 把上下文扩到 128K，只对 assistant 消息计 loss，训练集由筛选后的成功轨迹与两类增强样本组成。增强样本占比扫描四档，超过三成后同类状态下的回复在两种风格间摇摆，取 25%；与初版数据同超参对照，盲改次数下降 38%，总分差异处于噪声量级。

#### 项目三：编码 Agent 长程 agentic RL 的 context compaction 与 step 级信用分配
**项目背景**：SFT 只模仿成功轨迹，模型在百轮级仓库任务中报错后反复同一处修改、压缩后丢失任务状态，终局 reward 又无法把信用分到具体步骤。以项目二的 Qwen3-32B SFT checkpoint 为起点，先在项目一的函数级任务、再在仓库级任务上做多轮 GRPO，重写 reward、compaction 条件下的样本构造与 step 级 advantage；96 个 held-out 仓库级任务的平均测试通过率由 36.2% 提升至 45.3%。本人负责 compaction 分段训练与 step 级 advantage，参与 reward 设计与沙箱容器池。  
**函数级到仓库级的两阶段 curriculum**：起点模型在仓库级任务上多数组的轨迹全部得 0 分，直接训练几乎没有有效梯度。先在项目一的函数级任务上训练 120 步，再切换到仓库级任务，替代直接在长任务上训练；两阶段都按当前 checkpoint 的采样通过率只保留部分通过的题，阶段二开训时零方差组占比由 52% 降至 31%。  
**隐藏测试通过率 reward 与篡改检测**：全部通过才得分的 reward 过于稀疏，训练中期策略开始在包内写入 conftest 文件，或检测 pytest 环境后跳过实际逻辑。reward 改为新容器中隐藏测试的通过比例，并对最终代码做静态扫描，命中篡改规则的轨迹记 0 分，替代只看测试结果。篡改轨迹占比由 4.7% 降至 0.3%。  
**context compaction 分段轨迹的 advantage 共享**：rollout 窗口为 64K，超过阈值时由策略自己写九段摘要后继续，一条轨迹被切成多段训练序列。各段共享整条轨迹的 advantage，摘要 token 同样计入 loss，按整条轨迹的 token 总数归一，替代只训练最后一段。触发压缩的任务子集平均通过率由 27.4% 提升至 35.1%。  
**规范化报错 anchor 的 GiGPO step 级分组**：轨迹级 advantage 无法区分报错后哪一次修改有效。pytest 报错去掉路径、行号、地址与字面值后作为 step 级 anchor，同一报错状态下的不同修改动作进入同组比较，替代按原始观测文本分组。单元素组占比由 93% 降至 52%，平均通过率提升 1.4pp。  
**沙箱容器池的预热与快照复位**：每条仓库级 rollout 都要新建容器并安装依赖，初始化慢且约 3.1% 失败重试。按下一步已确定的任务预构建依赖镜像层、维护预热容器池，rollout 从写时复制的快照启动，结束后丢弃可写层复位，判分仍在新建的官方镜像容器中执行，替代每条轨迹从头构建环境；单步耗时由 41 分钟降至 35 分钟。

#### 项目四：多领域代码专家的多教师 on-policy 蒸馏合版
**项目背景**：长程 RL 后的模型在仓库级任务上提升，但数学、指令遵循与通用对话相对起点回退，各专项能力又分散在不同 checkpoint 中，无法同时部署。按统一 SFT、八个领域 RL 教师、教师准入、多教师 on-policy 蒸馏的流程合成一个 Qwen3-32B 学生，学生每题采样一条、按领域路由教师计算 reverse KL：八项评测的教师增益平均恢复 79.2%，最弱的指令遵循恢复 72.1%，八项均分由 55.42 提升至 60.77。本人负责教师池合并与拆分、教师可靠性加权与领域 advantage 归一，参与分域预热与路由校验。  
**跨域能力矩阵的教师池合并与拆分**：按领域一对一设教师时，函数级生成与竞赛编程两个教师在对方领域互为次优，服务成本翻倍而信号几乎重复。先测候选教师在全部领域验证集上的能力矩阵，reward 来源相同且对方领域分差落在噪声带内才合并，子类表现分化时拆分，替代按经验划分领域；十个候选领域定为八个教师，教师服务卡时减少 19%。  
**低重合领域的分域预热 SFT**：仓库级教师来自另一条 RL 路线，与学生起点在摘要格式与工具调用写法上不同，学生采样的 token 多落在教师低概率区域。准入时测学生与各教师的 reverse KL 与 top-20 重叠率，只对不达标的仓库级与工具调用两个领域按重叠率缺口采集教师样本做短步数 SFT，替代全领域统一预热；两个领域的重叠率由 0.66 与 0.72 升至 0.80 与 0.81。  
**分段样本的路由校验与 log-prob 重算**：agent 领域的轨迹分段后新样本没有继承领域标签，被默认路由到冻结起点，约 6.8% 的仓库级分段受错误监督且不报错。领域标签与教师版本从采样、分段、打分到 loss 逐级保留，缺失即停训，教师版本变化后重算 log-prob，替代缺失时默认路由；仓库级恢复率由 79.1% 提升至 85.7%。  
**教师校准位移的 token 级可靠性加权**：通过准入的教师仍有局部缺陷，issue 修复教师偏好重复执行同一条测试命令，会经蒸馏传给学生。以冻结起点为共享参照，按教师 log-prob 位移分桶，统计各桶 token 来自通过样本的提升倍数作为可靠性，token 权重取其平方，替代对教师信号一视同仁；学生重复调用率由 7.6% 降至 4.0%。  
**领域滑动标准差归一的 token 级 advantage**：长程 agent 领域少数 token 的 log-prob 差远大于短回复领域，同一 batch 中短回复领域的梯度被淹没。各领域的 token 级 advantage 除以本领域按 token 数加权的滑动标准差，替代全 batch 统一尺度；指令遵循的恢复率由 60.5% 提升至 72.1%。

#### 项目五：翻译模型 GRPO 的 MQM 多维 reward 与 LLM judge 校准
**项目背景**：中英翻译业务反馈集中在术语误译，单一 LLM judge 打分做 RL 时，reward 被流畅度主导，术语错误不降反升，属于 reward hacking。在 Qwen3-30B-A3B 的 LoRA SFT 模型上做 GRPO，重写 judge 判分协议、reward 构成与组内 advantage；790 条业务评测集平均 MQM penalty 由 1.1759 降至 1.0190，Pairwise 对比显著优于 SFT 起点。本人负责 judge 协议设计与校准、reward 组合与训练诊断，参与 RL 数据治理与业务评测。  
**Pointwise MQM 与位置交换 Pairwise 的混合 judge**：judge 只标错误位置与严重度，扣分由程序按严重度计算，替代 judge 直接给分造成的尺度漂移。两条译文分差小于阈值时转 Pairwise，并交换左右位置各判一次，结论不一致记平局。在 600 余条双人金标上，与人工一致率由 57% 提升至 80%。  
**五维 MQM 与重复、长度惩罚的 7 维 reward**：加权和 reward 中流畅度最易优化，策略把分数堆在流畅度上，术语错误不降。reward 改为准确、术语、流畅、风格、语境五个 MQM 维度分别计扣分，另加重复与长度两项惩罚，术语维度不与其他维度相互抵消。每百句术语错误由 4.2 降至 3.1。  
**参考译文质量锚点的组内 advantage 修正**：组内相对 reward 只比较同组 8 条译文，整组质量都差时最好的一条仍得到正 advantage。每组匿名混入一条强模型参考译文作锚点，锚点分经 batch 内 whitening 后作为绝对质量基准，组内 advantage 叠加相对锚点的修正项，替代纯组内比较。  
**重复与超长输出的 hard mask 与梯度隔离**：重复生成与超长输出的 judge 分数不可靠，计入组均值会扭曲其余样本的 advantage。这类样本整条屏蔽 loss，并从组均值与标准差的计算中剔除，逐步核对其梯度贡献为零。重复输出占比由 3.4% 降至 0.6%。  
**Qwen judge 与 GPT-5 的一致性诊断与 checkpoint 选点**：训练用自部署 judge 降低成本，需确认它与强 judge 的排序一致。在 96 个真实 rollout 组上，两者 penalty 相关系数约 0.725，约 15% 的组最优候选不一致，因此选点改由 GPT-5 Pointwise 与 Pairwise 双口径判定，替代按训练 reward 选点。  

#### 项目六：数学推理 RLVR 的 entropy 带宽约束与难度加权 advantage
**项目背景**：教育场景的数学解题要求答案与解题步骤都正确，蒸馏推理模型在 RL 中出现中英混杂输出，动态采样又浪费大量已生成样本。在团队 14B 推理模型上以 DAPO 做两阶段 RLVR，改造判分、entropy 约束、advantage 与样本调度；内部 K12 评测集准确率由 84.1 提升至 91.7。本人负责多小问 judge 判分与校准，参与 entropy 约束、难度加权与样本复用的实现与消融。  
**规则验证与逐小问 judge 的分流判分**：格式错误或thinking 与答案出现重复的输出直接不进正确性判分，替代把格式加进加权 reward。单一表达式答案走规则验证，多小问题目拆成逐小问由 judge 判定答案与步骤，全部正确才得分。judge 假阳性率由 6.3% 降至 1.7%。  
**entropy 带宽约束的 hinge 正则**：单向 entropy bonus 会放大中英混杂。loss 中只对落在区间 [0.45, 0.65] 之外的 entropy 施加 hinge 惩罚，区间内不干预，替代固定目标值的双向拉拽。语种混杂回答占比由 6.8% 降至 0.9%。  
**组通过率峰值加权的 advantage**：全部题目等权时，模型偶尔能做对的中等难度题信号被稀释。advantage 乘以随组通过率变化的权重，在通过率约 0.25 处取峰值 1.6，两端回落到 1，并去掉长度归一化，替代按静态难度排 curriculum。准确率提升 2.4。  
**溢出样本单步复用与截断重要性比**：动态采样为凑满 batch 过采样数倍，溢出的合格样本被丢弃。溢出样本只保留到下一步，并对 token 级重要性比截断到 2 后计入 loss，替代直接丢弃，过采样倍数由 4.1 降至 2.3。
