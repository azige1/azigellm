## 项目之间的衔接

1. 项目一产出函数级任务包，作为项目三阶段一的 RL 任务。
2. 项目二的 `task_builder` 构建仓库级任务，作为项目三阶段二的 RL 任务；项目二蒸馏 SFT 得到的 Qwen3-8B checkpoint 是项目三的起点。
3. 项目三的环境、判分与工具直接调用项目一、二的包，安装项目三前先以可编辑方式安装项目一、二。
4. 项目三的 RL checkpoint 是项目四仓库级实现领域的教师；项目四仓库级领域的 rollout 复用项目三的 agent loop 与沙箱容器池；项目二的轨迹数据并入项目四的统一 SFT。
5. 项目五、项目六与其他项目没有代码依赖，可以单独运行。

项目一至四共用 Qwen3 同族模型与 tokenizer，项目四的逐 token 蒸馏依赖这一点，换模型时四个项目要一起换。

## 建议的运行顺序

1. 项目一：按项目目录说明文档的「流程」一节执行，任务包输出到工作区的 tasks 目录。
2. 项目二：按「运行步骤」一节完成任务构建、轨迹采集、增强与 SFT，得到 Qwen3-8B checkpoint。
3. 项目三：`pip install -e ../项目1-函数级任务合成 -e ../项目2-长程轨迹增强蒸馏 -e .`，先跑阶段一（函数级），再跑阶段二（仓库级）。
4. 项目四：训练或准备各领域教师（仓库级教师直接取项目三的 checkpoint），完成教师池归并、准入与分域预热后做多教师蒸馏。
5. 项目五、项目六：按各自目录说明文档执行。

每个项目的 `experiments` 目录写明各组实验的目的、命令、预期过程、预期结果与排查顺序。`tests` 目录下的测试覆盖不需要 GPU 与网络的部分，安装依赖后用 pytest 运行。

## 规模说明

代码默认配置的模型规格小于简历规格：项目一合成用 Qwen3-Coder-30B-A3B-Instruct、可解性检查用 Qwen3-8B；项目二、三、四的学生与教师用 Qwen3-8B；项目五策略用 Qwen3-8B 加 LoRA，在线 judge 用 Qwen3-32B；项目六策略用 Qwen3-8B，逐小问 judge 用 Qwen3-32B。各项目的 `configs` 或 `experiments/configs` 目录另附简历规模的参考配置，并注明所需卡数。

项目二默认的 8 个种子仓库用于验证全链路；要得到稳定的对照结果，需要按种子清单的字段扩充仓库，详见该项目的实验说明。
