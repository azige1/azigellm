## 1. 通用基础

### 1.1 RL / 后训练

**问题：GRPO 和 PPO 的区别？为什么 GRPO 去掉了 value 网络 / critic？**

回答：PPO 常用 critic 与 GAE，通过 $\delta_t=r_t+\gamma V(s_{t+1})-V(s_t)$ 和 $A_t=\sum_k(\gamma\lambda)^k\delta_{t+k}$ 估计前缀级 advantage。critic 可以复用同系列模型，但不必与 policy 同规模，资源开销也不必恰好翻倍。标准 outcome-GRPO 对同一 prompt 采 G 条轨迹，以 $\hat A_i=(r_i-\mathrm{mean}(r_{1..G}))/(\mathrm{std}(r_{1..G})+\epsilon)$ 构造轨迹级信号，不训练 critic，代价是同一轨迹各决策 token 缺少细粒度区分。多样本采样成本随 G 增长，但共享前缀、动态 batching 与环境等待使墙钟不必线性乘 G。GRPO 的 loss 归一和组内 std 会改变不同长度与难度的权重，[Dr. GRPO](https://arxiv.org/abs/2503.20783) 研究了固定 loss 分母和不除 std 的变体；不能只由全对或全错判断带稠密 reward 的组是否退化。参考 KL 是可选项，其是否启用与系数由具体配方决定。

**问题（追问）：组内相关性怎么办？同 prompt 共享基线会让梯度方差变大吗？**

回答：共享基线会使组内估计相关，但不能仅凭相关性断言梯度方差一定增大；基线本来就是用于降低方差，净效应取决于奖励、动作梯度及采样的协方差。需同时增加 batch 中不同 prompt 的覆盖，并权衡 G 的采样成本。二值成功率为 p、独立采样 G 条时，组内同时存在成功和失败的概率为 $1-p^G-(1-p)^G$，因此有效组率同时依赖 p 与 G。固定总 rollout 预算增大 G 会减少不同任务数，不能只比较单组估计精度。

**问题（追问）：第一遍 mini-batch 更新后还算 on-policy 吗？**

回答：忽略推理和训练实现误差且采样分布与优化口径一致时，刚采集数据的更新起点满足 $\pi_\theta=\pi_{old}$。一次参数更新后，其余 minibatch 仍来自旧采样策略，使用保存的 behavior log-prob 构造比率并限制更新幅度。clip 作用于 surrogate objective，并不保证更新后的所有概率比率被硬限制在区间内。还需明确温度、top-p 与 log-prob 重算协议，异步滞后和引擎差异可能让更新起点也不是严格同分布。更新遍数和 clip 范围通过独立 valid 与漂移统计选择。

**问题：GRPO 的 group size 怎么定？组内全对/全错怎么办？**

回答：group size 在优势统计与 rollout 成本之间权衡，8 或 16 是常见候选，并非固定最优。所有完整 reward 相同的组得到零 task advantage，task policy-gradient 项不提供信号；若启用 KL 或 entropy 项，这些项仍可能有梯度。终局结果全对或全错时，稠密过程项也可能使完整 reward 不同。仅在二值 outcome 配方下，[DAPO](https://arxiv.org/abs/2503.14476) 的 Dynamic Sampling 可通过过滤并补采非退化组提高有效组率，仍需限制补采成本与选择偏差。监测近期通过率、组内方差和训练任务分布，防止只保留易得分样本或奖励漏洞任务。

**问题：DAPO 的四条改进是什么？分别解决什么失效模式？**

回答：① Clip-Higher 使用非对称的 $\epsilon_{low}=0.2,\epsilon_{high}=0.28$，扩大正 advantage 对应的 surrogate 有效上行区间，缓解探索退化；它不把真实 ratio 硬截断为某个概率上限。② Dynamic Sampling 在原二值 outcome 设置中过滤同分组并补采，提高非零 task advantage 组率，仍需限制成本与选择偏差。③ Token-Level Policy Gradient Loss 改用 batch 内有效 token 总数归一，改变长短序列的相对权重。④ Overlong Reward Shaping 包含截断样本过滤与接近长度上限时的软惩罚，区分长度限制和答案错误的噪声。原配方还关闭参考 KL；迁移到工具环境时，需要单独检查失败归因、完整 group 与环境预算，不能机械照搬。

**问题：GSPO 改了 GRPO 什么？为什么序列级比率更稳？**

回答：[GSPO](https://arxiv.org/abs/2507.18071) §4 将 ratio 定义为 $s_i=\exp(\frac1{L_i}\sum_t\log\frac{\pi_\theta(y_{i,t}|x,y_{i,<t})}{\pi_{old}(y_{i,t}|x,y_{i,<t})})$，优化逐序列的 clipped surrogate。同一序列 token 的梯度使用共同的 s_i A_i，并包含 1/L_i 的长度因子；它不是未经归一化的整轨迹重要性权重，因此不能称为严格无偏的整轨迹 IS。几何平均缓和长序列乘积 ratio 的数值波动，不能保证极端漂移不会发散。论文在 Qwen3-30B-A3B 的长推理/MoE 配方上报告稳定性与效率改善，不能外推为所有长程 agent 均优于 GRPO；过程优势不同的多轮任务还需区分 GSPO-token。§5.1 的左右 clip 为 3e-4/4e-4，与 GRPO 的 0.2 量级不同，迁移时必须重新标定。

**问题：KL 约束：为什么加？GRPO 里 KL 怎么进 loss？系数怎么设？**

回答：参考 KL 用于限制偏离参考策略，可能缓解过优化，但不能保证杜绝崩塌或 reward hacking，部分配方关闭它。[DeepSeekMath](https://arxiv.org/abs/2402.03300) §4.1.1 将 k3 直接加到 loss，与 task advantage 分开：$\widehat{kl}=e^u-u-1$，$u=\log\pi_{ref}-\log\pi_\theta$。将 KL 混进 reward 再组内标准化会改变其绝对尺度与排序，不代表数学上不能采用这种设计。固定状态下，若 token 真正采自当前归一化策略、支撑条件满足，E[k3]=KL(π_θ‖π_ref)，且单样本非负；低方差是近分布时的常见性质，不是对任意分布低于 k1 的定理。多步复用旧样本时一般不再无偏；数值估计无偏也不等于把固定样本上的 k3 直接反传就得到完整 KL 的无偏梯度。β=0.04 是原文设置，迁移需明确逐 token/序列聚合与 mask，并联合监控参考 KL、reward、entropy 和独立评测，不能由 β 大小单独预测熵。

**问题：on-policy 和 off-policy 的区别是什么？异步采样带来的策略滞后如何修正？**

回答：on-policy/off-policy 看目标策略与行为分布是否一致，不能仅按 REINFORCE/Q-learning 名称分类；策略梯度也能加入 off-policy 修正。PPO/GRPO 通常归入 on-policy 算法，但一批旧 rollout 上多次更新是在旧分布下优化近端 surrogate，单 token ratio 不完整校正历史状态分布。异步时需记录策略版本和真实 behavior logprob，限制滞后与极端 ratio，并按目标选择截断 IS、拒绝采样或 V-trace 类估计。训练端重算同版本 old_logprob 可以作为优化锚点，不能冒充真实 behavior 概率。[verl](https://arxiv.org/abs/2409.19256) 原始论文的典型循环同步交替执行，但当前版本也有分离/异步实现；是否滞后由实际调度决定，同步也仍可能存在引擎数值与采样协议差异。

**问题：训推不一致有哪些来源、怎么解决？TIS 修正的是哪一种？**

回答：三类来源。①引擎数值与权重滞后：在 verl 的 decoupled 模式中，π_rollout 是真实采样分布、π_old 是训练端优化锚点、π_θ 是更新中策略；token-TIS 可取 min(π_old/π_rollout,C)，序列-TIS 则先聚合整序列 log-ratio。截断以偏差换方差，偏差不保证很小，也不能只凭单 token 比率称为完整状态分布修正。bypass 模式直接以 rollout 概率为 old，不能再重复套同一校正。②模板与 token：两端一致地保存 input_ids、工具消息边界与 policy mask，避免重组改变状态。③采样协议：temperature、top-k/top-p 与约束解码均改变 behavior 分布；训练端 logprob 必须说明是否包含这些变换，硬截断还可能破坏目标支撑覆盖。训练探索温度不必等于部署温度，更不应无条件后期降温，需在部署配置下评测并做消融。依据：[verl Rollout Correction](https://verl.readthedocs.io/en/latest/algo/rollout_corr.html) 的 Operation Modes / IS Aggregation（2026-09-23 文档）。

**问题：entropy 塌缩怎么识别、怎么处置？**

回答：联合看 policy entropy、独立 pass rate、输出重复率、长度及组内多样性；熵下降且成功率上升可能是有效收敛，熵骤降且任务进展停滞才是警报，不能只按早期/后期划分。[The Entropy Mechanism of RL for Reasoning LLMs](https://arxiv.org/abs/2505.22617) 给出协方差机制与其设置下的经验关系，不构成任意奖励下熵必然单调下降或可准确预测最终性能的定理。处置先查 reward、ratio、LR、难度与参考约束，再对非对称 clip、熵正则、温度和采样多样性做小规模消融；KL 强弱不直接决定熵方向。entropy 通常是在有效 policy 状态上算全词表分布熵，再按生成位置聚合；单个已采 token 的 −logprob 是熵的采样估计，top-k 近似须明确缺失尾部，不是词串去重率。

**问题：reward hacking 怎么防？三层防线分别怎么做？**

回答：①信号设计优先可靠执行判定，judge 按维度评分并与人工校准；规则与模型都会有漏洞。②训练中参考 KL 可降低偏离，不是防作弊保证；保护判分器、隐藏 gold、审计最高奖励轨迹。③监控 reward 与独立评测背离、真实越权行为及规则漏洞，背离是报警而不是单独的作弊证明。修改隐藏测试、读取 gold patch 属作弊；合法检索、带引用的抽取式回答与来源重合并不自动作弊。代码基准可限制外网，搜索任务则要保留任务允许的检索渠道并隔离参考答案。[SWE-bench+](https://arxiv.org/abs/2410.06992) 审计中 32.67%/31.08% 的分母是该设置下被判已解决的补丁，不是全题库。错误补丁通过测试提示约束不足，需确认该探针确实不满足规格，不能仅因与参考补丁不同就判错。

**问题（追问）：发现 hacking 后怎么办——直接改 reward 吗？**

回答：先定位漏洞形态再补对应规则（只修补单点症状会引入新漏洞），同时把 hacked 样本从历史数据中剔除或降权重训。奖励模型同样存在可被利用的泛化漏洞，关键任务以规则校验为最终判定，奖励模型只作辅助信号。

**问题：蒸馏选 forward KL 还是 reverse KL？OPD 是什么、解决什么？**

回答：forward KL $D_{KL}(p_T\|q_S)$ 在教师分布取期望，倾向覆盖教师模式；reverse KL $D_{KL}(q_S\|p_T)$ 在学生分布取期望，倾向集中于教师高概率模式。这是优化倾向，不是按模型容量硬划分的选型定律。教师样本 CE 在教师分布固定时等价于 forward KL 去掉常数；序列 reverse KL 可用 score-function 梯度，固定前缀下也可对词表精确求和或使用有支撑覆盖的 proposal，不是只能从学生采样。[MiniLLM](https://arxiv.org/abs/2306.08543) 给出其降方差设计。OPD 的核心是学生生成前缀、教师在学生访问状态上提供监督，可选不同散度，缓解而非保证消除 exposure bias。[Thinking Machines 的 OPD](https://thinkingmachines.ai/blog/on-policy-distillation/) Implementation 使用采样 token 的教师 logprob，令即时 advantage 为 logπ_T−logπ_S，并不要求教师完整词表 logits；其 γ=0 的局部更新也不等于严格完整序列 KL 梯度。可与环境奖励组合，但收益需独立验证；教师质量、支撑覆盖与部署采样配置同样重要。

**问题：GRPO 与 DPO 各涉及几个模型？一条样本各需要几次前向？**

回答：标准 GRPO 使用策略、采样时的行为概率和可选参考策略；不使用 critic，关闭参考 KL 时也不必保留一个独立参考模型。DPO 优化偏好对损失 $\mathcal{L}=-\log\sigma\!\left(\beta\log\frac{\pi_\theta(y_w)}{\pi_{ref}(y_w)}-\beta\log\frac{\pi_\theta(y_l)}{\pi_{ref}(y_l)}\right)$，一对数据需要策略与参考各计算 chosen/rejected 两条序列的概率，但四条序列评价不等于必须调用四次 forward；可拼成 batch，参考结果也可预计算。通常对合并后的策略 loss 做一次 backward，参考模型不反传。离线 DPO 本身不进行环境探索，偏好可以来自人工、模型或执行判定。

**问题（追问）：既然 DPO 更省，为什么还需要 RL？**

回答：离线 DPO 通过已有偏好对学习相对选择，不能在这次更新中探索当前策略的新环境轨迹。偏好标签本身可以由不可微的执行判定构造，所以不能声称 DPO 无法间接优化此类目标。在线 RL 直接使用当前采样与可验证反馈，适合需要持续探索的新行为，代价是环境、采样与训练稳定性成本。两者可组合，但需比较独立评测和总预算，不将算法名称直接等同于优劣。

**问题：重要性采样、clip 与归一化分别解决什么问题？**

回答：重要性比率在支撑覆盖等条件下对行为与目标分布做重加权；单步条件 ratio 不能完整校正整轨迹状态访问分布。PPO clip 优化 $\min(\rho_t A_t,\mathrm{clip}(\rho_t,1-\epsilon,1+\epsilon)A_t)$：A>0 时抑制继续增大过高 ratio 的收益，A<0 时抑制继续降低过低 ratio 的收益。它没有把真实 ratio 或参数更新硬限制在区间内，也不保证严格信任域。loss 归一决定样本/token 权重和整体梯度尺度，必须与 reward/advantage 标准化分开说明。

**问题（追问）：clip 之后为什么还要再归一化？**

回答：两者互不替代：clip 改变 surrogate 的有效梯度，因此也可能改变 token 相对贡献；归一化则明确总量与样本长度的权重。token mean 对每个有效 token 等权，长回答通常占更多 token 权重；response mean 对每条回答等权，长回答单 token 权重较小。实际梯度还依赖 advantage、clip 激活和梯度方向，不能等同于给长样本更高 LR，更不能把一种归一方式一概称为不稳。Dr. GRPO 的固定分母与 DAPO 的 batch token 分母并非同一目标。分母按 policy mask 而非环境 token 计，多卡/累积需保持全有效 batch 的权重一致。

**问题（追问）：组内优势归一化与上面两件事有交集吗？**

回答：作用层级不同，但会共同决定梯度权重，不能说没有交集。组均值提供相对 baseline，组内 std 缩放优势，会重加权不同奖励方差的 prompt；它不能消除任务难度差异，也不是所有任务绝对 reward 都不可比。clip 的激活取决于 ratio 与优势符号，loss 分母进一步改变长短样本权重。比较配方时应分别列出 reward、advantage、clip 与 loss reduction，避免同时改多项后只归因于其中一项。

**问题：为什么 RL 能学会长轨迹任务，SFT 学不会？**

回答：SFT 在教师轨迹的状态分布上做最大似然，RL 在策略自身的状态分布上按结果优化，两者的差距随轨迹长度放大。① 复合误差：行为克隆只在教师访问过的状态上训练，推理时某一步偏离后，后续状态落在训练未覆盖的区域，错误不会自我纠正。设教师分布上的单步出错率为 $\epsilon$、轨迹长度为 $T$，行为克隆的累计代价上界为 $O(\epsilon T^2)$，在学习者自身访问的状态上采集监督的 [DAgger](https://arxiv.org/abs/1011.0686) 为 $O(\epsilon T)$ 量级，$T$ 越大差距越大。② 缺少恢复样本与负信号：教师轨迹几乎只包含正确路径，模型没有见过自身出错后的状态，也没有学到哪些动作应当避免；RL 的 rollout 包含策略自己的错误，负优势直接压低导致失败的动作，出错后改走其他路径并最终完成的轨迹同样获得奖励。③ 单路径模仿与多解：长任务存在多条等价的完成路径，SFT 拟合教师选定的一条，最大似然在多个模式之间摊薄概率；outcome reward 只判定结果，任一可行路径都得分。④ 能力错位：教师的长轨迹依赖学生不具备的规划与记忆能力，学生只能复制表面动作序列；on-policy 样本天然处在学生的能力边界上。适用边界：RL 不能从零习得能力。只有策略已能以非零概率完成任务时，组内才存在正负对比；[Yue et al.](https://arxiv.org/abs/2504.13837) 观察到 k 足够大时基座模型的 pass@k 不低于 RL 后的模型，说明 RL 的主要作用是把已有的低概率成功路径提升为高概率路径。因此长轨迹任务的常见配方是 SFT 冷启动输出格式与基础动作，再用 RL 提升长链路的稳定完成率，并配合调用预算 curriculum 或过程信号缓解稀疏终局奖励的信用分配问题。[SFT Memorizes, RL Generalizes](https://arxiv.org/abs/2501.17161) 在规则变体与视觉变体上观察到 RL 的分布外泛化优于 SFT，同时指出 SFT 仍是稳定输出格式、使 RL 可以启动的前置步骤。

**问题（追问）：训练数据由自己准备，多加长轨迹做 SFT 能否解决？**

回答：增加教师长轨迹能降低教师分布上的单步误差 $\epsilon$，训练分布与推理分布的错位仍然存在，复合误差的 $T^2$ 结构不变。消除错位需要在学习者自己访问的状态上采集监督，即 DAgger 的思路，在 LLM 上对应拒绝采样微调、on-policy 蒸馏与在线 RL 三类做法。此外长轨迹的教师成功率随长度下降、人工标注成本随长度上升，可用的高质量长轨迹本身稀少。

**问题（追问）：用 reward 筛选模型自己的成功轨迹再做 SFT，与直接做 RL 有什么区别？**

回答：这类做法即拒绝采样微调（[RFT](https://arxiv.org/abs/2308.01825)、[STaR](https://arxiv.org/abs/2203.14465)、expert iteration）：从当前策略采样，用 verifier 保留成功轨迹做 SFT。样本来自学生自己的分布，缓解了分布错位，实现上只需要 SFT 管线，可视为只使用正奖励样本的离线策略梯度近似。与在线 RL 的差别有三点：① 失败轨迹被丢弃，没有负梯度，模型不知道应当避免什么；② 按轮离线迭代，同一轮内的数据随策略更新逐渐变旧；③ 成功率很低的难题几乎采不到正样本，与 RL 一样受限于 pass@k。on-policy 蒸馏（[GKD](https://arxiv.org/abs/2306.13649)）是另一种折中：学生自己采样，教师对每个 token 给出分布监督，同时获得学生分布与稠密信号，代价是教师需要在线打分。工程上常见的顺序是 SFT 冷启动、拒绝采样微调扩充学生分布上的数据、在线 RL 或 on-policy 蒸馏收尾。

### 1.2 训练诊断与微调

**问题：训练 loss 震荡/发散怎么定位？**

回答：按超参、数据、工程三个方向排查，顺序按验证成本从低到高。①超参：lr 过大最常见（降一个数量级试跑），其次是 KL 系数过小（RL 阶段策略漂移）、clip 范围过大；②数据：新混入批次的分布突变或脏样本——记录每个 batch 的样本 id，把震荡 batch 的数据单独回放，能复现即为数据问题，再检查该批数据的长度分布、重复度与标签噪声；③工程：并行 rollout 不同步（部分 worker 使用旧权重）、梯度累积边界错误（loss 归一化方式不一致）、数值问题（fp16 下的上溢、attention mask 的 −inf 与全屏蔽行、低精度下的舍入误差累积）。监控上保留 loss、grad-norm、KL、entropy 四条 batch 粒度曲线，并关联 batch 级数据索引。出现 loss spike 时回滚到最近的稳定 checkpoint 后离线归因，不在异常状态下继续训练。两类 spike 的区分：数值类通常 grad-norm 同步激增、此前无征兆；数据类的前后 batch 正常，可定位到具体样本。

**问题：CPT/垂域继续预训练后通用能力掉点怎么办？**

回答：标准解法三条，外加一个激进方案。①replay：混入通用语料（垂域:通用从 3:7 到 7:3 按目标垂化强度扫描定，通用数据的作用是对抗遗忘——选"原预训练配比的缩小版"，指令/代码/数学按原比例缩）；②调度：[WSD](https://arxiv.org/abs/2404.06395)（warmup-stable-decay）的 decay 段提高通用高质量数据占比做"退火回正"（decay 段数据质量对最终能力影响极大）；③监控：固定通用回归集（MMLU/C-Eval/代码/数学抽样）每 N 步测，掉点超阈值（如 >3pp）触发回滚或加 replay。激进方案 [LLaMA Pro](https://arxiv.org/abs/2401.02415) 式 block expansion：冻结全部原层、插入恒等初始化的新层只训新参数——恒等初始化保证训练起点与原模型等价、旧层不受梯度直接破坏从而大幅缓解遗忘，可增量叠加，代价是总参上涨推理变慢。replay 比例不给固定单值、按方法定：垂域评测与通用回归双目标网格扫描（5:5/6:4/7:3 三档），选两目标都达标的边界点。

**问题：LoRA 的秩 r 是什么意思？α 呢？推理有开销吗？**

回答：[LoRA](https://arxiv.org/abs/2106.09685) 将更新写为 ΔW=BA，若 W 为 d_out×d_in，则 A 为 r×d_in、B 为 d_out×r，rank(ΔW)≤r。原文 A 随机、B=0；第一步 A 梯度为零、B 可有非零梯度，之后两者共同更新。α/r 控制支路尺度，但不保证跨 r 的更新量严格不变，r、α、LR 与目标模块要联合扫描；rsLoRA 的缩放是 α/√r，不能混称。r=8/16/32 是候选而非覆盖保证。合并到兼容精度的单一 W 后无额外支路算子；未合并、多 adapter 切换和量化路径仍有实际成本或误差，须明确“零开销”的前提。

### 1.3 模型结构

**问题：把一个 decoder-only Transformer 从 token id 到 logits 的完整流程按张量形状讲一遍？**

回答：以 Llama 2 7B 的 MHA、pre-norm、RoPE、SwiGLU 配置为例，不代表所有 7B。① token 查表得 X∈R^{B×L×4096}。② norm 后投影 Q/K/V，变为 B×32×L×128，Q/K 按 position_ids 旋转，算 softmax(QKᵀ/√128+M)V，concat 后过输出投影并加残差。GQA 时 K/V 的头数更少，不能把三者形状都固定为 Q 头数。③ 第二个 norm 后做 SiLU(XW_g)⊙(XW_u)，中间维 11008，再投影回 4096 并加残差。④ 32 层后 final norm、LM head 输出 B×L×Vocab；Llama 2 的 embedding 与 LM head 不共享，其他架构可能共享。⑤ causal LM 做 next-token shift，并仅监督协议允许的位置。transpose 后 view 需检查连续性，reshape 可自行复制；固定频率 RoPE 通常旋转后缓存 K，动态频率变更则需重建/重旋缓存或使用专门缓存方案，不能混用前后频率。

**问题（追问）：注意力的时间和空间复杂度是多少？FlashAttention 改了什么？**

回答：只看 attention 核，时间 O(L²d)，显式注意力权重空间 O(BhL²)；计入 QKV/输出投影时还有 O(Ld²)，短序列不一定由二次项主导。[FlashAttention](https://arxiv.org/abs/2205.14135) 分块与 online softmax 避免在 HBM 落完整权重矩阵，固定模型宽度时辅助存储对 L 线性，attention FLOPs 仍为二次阶。原文特定 GPT-2 设置约 3 倍加速，不能当所有模型的端到端加速。数学上是精确 dense attention，浮点顺序可有差异；能否启用还取决于硬件、head_dim、mask 与所需 attention 输出，不是所有调用都无条件可用。

**问题：Self-Attention 里为什么要除以 √d_k？为什么要多头，计算量变大了吗？**

回答：缩放是方差控制。设 q、k 各维独立、均值 0、方差 1，点积 $q\cdot k=\sum_{i=1}^{d_k}q_i k_i$ 的方差随 $d_k$ 线性增长；$d_k$ 大时点积量级大，softmax 被推到饱和区、输出接近 one-hot、梯度趋零，数值上也易溢出。除以 $\sqrt{d_k}$ 后点积方差回到 1，softmax 落在梯度敏感区间——注意除的是单头维度 $d_h$ 而不是模型维度 d。多头把 d 维拆成 h 个子空间各自算注意力再拼接，让不同头学不同关系模式（局部搭配、长程指代、位置模式）。计算账：单头注意力 $O(L^2 d)$，多头每头 $O(L^2 d_h)$、h 头合计仍 $O(L^2 d)$，投影矩阵也是同一组 $d\times d$ 按头切分——表达能力的提升基本免费。工程边界两条：实际开销略高（reshape/transpose 的内存布局操作、h 个小矩阵乘的并行效率低于一个大矩阵乘）；$d_h$ 过小单头表达不足，实践中 $d_h$ 取 64 或 128，头数由 d 反推。

**问题：RoPE 为什么能表达相对位置？为什么要用多组不同频率？**

回答：[RoPE](https://arxiv.org/abs/2104.09864) 将旋转维度两两配对，第 i 对在位置 m 旋转 mθ_i，θ_i=b^{−2i/d_rope}。由 R_mᵀR_n=R_{n−m}，位置旋转因子只依赖相对位置差；q/k 内容仍依赖上下文，不能称整个打分仅由距离决定。多频率提供不同尺度的相位变化，比单频更能区分位置，但不保证没有数值近碰撞，也不是所有频率周期都互不成整数比。高频可表达细小位置变化、低频跨更长距离变化，这只是表示结构，不保证各维实际学到对应功能或外推有效。经典 Transformer 用 RoPE 旋转 Q/K、不旋转 V；长距离衰减不是任意内容下严格单调，检索能力需训练与评测。

**问题（追问）：4K 训练的模型怎么外推到 128K？NTK 插值和 YaRN 分别改了什么？ALiBi 那条路线呢？**

回答：①PI 将位置 m 缩为 m/s，所有频率一起压缩，通常配长文继续训练。②NTK-aware 改 base，高频少改、低频多插值，可提供一定免训练扩展但无统一倍数保证。③[YaRN](https://arxiv.org/abs/2309.00071) 按波长分段插值，再把 attention logits 乘 1/t；推荐 √(1/t)=0.1 ln(s)+1，对应 Q/K 各乘该系数，不能把 logits 只乘 √(1/t)。其 Llama 2 设置用 400 步到 64K，再 200 步到 128K。低频未见相位是失效因素之一，高频见过单维相位不等于见过全部联合相位/距离分布。扩窗验收须覆盖短文回归、各长度/深度检索及真实长文任务，[RULER](https://arxiv.org/abs/2404.06654) 分数不等于完整长文能力。ALiBi 在 logits 加按头设定的线性距离偏置，因果位置可写 −m(i−j)；与 RoPE 的优劣依任务与训练配方，不能无条件说长程检索较弱。

**问题：KV cache 存的是什么、显存怎么算？GQA、MQA、MLA 分别怎么把它压下去？**

回答：KV cache 存每层每头每个已生成 token 的 K 与 V：显存 $=2\times N_{layer}\times n_{kv}\times d_h\times T\times B\times$ 字节数。以 7B 档（32 层、$n_{kv}=32$、$d_h=128$、bf16）计，单条 8K 序列约 4 GiB——长序列与大 batch 下它是推理显存主因，[PagedAttention](https://arxiv.org/abs/2309.06180) 的分页块管理正是为治它的碎片与超额预留。只存 K/V 不存 Q：Q 只服务当前位置、下一 token 的 Q 重新算，K/V 参与所有后续位置的注意力。压缩三路：① [GQA](https://arxiv.org/abs/2305.13245) 让多个 Q 头共享一组 KV 头，cache 按 KV 头数与 Q 头数之比缩小（32 个 Q 头配 8 个 KV 头即 1/4），是当前开源基座的常见配置，在表达力与显存之间折中；② MQA 全部头共享一份 KV，压缩最激进、表达损失最明显；③ [MLA](https://arxiv.org/abs/2405.04434)（DeepSeek-V2/V3）不共享而做低秩压缩：KV 联合投影为低维 latent 向量（$d_c=512$）外加 64 维解耦 RoPE 分量，只缓存这两者，注意力时上投影恢复各头 K/V——压缩率接近 MQA 而保留各头差异化表达。工程边界：GQA 的 KV 头数要能被 TP 度整除（不足则复制）；MLA 省的是推理 cache，训练侧前向仍是完整注意力。

**问题（追问）：MLA 说的"矩阵吸收"是什么意思？**

回答：内容分数 qᵀ(W_UK c) 可改写成 (W_UKᵀq)ᵀc；value 的线性恢复也可放到加权 latent 求和之后，再与输出投影组合。这样无需为历史 token 物化完整多头 K/V。位置相关的 RoPE 一般不能与上投影交换，所以 DeepSeek 的 MLA 另缓存一小路解耦位置 key。省 cache/恢复带宽并不保证所有算子 FLOPs 都更少：吸收后的每头内积维度可比原 head_dim 大，prefill 与 decode 常用不同实现，收益要按硬件与 kernel 测量。

**问题（追问）：prefill 和 decode 的瓶颈分别是什么？**

回答：prefill 大块矩阵乘通常算术强度高，decode 小 batch 单 token 前向通常受权重/KV 读取带宽约束，这是常见画像而非定律。大并发、MoE 通信、长 KV 和短 prompt 会改变瓶颈。GQA/MLA、cache 量化与 continuous batching 可改善 decode 吞吐，但并发过高也增加排队、显存与单请求延迟。PD 分离能分别调度两阶段，却增加 KV 传输与运维成本；长 prefill 不只有 L² attention，投影/FFN、视觉编码及排队也可能主导 TTFT，应先做 profiler 归因。

**问题：RMSNorm 和 LayerNorm 有什么区别？Pre-norm 和 Post-norm 又差在哪？**

回答：LayerNorm 对激活做 $\frac{x-\mu}{\sqrt{\sigma^2+\epsilon}}\gamma+\beta$，减均值、除标准差、带平移参数；[RMSNorm](https://arxiv.org/abs/1910.07467) 去掉均值中心化，只做 $\frac{x}{\sqrt{\mathrm{mean}(x^2)+\epsilon}}\gamma$。三点差异：① 计算——RMSNorm 少一次均值归约与减均值广播，norm 本身占整网计算比例小，收益主要是实现简化；② 动机——LayerNorm 的再中心化假设在 LLM 上不关键，再缩放不变性已够，LLaMA/Qwen/DeepSeek 全系 RMSNorm；③ 参数——RMSNorm 通常只保留缩放参数 γ，不设平移参数 β。Pre-norm 与 Post-norm 的分歧是 norm 放子层内还是外：Post-norm（[Attention Is All You Need](https://arxiv.org/abs/1706.03762) 的原始结构，$x+\mathrm{sublayer}(x)$ 之后再 norm）深层网络训练不稳定，依赖 warmup 与初始化；Pre-norm（先 norm 再进子层、残差直通到底）梯度有恒等通道、上百层也稳，代价是残差流主导、各层贡献被稀释，超深网出现"深度浪费"，折中变体有 DeepNorm 式残差缩放。现代基座默认 Pre-norm 加 RMSNorm。

**问题：FFN 从 ReLU 到 SwiGLU 演进改了什么？SwiGLU 为什么中间维取 2/3 左右？**

回答：FFN 演进主线是 ReLU → GELU（BERT/GPT-2 起）→ [SwiGLU](https://arxiv.org/abs/2002.05202)（PaLM/LLaMA 起成主流）。SwiGLU 属门控线性单元：$\mathrm{SiLU}(xW_g)\odot(xW_u)$ 再过 $W_d$，其中 $\mathrm{SiLU}(x)=x\sigma(x)$——三个投影矩阵，一支经激活当门控、与另一线性支逐元素相乘，给逐位置信息流一个可学习的乘性开关；相对单激活 FFN 多了门控路径，经验上同参数量收敛更快、下游更好。2/3 是参数配平：标准 FFN 两矩阵参数量 $2\cdot d\cdot d_{ff}$（$d_{ff}=4d$），SwiGLU 三矩阵 $3\cdot d\cdot d'_{ff}$，令总量相等得 $d'_{ff}=8d/3$——LLaMA 在 d=4096 时取 11008（$8d/3\approx10923$ 向上对齐到 256 的倍数）。边界两条：门控乘法使激活分布更尖、低 bit 量化时门控支是敏感点；小模型或训练预算很短时 SwiGLU 的收益不一定盖过额外的调参成本。

**问题：7B 模型 bf16 推理要多少显存？全参训练的显存账又怎么算？**

回答：7×10⁹ 个 bf16 参数占 14 GB（十进制），约 13.0 GiB，KV cache、激活峰值、临时 workspace 和框架开销另计，不能仅凭参数量保证 24/32 GB 卡足够。训练若采用 bf16 参数/梯度、fp32 master 和 fp32 AdamW 双矩，则状态为 16 B/param，7B 约 112 GB、14B 约 224 GB，均未计激活；梯度 dtype、是否有独立 master、分片与 offload 会改变账目。无分片/offload 时 7B 这套全参状态已超过 80 GB。dense 主干近似前向 2ND、含反向 6ND，不包含所有长上下文注意力和系统成本，MoE 则区分激活与总参数。

**问题（追问）：用 6ND 怎么估一次训练要多久？**

回答：主干时间近似 6ND/(卡数×单卡峰值×MFU)，前提是 FLOPs 定义和 MFU 分子一致。H100 SXM 的 dense bf16 Tensor Core 峰值约 989 TFLOPS，PCIe 与稀疏口径不能混用；MFU 要由目标模型/长度/并行配置测量，35%–50% 只能作候选假设。7B×1T token 为 4.2×10²² FLOPs，512 卡、每卡有效 400 TFLOPS 的主干估算约 57 小时，墙钟还受保存、评测、故障和数据等待影响。全重算可粗算 8ND，但若 MFU 已按实际训练吞吐和 6ND 定义测出，不能再机械乘 8/6 重复计重算；长 attention 与 MoE 通信也需单独校准。

**问题：BPE 分词的原理是什么？词表大小怎么权衡？**

回答：BPE 训练按相邻符号对频率迭代合并，编码按 merge rank 应用同一规则，实际还受预分词、规范化与 byte fallback 影响。较大词表通常降低 token 膨胀，却增加 embedding/LM head 与稀有 token 的学习成本：152K×4096 约 6.2 亿参数是一张矩阵，未共享时输入/输出两张另计。版本例子应明确：GPT-2 50,257，Llama 2 32,000、Llama 3 128,256；Qwen2/3 约 152K（tokenizer 有效词元与配置填充行数可能不同）；DeepSeek-V2 102,400、V3 129,280。TP 可通过 padding 词表满足切分，不要求原始 tokenizer 词元数天然整除。扩表可只新增 embedding/head 行，不必重置全部旧行，但切分与 softmax 分母变化需回归；模板、special token ID 与真实分词结果必须训推一致。

### 1.4 优化器与训练工程

**问题：AdamW 和 Adam 的区别是什么？β、ε、weight decay 的典型值是多少？**

回答：[AdamW](https://arxiv.org/abs/1711.05101) 把 weight decay 从梯度中解耦。Adam 里 L2 正则项进梯度后被自适应步长 $\hat m/\sqrt{\hat v}$ 缩放——梯度大的参数 decay 被压小，正则强度逐参数失真；AdamW 把衰减直接施加在权重上：$\theta\leftarrow\theta-\eta\,\hat m/(\sqrt{\hat v}+\epsilon)-\eta\lambda\theta$，衰减与梯度统计无关，正则强度全网络一致。典型值：LLM 预训练 β1=0.9、β2=0.95（较小的 β2 让二阶矩更快跟上梯度尺度的变化；微调常用默认的 0.999）、ε=1e-8、wd=0.1（LLaMA 的公开设置，SFT 常降到 0.01~0.1）；lr 量级：预训练峰值 1.5e-4~3e-4（7B 档）、SFT 1e-5~2e-5、RL 5e-7~1e-6。边界：wd 不施加在 norm 参数与 bias 上（一维参数衰减会破坏归一化尺度）。优化器方面的新进展：[Muon](https://arxiv.org/abs/2502.16982) 把动量做 Newton-Schulz 正交化后更新二维参数矩阵，Moonshot 的论文报告其计算效率约为 AdamW 的 2 倍，embedding 与 norm 等非矩阵参数仍用 AdamW。

**问题（追问）：weight decay 和 lr 是什么关系？调一个要不要动另一个？**

回答：AdamW 每步乘以 1−η_t λ，η_t λ 是该步的衰减量；整个运行的纯衰减因子为 ∏_t(1−η_t λ)，小步近似 exp(−λΣ_tη_t)。LR 减半而 wd 不变会减小每步衰减，但若步数和 LR 曲线不同，不能只比较单步乘积；反比调 wd 只保持对应步骤的衰减，不保证最优正则或训练等价。LR 趋零时任务更新与 decay 都趋零，不能称为无正则精修，更不能把理论正则系数仅定义成 ηλ。

**问题：warmup 为什么需要？cosine 和 WSD 两种调度怎么选？**

回答：warmup 治训练初期的两类失稳：Adam 二阶矩从零起步、初期估计偏差大，大 lr 直接上会沿噪声方向大步走、表现为开局 loss 尖峰；深网（尤其 post-norm）的梯度尺度尚未建立。做法是线性升到峰值，步数常取总步数的 0.1%~3%（GPT-3 为前 3.75 亿 token，总量 3000 亿）。调度对比：cosine 一条曲线平滑到底，适合预算与数据一次性确定的一次性训练；[WSD](https://arxiv.org/abs/2404.06395) 主体段常数 lr、最后约 10% 的步数内快速衰减（MiniCPM 用指数衰减）。WSD 的工程优势三条：stable 段 checkpoint 可随时分叉续训加数据、不必重跑整条 cosine；decay 段集中注入最高质量数据做退火精修，该段数据质量对最终能力影响极大；多阶段 CPT 与扩窗天然衔接（稳定段末 checkpoint 连同优化器状态交付，一阶/二阶矩缺失会让自适应步长在接续初期失真）。代价：stable 段中途 snapshot 略逊于同期 cosine（尚未退火收敛）；退火终点的取值在公开做法中从峰值的 1% 到 10% 不等，较低的终点降低末段的梯度噪声。

**问题（追问）：从已收敛模型做 CPT 续训，学习率怎么接？要重新 warmup 吗？**

回答：依据训练起点、模型规模、优化器状态、数据变化与预算选择，不固定为 1e-5 或原峰值的十分之一。恢复同一运行的完整状态可继续原 LR/scheduler；只取得公开权重、重建优化器或大幅改变分布时，可设独立调度和短 warmup。stable checkpoint 接续也仍要验证新数据下的稳定性。扩窗处可用较低 LR 适应、短回升或其他调度，是否回升由消融决定，不是每档必做；warmup 与 stable 段不能混称。

**问题：梯度裁剪怎么做的？clip 阈值怎么定？**

回答：常用 global L2 norm clipping，g>c 时将全部梯度乘 c/g，保留原始梯度方向并限制范数。Adam 的动量与自适应预条件会再改变更新，故不等于给最终参数步长硬封顶；PPO ratio clip 也不是概率偏移硬约束。c=1.0 是常见公开设置，不是所有 SFT/RL 的标准。混合精度先 unscale，分片训练正确聚合全局范数，再裁剪；保留裁剪前 norm 和触发率。高触发率可能来自 batch 尺度、数据或阈值，不单独证明 LR 大；LR 不直接出现在当前参数的原始梯度计算中。出现 NaN/inf 要查源算子，clip 本身不能修复非有限梯度。

**问题：bf16 和 fp16 差在哪？混合精度为什么还要 master weights 和 loss scaling？**

回答：fp16 为 1+5+10 位，最大 65504、最小正规数约 6.1e-5；bf16 为 1+8+7 位，指数范围接近 fp32、有效精度更低。fp16 常配 loss scaling 防小梯度下溢，unscale 后再裁剪/step，检测非有限值时跳步并调缩放；它不能修复前向激活已经溢出。bf16 通常不需 loss scaling，但仍可有 NaN、舍入与异常输入问题。小更新易被低精度权重吸收，通常用 fp32 主参数/累加或其他高精度更新机制；若模型参数本身保留 fp32、仅计算用低精度，就不需额外独立 master 副本，不能说所有实现都必须双份权重。norm/softmax 内部累加常用 fp32，跨卡通信 dtype 则依框架与配置，可用 bf16 通信，不能无条件说 all-reduce 都 fp32。

**问题（追问）：推理侧为什么反而常见 fp16？**

回答：历史硬件/推理栈更早支持 fp16，其精度位也更多，但推理激活不保证低于 65504。bf16 训练权重或存在大激活的模型直接转 fp16 可能溢出，应按模型推荐 dtype、硬件支持与精度回归选择，不能只因没有反向就认定 fp16 更好。INT8/FP8 需 scale 管理与量化验证；E4M3/E5M2 的典型用途不同，但不是所有配方必须前向 E4M3、梯度 E5M2，DeepSeek-V3 的低精度矩阵乘选择是另一套配方。

**问题：梯度累积和梯度检查点分别拿什么换什么？**

回答：梯度累积把同一有效 batch 拆为多个 microbatch，只在末尾 step，激活峰值按 microbatch 计。固定 global batch、相同目标归一、模型/RNG 处理一致时与大 batch 梯度近似等价；有效监督 token 数不同的 microbatch 不能简单均值等权，DP 同步也需正确处理。是否降低吞吐依 microbatch 与 no_sync/通信策略，不因增加累积次数就必然重调 LR。checkpointing 是额外计算换少存激活：逐层重算仍需保存各层输入，不自动得到 O(√层数)；该界依特定分段调度。全重算粗略增加一遍前向，选择性重算成本随 kernel、长度和保存对象变化；FlashAttention 已不存 L² 权重，不能把重复重算的收益重复计算。按显存与实测吞吐选择，不设固定 32K 必开规则。

**问题：ZeRO 三个阶段各切什么？通信代价是什么？**

回答：ZeRO 消除数据并行下"每卡一份完整状态"的冗余，三阶段递进。ZeRO-1 切优化器状态：每卡只持 $1/N$ 的 fp32 主权重与两个动量（显存最大头，约 12 B/param），step 时各卡更新自己的分片再 all-gather 参数，通信量与标准 DP 基本持平。ZeRO-2 加切梯度：反向用 reduce-scatter 替代 all-reduce，每卡只留自己分片的梯度，通信量仍与 DP 相当。ZeRO-3 加切参数：每卡常驻 $1/N$ 参数，前向与反向按层 all-gather 出完整参数、用完释放——显存随卡数近似线性下降，代价是通信量约为标准 DP 的 1.5 倍且对带宽敏感。实现上张量展平成一维等分切而非按语义维切：负载天然均衡、与模型结构解耦，代价是单张量可跨卡、通信要按参数组重组。边界：ZeRO-3 跨机 all-gather 走 IB 易成瓶颈，常配机内满切加机间 DP，或叠 TP；FSDP 是 PyTorch 对 ZeRO-3 思想的原生实现（full_shard 对应 ZeRO-3）。

**问题（追问）：ZeRO-3/FSDP 和 TP 的区别是什么？**

回答：ZeRO-3/FSDP full_shard 主要分片参数、梯度和优化器状态，计算某层前聚合所需完整参数；不把该层矩阵乘本身按分片计算。TP 切矩阵计算，各卡执行分片并在算子边界通信。经典 Megatron dense 层前向/反向各两次 all-reduce 是一种配置，sequence parallel 等可改变通信原语。TP 通常放在高带宽域，但不是必须 NVLink/机内，跨机是否可行取决于拓扑与测量；两者可叠加。比较计算量必须固定处理的全局 token，纯 DP/FSDP 还会按不同数据分摊工作，不能脱离 batch 定义直接说哪种必快。

**问题：70B 级模型的训练，TP/PP/DP 怎么切？单机 8 卡放得下吗？TP 为什么不跨机？**

回答：选择次序是 DP 优先（通信最少，只有梯度同步），显存放不下才引入 TP/PP：TP 限制在机内（NVLink 带宽高），PP 与 DP 可以跨机（通信频率低）。先算显存账：70B 的 bf16 权重为 140 GB，TP8 后每卡 17.5 GB，推理与 LoRA 微调可以放下；全参训练按前文 16 B/param 估算需要约 1120 GB，超过 8×80 GB，单机 8 卡放不下，需要多机（机内 TP8，机间 PP 与 DP，并做优化器状态分片）或改用参数高效微调。TP 不跨机的定量理由：TP 每层前向两次 all-reduce、反向再两次，环形 all-reduce 的通信量为 $2D(TP-1)/TP$，是每个 micro step 的固定开销、不随 batch 摊薄——机间网络带宽明显低于 NVLink，跨机 TP 会使通信时间占主导；PP 每个 stage 边界只传一次激活，流水线空泡可用 1F1B 与 interleaved 调度压低，适合跨机。两个配套约束：GQA 模型的 KV 头数要能被 TP 度整除（不足时复制 KV 头）；MoE 再叠加 EP，EP 与 TP 正交，专家间的 all-to-all 尽量留在机内。

**问题（追问）：TP8 是不是比 TP4 算得更快？**

回答：不一定。固定输入与经典 ring all-reduce，单次每卡字节量为 2D(p−1)/p，TP4/8 对应 1.5D/1.75D；参与卡增多时单卡计算减少，但通信延迟、小矩阵效率、拓扑与重叠改变实际速度，不能只由字节比例推出 TP8 不快。TP 也能切部分激活，PP 按层分割但各 stage 激活峰值还受在途 microbatch 与调度影响，不保证全部显存恰好减半。模型能放下时常优先考虑 DP 吞吐；单请求延迟目标、高 batch 或特殊拓扑下仍需实测，不能称纯 DP 理论总最优。

**问题：单条超长样本显存放不下时有哪些处理手段？直接删掉行不行？**

回答：先分辨参数状态、单条激活、padding 或模型最大窗口限制。packing/长度分桶能减少多条短样本 padding，却不能让一条过长样本自行变短；独立样本 packing 需 attention 边界和跨段标签隔离。checkpointing 降激活，ZeRO/offload 降状态常驻，bf16+fp32 master 本身并不是额外省显存方案。要保留单条长依赖可用 Ulysses/Ring-Attention 类 context parallel，且需区分 Megatron 通常所说的 sequence parallel；切分或压缩会改变可见上下文和任务，应重新校验目标。把历史作为条件但 loss mask=0 不会自动切断经过历史激活的梯度，真正 detach/KV 缓存需显式实现。资源和业务不允许时可按预设长度过滤，记录覆盖损失，并用独立长任务评测补足边界，不要求所有被过滤样本都 teacher 重写。

**问题（追问）：把超长样本直接删掉会怎样？**

回答：长样本往往对应最难的那部分任务（多跳、多约束、长文档聚合），删掉等于对难度分布做隐式截断，模型在最难的一档上永远拿不到梯度，表现是"简单题很好、难题怎么训都不动"。正确做法是先切分保语义、再上序列并行扩容；确实不可切分（单轮输出本身就超上限）时做长度上限过滤并由 teacher 重写压缩，同时把被过滤的比例作为数据侧指标记录下来，避免它悄悄接管训练集。

### 1.5 数据与评测

**问题：预训练数据的清洗漏斗分哪几级？为什么是这个顺序？**

回答：四级漏斗按单样本处理成本递增组织，每层只处理上层存活的样本。① 规则层：格式清理（HTML/PDF 抽取修复、去模板噪声）、字符集与长度规则、PII 与许可证过滤，成本近零，滤除格式明显损坏的样本；② 去重层：文档级精确哈希加 MinHash-LSH 近重，必须在打分前做——重复样本会污染打分统计且浪费打分算力；③ 质量打分层：fastText 级分类器或小模型 PPL 过滤全库打分，PPL 由小模型计算、设上下双阈值（过高判乱码与多语混杂，过低判模板堆砌与机翻）；④ 精细分级层：LLM 评判器多维打分，或用下游退火实验标定的分类器分档，高档料留给 decay 段上采样。各层保留率随语料来源差异很大，需按层统计并留档，用于回溯每一层的过滤量。边界：每层阈值先在"应留/应删"人工抽样集上标定、再用下游指标复核；过滤过狠伤长尾知识召回，规则层对代码与表格的误删高发。

**问题：去重分哪几级？MinHash 的原理是什么？阈值怎么定？**

回答：去重按粒度与成本分三级。① 精确去重：URL 或文档级哈希，去掉完全重复，成本近零；② 近重去重：MinHash-LSH 文档级——文档表示为 n-gram 集合，用 k 个哈希函数各取集合最小哈希值构成签名，利用 $\Pr[h_{\min}(A)=h_{\min}(B)]=\mathrm{Jaccard}(A,B)$ 把相似度估计转成签名比较，签名分 band 进 LSH 桶、同桶即候选近重对，把 O(N²) 两两比较压到近似线性；③ 语义去重：embedding 近邻（cosine 0.9 量级）抓改写变体，成本高，只用于高价值子集（SFT 数据与评测防污染）。MinHash 阈值即 Jaccard 相似度，语料级常用 0.8 上下。标定方法：抽样标注一批"应判重/不应判重"的文档对，扫阈值看误删率与漏重率（或看 Jaccard 分布的双峰间隙），再结合下游指标复核——阈值过低误删同模板不同实例（商品详情页、boilerplate 重的代码），过高漏重导致训练冗余与评测泄漏。配套两条：评测集对训练集要跑同一套近重检测（n-gram 重合率）；去重粒度可分文档、段落、句子三级，语料级别越细越保数据量。

**问题：训练数据的配比怎么定？**

回答：可以用公开配方作先验、小模型或短预算网格搜索、公共 checkpoint 分叉的退火探针来筛选候选。任何代理的排序迁移都需要检查，退火探针也不保证比其他方法更可靠，更不能测出所有桶之间的交互。探针应与同预算背景对照比较，固定起点、优化器状态、LR 与评测协议，并把多个分支、重复 seed 和公共前缀都计入成本。配比先明确输入 token 或监督 token 分母，固定通用 replay，在领域收益和通用回归的约束下选择，再用正式训练复核；按条数抽样不保证变长数据的 token 比例。

**问题（追问）：SFT 阶段多任务混合会不会出现此消彼长？怎么处理？**

回答：会，任务间梯度冲突与难度不均使弱任务的梯度被强任务主导，总 loss 平稳时任务间的此消彼长可能已经发生——所以监控必须看逐任务准确率曲线。处置四条：① 按能力缺口定向补数而非等比混——先跑 baseline 找短板任务，对短板类定向 1:1 补样本；② 分桶限量，防高频模式淹没长尾；③ 通道化——异构目标（长 CoT 推理与短直答）拆通道、system prompt 打标签、各通道独立 loss 权重，比硬混稳定；④ 两阶段——先混训打底，末期短退火段上采样弱任务。

**问题：评测集怎么构造才可信？**

回答：构造五要素。① 来源隔离：训练与评测按"源"划分而非按"条"——同仓库、同文档、同模板族的样本只出现在一侧，题面与参考解不进训练语料；② 难度标定：用 pass@k 或人工分层给难度先验，全对与全错的题区分度低，可在分析时单独标注，但仍计入总体指标，剔除会引入选择偏差；③ 判定可复现：能执行判定就不用模型打分，LLM-as-judge 要 rubric 分维度独立打、多次采样聚合、与人工标注校准系统性偏置；④ 规模按置信区间定：准确率在 50% 附近时，500 题的 95% 置信区间半宽约 ±4.4pp，100 题约 ±9.8pp，报告需带置信区间；⑤ 防过拟合机制：held-out 集与公开 benchmark 互为校验，公开榜涨而 held-out 不涨即过拟合警报。边界两条：自建集测相对变化不测绝对水位，横向对比仍要公开基准；评测模板（prompt、few-shot、答案解析器）必须冻结并写进评测卡，否则前后分数差里混入模板差异。

**问题：训练数据与评测集之间的污染怎么查、怎么防？**

回答：查与防两条线。查两道：① n-gram 重合——评测样本对训练语料算 8~13-gram 重合率（GPT-3 用 13-gram，重合即删或标记），n 太小误伤常见短语、太大漏掉改写；② 语义级——embedding 近邻补抓改写变体，高价值评测集必做。防三条：① 时间切分——评测集来源的发布时间晚于训练语料快照截止日，对新题类榜单有效、对沉淀多年的经典题无效；② 入库门禁——训练语料入库前对评测库全量跑去重，命中即删并记录；③ 变体探针——对疑似污染题做数值与实体改写重测，分数骤降说明记住的是原题而非能力。边界两条：污染检测只能证重合不能证因果，报告应同时给重合率与去重合后的分数；agent 时代还有轨迹级污染（工具返回与环境里带答案），要靠环境侧注入隔离（truth 只在判分阶段注入）。

**问题：perplexity 怎么计算？为什么不能把它当作主指标？**

回答：PPL=exp(有效目标 token 的平均负 logprob)，通常使用自然对数。比较需固定 tokenizer、语料、上下文窗口、滑窗/截断策略和监督分母；相同分词与协议下不同模型可以比较，不能笼统说“跨模型不可比”。不同 tokenizer 的每 token PPL 不能直接横比，可另定义 bits/byte 或字符级指标。held-out PPL 是语言建模指标，可用于同模型 checkpoint 和分布拟合比较，但不保证随训练单调；低 PPL 也可能来自重复记忆或模板，不能直接等价高质量/高下游能力，过滤需按领域人工校准。

**问题：pass@k 和 majority vote 分别度量什么？k 怎么定？**

回答：pass@k 度量能力上界：同题独立采样 k 条、至少一条正确的比例，报告时用无偏估计 $1-\binom{n-c}{k}/\binom{n}{k}$（n 总采样数、c 其中正确数，n 大于 k 以压低估计方差）。majority vote（self-consistency）度量共识可靠性：k 条答案投票取多数，依据是正确推理路径殊途同归、错误路径各自分散的经验性质；不需要验证器，但只适用于答案可聚合的任务（数学、选择题），代码补丁这类结构化产物不能直接投票。k 按用途定：能力上界评估报多档（1/8/16，RL 后训练常用 16 档评估提升空间）；投票 8~16 条边际收益已递减。选优场景三个数要并列报：pass@k（上限）、选优后正确率 $P_{sel}$（经验证器或投票从 k 条中选出一条后的正确率）、归一化比值 $(P_{sel}-P_1)/(P_k-P_1)$（选优机制实现了多少理论收益）。边界两条：pass@k 高不等于可用——没有可靠选优机制时线上仍是 pass@1；模型有系统性偏置时投票会一致地错，温度过低则 k 条趋同、投票退化。

**问题（追问）：pass@k 低是不是就说明任务难？**

回答：不能直接等价，低分可能来自模型能力、预算/采样设置、题面与 gold 错误或环境缺陷。代码任务先验证基线 F2P/P2P，再确认参考解可应用且测试稳定；换异构强模型只能增加诊断信息，多个模型都失败仍可能是真难题，不能据此推断题目有缺陷。有限 n 次零成功也不等于真实成功概率为零，需报告采样数与不确定性。题目准入还要检查题面语义、测试约束与可复现环境，不只检查参考补丁通过。

## 2. Coding Agent 方向高频

**问题：仓库原生测试不足时，模型生成的测试能否用于判分？需要哪些约束？**

回答：模型生成的测试可作为补充，用于 PR 只修改代码而未修改测试的实例，主体仍应是从 PR 的测试改动中提取的原生测试，合成测试的占比按下游验证结果设定上限。风险与弱测试的失效模式一致（见测试断言一题），其中最突出的是生成时可见 golden patch 导致测试内联解法。治理分三层。信息隔离：生成测试时只提供 issue 与被测接口签名，不提供 golden patch，生成后做 test patch 与 code patch 的相似度泄漏检测。执行校验：合成测试与原生测试通过同一套三项校验，并追加对抗补丁检验，硬编码特判补丁能通过的测试弃用。评分审查：按正确性（断言与题面语义一致）、确定性（重复执行结果稳定）、边界覆盖三项打分，低于阈值的整组重新生成。还需单独校验测试与 issue 的一致性，因为执行校验只应用补丁、不读取 issue：把 issue 归纳为行为断言清单后与各测试的被测意图逐条匹配，并比对未应用补丁时的失败输出与 issue 症状。合成测试未经人工评审，证明力低于原生测试，评测集不使用合成测试判分。

**问题：测试断言约束不足与约束过强如何识别与治理？**

回答：SWE-bench+ 在 SWE-Agent+GPT-4 被判已解决的补丁中审计出 31.08% 弱测试可疑通过；剔除泄漏及弱测试下的可疑修复后，按其原评测分母重算解决率从 12.47% 到 3.97%，不是删题后直接比较两个榜单。UTBoost 在测试不充分实例的原判通过补丁中重判 28.4%（Lite）/15.7%（Verified）为错，不能把该比例外推全库。治理分三层：静态统计断言、覆盖与补丁相似度；执行变异/对抗补丁并确认其确实违反规格；语义对照测试与 issue 的行为要求。LLM 生成的“等价补丁”仅是候选，失败不自动证明测试过强，需人工或差分测试验证等价性。绑定错误消息、覆盖参考修改行或高相似度本身都不证明好坏，必须看任务规格。来源：SWE-bench+ §2、UTBoost 的增强测试实验。

**问题（追问）：变异测试的成本如何控制？**

回答：成本为实例数、变异体数与单次测试时长三者的乘积。控制手段有三项。第一，只对入库前的候选任务执行，属于一次性开销，训练期不重复。第二，限制变异体数量，由 LLM 针对缺陷类别生成少量定向变异体，替代对全部算子的枚举。第三，只执行与被修改函数相关的测试子集（选择方法见测试子集一题）。变异体存活率高的实例进入人工复核或补充测试，不直接入库。

**问题（追问）：只能实施一层治理时如何取舍？**

回答：优先实施对抗补丁检验。该检验直接针对危害最大的失效，即错误或不完整的修复被判为通过，在 RL 中对应错误的正奖励。需要注意空补丁与只改注释的补丁不改变程序行为，F2P 用例必然仍然失败，在已做 F2P 校验的前提下这两类补丁没有检出能力；有效的对抗补丁是硬编码特判、单分支修复与 golden patch 的定向变异体。静态规则成本接近零，可同时执行；变异测试的全量执行与语义对齐作为增强项。

**问题（追问）：弱测试进入 RL 训练会造成什么后果？**

回答：弱测试产生错误的正奖励。只对测试输入做特判、或只修复部分分支的候选补丁获得与正确修复相同的奖励；组内归一后，这类样本抬高组内均值，使同组正确样本的优势被压低，策略被引导至迎合测试的方向，形成 reward hacking。蒸馏同样受影响：拒绝采样只保留判为通过的轨迹，弱测试会让未真正解决问题的轨迹进入 SFT 数据。因此弱测试治理应放在数据准入阶段完成，训练期难以弥补。

**问题：跨文件、repo 级的高难度任务如何构造？**

回答：真实 PR 经筛选后以单文件、小改动为主，提高难度有两种方法。第一种是 PR 合并：由模型基于仓库上下文把语义相关的多个 PR（同一特性或同一次重构）合并为一个跨文件、跨模块的任务，并生成合并后的题面，要求模型完成多步定位与多文件修改。第二种是扩大注入跨度：按调用图选择多个相关函数同时注入缺陷；SWE-smith 的组合缺陷方式即把同一文件或模块内已验证的多个缺陷补丁合并。两种方法的产出都需重新执行校验：合并任务的 F2P 与 P2P 用例集合应在合并后的修复前、修复后两个代码状态上重新执行得出，由子任务的用例集合做并集与交集只能作为初值，因为各子 PR 的基准提交不同。子改动之间缺少语义关联时题面无法自洽，这类合并应弃用。难度标签使用两类特征：静态特征（改动文件数、diff 规模、跨文件依赖深度、issue 描述位置到修复位置的距离）与行为特征（参考模型多次采样的通过率）。构造完成后按任务结构、依赖复杂度、测试密度、语言四个维度与真实任务对照分布。

**问题（追问）：如何根据失败轨迹判断模型在任务链路的哪一环节不足？**

回答：按执行证据记录候选原因：F2P 部分通过提示修复不完整，P2P 回退提示回归，工具错误需区分非法参数与基础设施故障。修改文件与 golden patch 无交集只能提示可能定位偏离，golden patch 不是唯一可行实现；结合症状、调用链、测试与补丁语义复核，不把合法替代修复误标。失败类别可多标签，不能只按一个指标确定根因。数据补充对应定位、完整修复、验证与错误恢复能力，并用独立评测确认改善，不自动将“不完整”全部归因于任务不够难。

**问题：沙箱超时或初始化失败的样本在训练中如何处理？**

回答：按责任而非错误字符串分类。容器未启动、服务故障等基础设施失败可重试或在计算组统计前移除，补齐预设 group size；补丁引入死循环、资源爆炸或模型非法命令造成的超时属于模型失败，不能借“超时”标签剔除。可用稳定基线/参考解在同环境重放辅助诊断，但单次对照不是完备归因。固定预算评测中候选超时记未通过并计入总体分母；训练中基础设施缺失另报，不当作任务 reward=0。生成/轮数预算耗尽则按产物可判性选择失败、强制提交后判分或屏蔽/软惩罚，与服务超时分开统计。

**问题（追问）：环境失败的任务是否永久丢弃？**

回答：不丢弃。环境失败说明执行条件有问题，任务本身的题面与测试仍然有效。做法是维护两张表：可判分任务池记录通过三项校验的任务，环境健康状态表记录每个任务镜像最近的执行结果。任务失败时只更新健康状态并暂停调度；环境修复并重新通过 golden patch 校验后恢复调度。长期无法修复的任务才从任务池移除。

**问题：teacher 模型如何选择？蒸馏轨迹的质量如何保证？**

回答：teacher 按目标任务通过率、工具协议遵循与单位成功成本选择。最终产物执行 F2P/P2P，过程审计权限、隐藏 gold/PR 访问与关键决策依据；合法读取仓库和引用资料的重合不自动判作弊。通过轨迹中比较效率，但保留多种合理解法，防止只选最短导致覆盖退化。teacher 轨迹通常用于 SFT；标准在线 RL 用学生采样及真实 behavior logprob，若引入 off-policy 教师数据需另有明确算法。teacher 解不出的任务也可能由其他教师/人工示范进入 SFT，不是必须留给 RL。

**问题（追问）：teacher 与学生模型的对话模板不一致时如何处理？**

回答：蒸馏前把 teacher 输出转换为学生模板。动作格式按字段逐项映射（工具名、参数名、参数取值格式），思考段与动作段的分隔标记替换为学生模板的标记，转换后抽样检查能否被学生侧解析器正确解析并在环境中重放。模板不一致若未处理，学生在训练时见到的格式与推理时环境要求的格式不同，是训练与推理不一致的常见来源，表现为格式错误率偏高。

**问题：如何防止学生模型学到 teacher 轨迹中的捷径行为？**

回答：teacher 与学生在工具权限、状态转移和信息边界上对齐；预算可有课程差异，但不能把学生不存在的操作直接当正例。审计未经授权的工具、隐藏测试/gold 访问和未核验的产物，不将合法仓库代码重用、检索引用或任务允许的测试修改自动判为捷径。禁用可疑渠道后多次复测可提供依赖证据，但渠道本来合法时，性能下降不证明作弊。重放、规格审查与人工抽检结合后再剔除，保留不同合理解法。

**问题：失败轨迹如何利用？**

回答：按失败原因分三类处理。环境失败：剔除，不利用（见环境失败一题）。能力不足导致的失败（推理方向合理但未完成）：有三种用法。提示后重生成：在失败位置注入提示后重新生成，成功的轨迹带提示标记并降权进入训练。失败点定位与局部重生成：保留前段，从出错步骤重新采样。用作负例：作为 DPO 偏好对中的被拒样本，或过程奖励模型的负样本。捷径型失败（作弊行为被检出）：剔除并加入检测规则库，不作为负例，因为其负例信号的含义不明确，模型可能学到规避检测而非放弃该行为。出错步骤的定位采用分叉重采样：从第 k 步的前缀分叉，重新采样 n 条后续并统计通过率，通过率在某一步之后明显下降，则该步为主要责任步骤。通过率关于 k 不保证单调，且每个分叉点需要足够的采样数，因此定位结果是概率性估计，成本随轨迹长度增长。

**问题（追问）：能否直接对失败轨迹施加负 reward？**

回答：若是纯二值 outcome、同组全部奖励做正仿射变换且忽略 ε，z-score 不变，{成功1/失败0} 与 {成功1/失败−1} 等价；存在稠密分项、硬门、多失败等级或 ε 不可忽略时不能套用。完整 reward 相同的组 task advantage=0，但启用 KL/熵项仍可有梯度。模型失败可作负信号，基础设施失败需移除，预算截断按任务判分协议处理。即使不组内标准化，给所有样本加常数在理想 REINFORCE 中也可被合法 baseline 抵消，不能由“失败有负 reward”直接断言策略必然更保守。

**问题：来自多种 Agent 框架（harness）的轨迹如何统一用于训练？**

回答：不同 Agent 框架的原子工具差别较大：搜索方面有的提供专门的代码检索工具，有的只有终端 grep；编辑方面有的按片段定位，有的按行号或全文替换；消息结构与调用协议也不同。接入多种框架的目的是泛化，使模型见过多种工具范式并能适配新的框架。做法是定义统一的训练格式，对工具名、参数、返回结构逐字段映射，同时保留各框架的调用特征与行为分布，不把所有框架归并为同一套工具。映射的正确性需启动真实服务执行对比 rollout 来验证，仅阅读框架源码不够，例如编辑类工具在片段定位与行号定位之间的转换容易出错。训练侧有两项设置。工具描述与参数 schema 写入 system 段并在训练时可见，使模型根据上下文中的描述选择工具。环境返回文本不计入 loss，teacher 轨迹中的工具调用（工具名与参数）计入 loss，因为训练目标包含何时调用哪个工具以及参数如何填写。适用边界是统一格式只解决表示层差异，各框架在上下文压缩、子任务委派等机制上的差异仍需通过保留原始行为分布来覆盖。

**问题（追问）：工具幻觉如何治理？**

回答：分别统计不存在工具/参数、schema 非法和语义误用，轨迹错误率与调用级错误率不能混用。工具顺序变化下性能下降提示位置先验，但不单独证明模型没读工具表。训练可乱序并加入易混/无关工具；随机删除只能删轨迹未调用的工具，若删掉目标工具必须重生成合法替代/拒绝轨迹，不能保留原调用标签。工具移除后无可行解的任务不应仍按原成功目标判分。区分格式硬校验与允许报错后恢复的完整任务成败。

**问题：长程任务（数十至上百轮交互）如何训练？为什么不宜直接在长 horizon 上开始 RL？**

回答：长任务可能起始task奖励全同，缺task优势差异，KL/熵仍可更新。可从可解子任务、teacher冷启动、预算/复杂度课程开始，但缩短预算不保证同题更易，升档不必每次再SFT。摘要形态需训推一致，外部摘要作观察，策略摘要作动作并记录behavior概率。预算耗尽按产物判分协议处理，不以无限摘要逃避预算。定位/复现/修复/验证事件可作弱辅助，gold文件集不代表唯一路径；事件奖励需reward-to-go或明确局部目标，原样只加当前token不保证正确信用分配。比较成功、成本、截断与任务覆盖。

**问题（追问）：长程任务如何评测？**

回答：在终态通过率之外增加三类过程指标：成功任务的成本（轮数、token 数、工具调用数）、无效动作占比（同一工具与规范化参数的组合在短窗口内重复出现的比例）、超时与截断率。长程任务单独分组统计，避免被短任务的通过率掩盖。面向长时间连续工作的场景，任务集应包含跨会话续做（上下文重置后依据摘要继续），并统计续做后首个操作的有效率，即不重复已完成的操作且参数可执行。

**问题：训练集与评测集之间的污染如何防控？**

回答：三项措施同时实施。仓库级切分：训练集与评测集的仓库不相交；同一仓库的不同任务之间仍有信息泄漏，模型可能已见过该仓库的代码结构与测试写法。时间切分：训练任务的提交时间全部早于某一日期，评测任务取该日期之后的新提交；评测任务的提交时间还应晚于基座模型的知识截止时间，否则基座在预训练中可能已见过评测仓库的修复提交，分数会被高估。重合检测：题面与补丁同训练集及可获得的预训练语料做 n-gram 与 embedding 两种相似度检测；golden patch 的代码片段单独检测，因为它可能经由 issue 描述或检索结果进入模型可见输入。另有两项操作要求。评测断网：联网评测时模型可能检索到原始 issue 或 PR，得到的分数不反映修复能力。公开集质检：公开基准存在环境损坏、参考答案错误、测试自身错误等问题题（见评测集构造一题），使用前应抽检；评测集的分数趋于饱和、失去区分度时，更换为更难且提交时间更新的任务集。

**问题（追问）：时间切分之后，早期任务还能使用吗？切分如何随迭代维护？**

回答：早期提交进入训练池，新提交进入评测池，滚动执行。每次更换基座或更新评测集时，按新的知识截止时间重新划定切分日期。配套维护一份评测集仓库名单，数据采集环节把它作为排除名单，防止后续迭代把评测仓库的数据采入训练集。时间切分对私有仓库同样适用，可以防止训练数据在多轮迭代后渗入评测集。

**问题（追问）：如何验证自建评测集没有泄漏？**

回答：先定义repo-disjoint、时间切分还是同仓库新issue泛化，不能所有实验都强制仓库交集为空。检查fork/镜像、题面、答案patch、PR与源材料近重，命中先复核，通用API/代码模板相似不自动删题。任务ID/片段复现补丁可提示记忆，也可能推理或公共实现一致，需多个特异细节、对照与来源证据，不能凭一次复现宣称见过训练题。报告训练可见范围与残留风险，未见近重也不是无污染证明。

## 3. 项目面试题

### 3.1 项目一：从真实代码仓库合成函数级编程任务与等价性判分

**问题：请介绍一下这个项目：输入是什么、产出是什么，你在其中负责哪些部分？**

回答：项目一为编程 Agent 的评测与短程训练供给函数级编程任务。输入是公开 Python 仓库，从 210 余个仓库抽取约 4.6 万个函数；产出是 1.4 万条任务包，每条包含签名、规格、隐藏判分测试、来源与覆盖率，评测时只给模型签名与规格，执行隐藏测试打分，训练时作为可验证样本进入 SFT 池，或以隐藏测试通过率作为 RL 的 reward。链路依次为函数抽取、依赖切片、插桩采集真实调用样本、测试合成、自等价校验、多轮反馈、规格提炼与打包。我负责等价性判分与依赖切片两个模块的设计与实现，参与插桩采集与多轮反馈生成的实现。

**问题（追问）：最终的效果用什么指标衡量？基准是什么？**

回答：两个指标。测试一次执行通过率指新生成的测试在参考实现上首次执行即通过的比例，基准是朴素流程（整仓上下文、测试写字面期望值），为 58%，加等价性断言与自等价校验后为 72%，加依赖切片后保持 72%，加运行时插桩后为 74%。覆盖率达标率指分支覆盖率达到 0.8 的函数占比，首轮 45%，第二轮 71%，第三轮 87%。另外同批 800 个函数上做了两种测试写法的抽检对照，抽检缺陷率由 28% 降至 1.9%。

**问题：数据从哪里来？候选函数怎么筛选？训练集和评测集怎么隔离？**

回答：数据来自公开 Python 仓库，抽取公开函数与方法，剔除依赖网络、文件系统或系统时间的函数，这部分约占候选的一成。210 余个仓库抽取约 4.6 万个函数，经自等价校验、三轮反馈、规格可解性检查与去污染过滤，入库 1.4 万条，留存约三成，计数单位是任务包。隔离按 `source_ref` 的仓库维度切分，同一仓库只出现在训练或评测一侧；与公开代码基准使用的仓库重名者列入黑名单过滤。同一仓库的不同函数共享代码风格与辅助函数，按函数切分会让模型凭记住的仓库源码得分。

**问题：为什么不让模型直接写出输入与期望输出？等价性判分具体怎么做？**

回答：期望输出需要模型在脑中执行函数，`Decimal` 舍入、空字段保留、生成器惰性求值这类细节经常预测错。同批 800 个函数抽检，预测期望值写法的缺陷率为 28%。等价性判分的测试不写字面期望值，把候选实现与参考实现加载进同一环境，对同一组输入分别调用并比较：返回值直接比较，浮点数按相对误差 1e-9 比较，不可直接比较的对象比较序列化结果，异常路径比较异常类型与消息。原函数即 oracle，抽检缺陷率降到 1.9%，测试一次执行通过率由 58% 提升至 72%。

**问题（追问）：自等价校验是什么？拦截了多少？**

回答：每条新测试先用参考实现同时充当候选与参考执行一遍，理论上必然通过；未通过说明测试自身有缺陷，例如调用了不存在的 API、输入不满足前置条件、依赖缺失或断言写反，此时标记 `test_defect` 拦截。拦截约 7%，一批 1 万条新测试中约 700 条在入库前被剔除。这一步把测试自身的缺陷与候选实现的缺陷分开，判分失败时只会是候选实现的问题。

**问题（追问）：参考实现自己有 bug 怎么办？**

回答：等价性判分把参考实现的行为当作标准，参考实现的 bug 会被保留为任务语义。处理方式是在规格提炼时以已通过测试验证过的行为为准写规格，例如参考实现对空输入返回 `[""]`，规格就明确写出这一行为，候选实现复现同样的行为即判通过，任务语义与规格一致。代价是任务考察的是复现既定行为，部分任务与「写出合理实现」略有差别。

**问题：判分为什么要在新容器里执行？判分资源是怎么配置的？**

回答：候选实现所在的工作区可能残留模型自写的测试与配置，例如在 `tests/` 下写一个总能通过的测试，或在 `pytest.ini` 中改变收集规则。判分时每次新建 Docker 隔离容器，先删除候选工作区中的测试目录与 `pyproject.toml`、`pytest.ini` 等配置，再写入隐藏测试，用固定的 `PYTHONPATH` 执行，只回收逐测试的通过结果，不读取候选源码。容器 32 并发，单例超时 600s，一批约 4 小时。

**问题（追问）：判分时遇到过环境噪声导致的误判吗？怎么定位和处理的？**

回答：遇到过。现象是部分任务的候选实现被系统性压分，全部测试失败，而参考实现在本地可以通过。排查顺序为：先看失败批次的报错类型分布，再看这些任务的参考实现在相同镜像中是否通过，最后看容器初始化日志。定位到容器初始化阶段输出的 `SyntaxWarning: invalid escape sequence` 一类警告被当成测试失败计入。处理是把这类环境噪声单列状态，不计入判分分母，初始化失败的任务重新执行；处理后这批任务的判分恢复与参考实现一致。

**问题：依赖切片是怎么做的？为什么不直接按文件截断？**

回答：整仓供给时上下文均值约 2.4 万 token，同名但语义不同的辅助函数会被模型误用，大仓库超过 32K 上限后被随机截断。依赖切片先把源文件解析为 AST，以语句为节点建依赖图，函数体、默认参数、装饰器与类型注解中引用的名字连边到定义；再用 PyCG 调用图补全跨文件调用；从目标函数起展开 3 层，第三方包只保留 `import` 语句。按文件截断对跨文件依赖多的函数会缺符号，对单文件很大的函数仍然太长；切片按执行时会用到的定义选择上下文。切片后上下文均值降至约 9.6 千 token，超出 32K 被截断的请求由约 6% 降到 0.3%。

**问题（追问）：切片深度为什么取 3 层？试过哪些档位？**

回答：扫描了 1、2、3、5 层与全展开，看两个量：无缺失符号的函数占比与上下文长度。1 层为 71%，缺失的多是二级辅助函数，模型只能猜其行为；2 层为 89%；3 层为 96.5%；5 层为 97.1%，上下文比 3 层长约四成；全展开没有额外收益，少数高耦合函数的闭包超过 32K。3 层是符号完整率的拐点。

**问题（追问）：切片之后一次执行通过率没有变化，怎么说明切片是有用的？**

回答：切片的作用对象是上下文成本与符号完整性，不是测试的可执行性。对照实验在等价性断言已开启的条件下进行，一次执行通过率保持 72%，说明上下文缩短约六成没有降低合成质量；收益体现在三处：合成上下文均值由约 2.4 万 token 降至约 9.6 千 token，单批 1 万条请求的输入 token 由 2.4 亿降到 0.96 亿，截断请求由约 6% 降到 0.3%。归因时把一次执行通过率的 +14pp 记在等价性断言上，把切片记为 +0pp，这样每一行的增量只对应一个改动。

**问题：动态导入和反射这种静态分析追不到的引用怎么处理？**

回答：`importlib.import_module`、`getattr(obj, name)` 一类引用按保守策略处理：出现动态导入的模块整体纳入切片；仍无法解析的名字进入保留白名单，执行前检查符号完整性。代价是大量使用元编程、插件注册或 ORM 动态字段的仓库，切片后的上下文明显变长。PyCG 调用图按仓库缓存，同一仓库的多个函数共享一次构建，抽取阶段 CPU 64 并发约 2 小时/万个函数。

**问题：运行时插桩采集的是什么？对结果有什么影响？**

回答：模型凭直觉构造的输入过于典型，覆盖不到真实调用中的边界形态，还可能违反隐式前置条件（如要求输入已排序）。插桩在执行仓库自带测试与示例时挂 hook：`before_call` 用 `inspect.signature(func).bind` 绑定实参并展开默认值，`after_call` 记录返回值与类型，同时记录调用者；超长值保留首尾各 90 字符；每个函数保留最近 3 条记录，随合成请求作为真实调用示例。有副作用的函数不启用采集。开启后边界输入覆盖相对提升约 20%，一次执行通过率由 72% 提升至 74%。

**问题（追问）：每个函数保留几条记录？为什么？**

回答：扫描了 1、3、6 条。1 条时边界输入覆盖相对提升约 9%，模型容易把唯一样本当作全部输入形态；3 条时约 20%；6 条时约 21%，但合成请求增加约 720 token，同一调用者的重复样本增多。定稿 3 条，单个请求增加约 360 token，约占切片后上下文的 3.8%。

**问题：多轮反馈是怎么设计的？终止条件为什么这样定？**

回答：一次生成难以同时满足可执行与覆盖率，首轮覆盖率达标率只有 45%。每轮只处理未达标函数，按失败原因分两类反馈：执行报错时回传异常类型、消息、出错的测试函数与行号，要求只改出错的测试；覆盖不足时回传未覆盖分支所在行、条件表达式与已覆盖分支数，要求新增用例、不删除已有用例。终止条件为单函数分支覆盖率不低于 0.8 且整批达标函数占比不低于 0.8，或达到 3 轮。达标率由首轮 45% 提升至 71%、87%，第二、三轮的容器用量分别约为首轮的 55% 与 29%。

**问题（追问）：整批达标比例试过哪些档位？为什么不要求全部达标？**

回答：扫描了 0.7、0.8、0.9。0.7 档两轮即终止，入库任务减少约 12%；0.9 档需要五轮，第四、五轮新增达标不到 3%，容器成本翻倍；取 0.8，三轮终止。不要求全部达标，是因为剩余约 13% 的函数多依赖外部状态或输入难以构造，继续重试会无限消耗预算。单函数覆盖率门槛取 0.8，取 0.95 时防御性分支无法覆盖，达标率停在 60% 左右；取 0.5 时测试只覆盖主路径，判分区分度不足。

**问题：如果某一批任务的模型评测通过率突然异常高，你会怎么排查？**

回答：先验证判分是否真的在执行：看这批任务 collection 阶段的报错率与单例执行耗时，耗时异常短说明测试可能没有真正运行。再看测试断言类型：是否大量只做「可导入」「有某属性」一类形状断言，这类测试空实现也能通过。最后看答案可达性：候选实现能否读到参考实现源码或隐藏测试文件。根因通常是测试过浅或判分镜像残留了答案可达路径；前者对相关函数重新合成并要求测试在空实现上失败，后者从镜像中移除参考实现目录后重新判分。

**问题：规格为什么不直接用 docstring？规格写多长？**

回答：约三成 docstring 只有一句「Returns a list of fields.」一类描述，省略了空输入、异常与舍入等边界行为，模型据此写出的实现在边界上与参考实现不同，失败原因在规格不足。规格以 docstring、签名与已通过的等价测试为材料，由合成 teacher Qwen3-Coder-480B-A35B-Instruct-FP8 改写为 3 至 8 句：先写功能，再写参数约定，最后给 1 至 2 个取自测试输入的示例与异常约定。不限长度时 teacher 会把测试逐行翻译成自然语言，相当于泄露判分测试；不超过 3 句时示例放不下，可解性检查退回率升到约 19%。

**问题（追问）：怎么确认规格足够让模型写出正确实现？**

回答：做可解性检查。用独立部署的 Qwen3-32B 只读签名与规格实现函数，采样 4 次，用隐藏测试判分；4 次全部失败的任务退回重写，第二次仍全部失败则剔除。首次退回约 8%；对照直接用 docstring 作为规格，同一检查的退回率约 31%。采样 1 次时偶然失败会误退约 6% 的可解任务，采样 8 次结论与 4 次基本一致、成本翻倍。

**问题：合成 teacher 选的是哪个模型？为什么？**

回答：测试合成与规格改写用 Qwen3-Coder-480B-A35B-Instruct-FP8，在 8×H100 上自部署，temperature 0.7，单条最多尝试 3 次，单请求上下文不超过 32K；规格改写用 temperature 0.3。选它有三个原因：测试合成是代码任务，代码专用模型对 pytest 写法与 Python 语义的把握更好；官方提供 FP8 权重，8 张 H100 即可部署，单批 1 万条合成约 6 小时；自部署没有 API 调用量限制，适合万级批量。可解性检查用的是能力更弱的 Qwen3-32B，与合成 teacher 分开，避免用同一个模型既出题又验题。

**问题：如果数据源从 Python 换成 TypeScript 仓库，这套方案哪些要改？**

回答：等价性判分的思路不变，执行层要改：TypeScript 需要编译与模块解析，判分容器要预装 node 与对应版本的 TypeScript，对照执行改为在同一进程中加载两个实现模块。依赖切片要重写，PyCG 只支持 Python，需要换成基于 TypeScript 编译器 API 的调用图，类型声明文件需要单独纳入闭包。插桩改为对导出函数做 wrapper。规格提炼与多轮反馈可以沿用，覆盖率工具换成 istanbul 一类的分支覆盖统计，门槛 0.8 需要重新扫描。

### 3.2 项目二：仓库级编码 Agent 长程轨迹的质量筛选与增强蒸馏

**问题：请介绍一下这个项目，任务是什么形态，你负责哪些部分？**

回答：项目二面向仓库级编码任务：Agent 接收一份整库规格，在空工作区从零实现一个可安装、可导入的 Python 库，判分在新容器中运行上游仓库的原有测试，单条轨迹上百轮工具调用、数万 token。任务库与 rollout 由团队完成，项目二从轨迹导出开始，依次做 stream-json 消息聚合与配对校验、失败断言到出错动作的归因、关键决策点的过程监督注入、压缩恢复样本合成，最后在 Qwen3-32B 上做全参蒸馏 SFT 并扫描增强样本配比。我负责过程监督注入与压缩恢复样本合成两个模块的设计与实现，参与轨迹导出、失败归因与配比实验。

**问题（追问）：这个项目和项目一是什么关系？项目一的函数级任务能产生百轮轨迹吗？**

回答：两个项目面对两种粒度的任务。项目一的函数级任务输入是签名加规格，几轮交互即可完成，不会产生百轮轨迹；项目二的轨迹来自仓库级任务，模型要先读规格、规划包结构，再逐模块实现、安装、运行测试、修复，整个过程展开到上百轮。项目一的任务包不作为项目二的 rollout 输入。两者共用两套口径：判分都在新建容器中删除模型自写的测试与配置后运行隐藏测试；训练集与评测集都按仓库维度切分。

**问题：数据从哪里来？规模多大？入训的样本是怎么构成的？**

回答：数据是仓库级任务的 rollout 轨迹，共 2,700 余条，teacher 为 Qwen3-Coder-480B-A35B-Instruct-FP8，每任务 rollout 2 次、最多 150 轮。导出时配对校验剔除约 3%，约 2,620 条进入归因与筛选，筛选后保留成功轨迹 1,730 条。入训量为 2,310 条样本：成功轨迹 1,730 条，过程监督注入版 444 条，压缩恢复段 136 条，增强样本占 25%。计数单位是样本，一条成功轨迹与它的注入版分别计数。评测集是 96 个 held-out 仓库级任务，与训练任务按仓库切分，与公开基准重名的仓库列入黑名单。

**问题：stream-json 轨迹导出时遇到了什么问题？怎么处理的？**

回答：rollout 日志按 stream-json 逐块输出，同一轮的思考、文本与多次工具调用被拆成多条带同一 message id 的记录，逐条转换会产生重复的 assistant 轮次与孤立的工具结果。导出时按 message id 合并同轮内容块，转为 OpenAI messages 格式，为全部消息重建全局索引 `g{N}`；再校验三项：每个 `tool_calls[].id` 都有且只有一个对应的 `tool_call_id`，assistant 与 tool 消息交替顺序合法，末尾没有未返回的调用。失败的轨迹整条剔除，约占 3%；合并重复轮次后，单条轨迹的 assistant 消息数平均减少约 37%。

**问题（追问）：配对校验失败为什么整条剔除，不做修补？**

回答：试过两种修补：删除孤立的工具结果，会让模型看到「调用后没有返回就继续推理」的形态；为悬空调用补一条空返回，会让模型学到对空结果的错误反应。两种修补在抽检中都产生了不自然的样本。失败轨迹约 81 条，约六成来自 rollout 超时被强制结束，约四成来自日志写入中断，只占约 3%，整条剔除带来的数据减少可以接受。

**问题：低分轨迹是怎么归因的？归因结论怎么用？**

回答：三层证据链。判分层从上游测试输出取失败用例、报错类型与 file:line，collection 阶段报错单独标记；轨迹层沿全局索引倒序查找最后一次改动出错文件的 Write 或 Edit，定位引入错误的轮次；归因层归入九类失败模式：过早终止、未完成、上下文截断、导航空转、盲改、依赖与包结构失败、自测与判分验证方式不一致、资源耗尽、答案获取，按高、中两档标严重度。在上游测试通过率不足 0.5 的约 1,100 条轨迹中，超过 95% 归因到验证方式不一致，约 46% 同时命中依赖与包结构失败，约 38% 同时命中过早终止。结论用于分流：答案获取类整条剔除，环境失败类重投，其余按通过率与最长盲改分流。

**问题（追问）：归因统计时有没有遇到过结论相反的情况？**

回答：遇到过。曾在按低分条件筛出的子集上统计答案获取类的影响，结论是答案获取没有带来高分；在全量上统计，答案获取类轨迹的平均得分明显更高。原因是低分子集的筛选条件系统性排除了高分轨迹，而答案获取恰好集中在高分区。验证方式是把筛选条件逐步放宽，观察结论在哪一步翻转。此后成因统计一律用全量，必须用子集时写明子集条件与被排除的样本。统计还按两列分开报告频率与命中样本均分，例如未完成类只有 12 条，均分 0.07，属于低频高危。

**问题：过程监督注入是怎么想到的？要解决什么问题？**

回答：归因显示低分的首要原因是自测与判分验证方式不一致，表现为模型没有执行上游风格的测试就宣告完成。成功轨迹里同样的行为也存在，只是结果恰好正确，原样蒸馏后学生学到的是「写完就宣告完成」的动作序列。逐轮打结构化阶段标签的做法与推理时的自然输出形态不一致，学生会复述标签格式。因此改为在少数关键位置写一段与该位置真实状态一致的英文回顾，只写已完成什么、还差什么、验证依据是什么，不给操作指令。

**问题（追问）：注入点怎么选？预算怎么分配？**

回答：沿全局索引扫描九类主触发点：完成宣告、报错到修复的拐点、首次执行测试、最后一次执行测试的前一轮、任务阶段边界、任务分解后的首次编辑、盲改段起点与终点、规划清单更新点；token 突增点与重读密集点作为备选。完成宣告点必定注入，不占预算。其余候选数为 n、上限 S=10 时，基础预算为 $\max(1,\lfloor nS/(n+S)\rfloor)$，轨迹超过 10 万字符加 2、超过 5 万字符加 1，最小间隔 $\max(2,\lfloor n/(e+1)\rfloor)$ 防止聚集。例如 n=24、长 7 万字符时预算为 8，质量门通过约 45%，最终写入 3 至 4 处。

**问题（追问）：注入文本由哪个模型生成？怎么保证不破坏样本结构？**

回答：注入模型为 Qwen3-235B-A22B-Instruct-2507，8×H100 自部署，temperature 0.6。选它是因为输入是触发点之前的整条轨迹，常有数万 token，它的原生上下文为 256K，写英文自然叙述的能力强于代码专用模型；输入另附触发点之后真实发生的 3 个动作，规划类回顾与真实进程一致。写回时注入文本前置拼接到该条 assistant 消息的 content，`tool_calls` 字段不变，从完整存档读取后写回。质量门只用规则：40 至 120 词、包含 completed、remaining、not yet verified 一类状态词组，完成宣告点须提及验证依据，不达标丢弃该点、保留整条轨迹。8×H100 约 5 小时处理 1,000 条轨迹。

**问题（追问）：候选注入点上限为什么取 10？注入版为什么和原版并存？**

回答：S 扫描了 5、10、20。S=5 时长轨迹的中后段几乎没有注入点；S=20 时单条轨迹平均注入 7 处以上，学生推理时出现每次工具调用前都写一段回顾的倾向；取 10。只保留注入版时学生的回顾频率偏高；注入版与原版并存时，学生在关键位置写回顾，在常规编辑位置直接调用工具。1,730 条成功轨迹中有 444 条产出了合格的注入版。

**问题：过程监督注入和 PRM 有什么区别？**

回答：两者作用的对象不同。PRM 是一个给中间步骤打分的模型，在 RL 中把步骤分数并入 reward，或用于候选排序，作用于优化目标，需要额外训练 PRM，并承担 PRM 被 reward hacking 的风险。过程监督注入改变的是 SFT 数据本身，把状态回顾写进 assistant 消息，模型按常规 SFT 学习在关键位置产生什么样的状态判断，不需要额外模型，推理时没有额外开销。PRM 教的是哪种步骤得分高，注入教的是如何做状态判断；两者可以叠加使用。

**问题：压缩恢复样本要解决什么问题？切点怎么选？**

回答：推理时上下文达到上限会触发压缩，压缩后的模型常凭记忆直接编辑文件，或反复重读同一批文件，对照组中经历过压缩的轨迹中位得分约为未压缩轨迹的一半。训练数据全部是完整上下文，学生没有见过只剩摘要的输入。合成时逐轮按字符数除以 3 估算 token，累积约 5 万 token 后，向后找第一个下一轮为 Read 或测试命令的轮边界切分，切点后至少保留 4 轮。前段原样保留，后段的历史改由九段有损摘要重建，再接恢复引导与切点之后的原始消息。

**问题（追问）：切分阈值为什么是 5 万 token？为什么要顺延到重读或测试的轮次？**

回答：扫描了 3 万、5 万、8 万。3 万档每条可切出 3 段以上，摘要占比过高，学生在没有压缩的场景也倾向于先输出总结；8 万档只有约 28% 的长轨迹满足尾部条件，样本太少；取 5 万，比真实压缩点更早，中等长度的轨迹也能切出样本。直接在阈值处切分时，约四成后段的第一个动作是 Write 或 Edit，相当于示范压缩后接着盲改；顺延后第一个动作就是重读或验证。

**问题（追问）：摘要和恢复引导有哪些约束？**

回答：摘要使用与推理时运行时一致的九段模板：主要诉求、关键技术概念、文件与代码段、错误与修复、问题解决过程、用户消息、待办任务、当前工作、下一步，每段 1 至 5 句，另附最后一次 Read 的文件路径与截断内容。恢复引导要求先确认文件当前内容与测试状态再修改，且不得出现 compaction、summary、context limit 等词，因为推理时的指令要求模型不提及摘要，训练数据中出现自指描述会造成训练与推理不一致。一批 136 段样本工具调用配对零错位，质量门删除约 3%。

**问题：压缩恢复样本和运行时的上下文压缩策略是一回事吗？**

回答：两者作用的对象不同。运行时压缩策略决定推理时何时压缩、保留什么，例如按工具输出长度分级裁剪或生成摘要，作用于推理系统。压缩恢复样本是训练数据，作用于模型本身，让学生见过「前面只剩摘要」的输入，学会压缩后的第一个动作是重读或验证。两者需要配套：训练数据的摘要模板必须与运行时的摘要格式一致，换运行时就要同步改模板。另一类方案是用 RL 训练模型主动管理上下文，属于在训练目标中加入压缩行为，成本高于在 SFT 数据中补样本。

**问题：学生模型为什么选 Qwen3-32B？上下文怎么处理？**

回答：Qwen3-32B 是 64 层 dense 模型，原生上下文 32K。选 dense 是因为百轮长轨迹 SFT 要开 128K 序列，dense 模型在长序列训练下没有 MoE 路由负载不均的问题，16×H100 的显存与吞吐也能承受 32B 级全参训练。轨迹样本均长约 3.6 万 token、最长超过 10 万，不扩展上下文就要截断，截去的恰好是末尾的验证与完成宣告。训练时在 RoPE 上启用 YaRN 因子 4，原始最大位置 32,768，序列上限 128K，训练与推理使用同一配置。

**问题（追问）：SFT 的超参与资源是怎么配置的？**

回答：全参更新，bf16，lr 1e-5，cosine 衰减，warmup 3%，global batch 16 条序列，2 epoch。入训 2,310 条样本，均长约 3.6 万 token，每 epoch 约 8,300 万 token、约 145 步，2 epoch 共 290 步，平均每步约 57 万 token。只对 assistant 消息计 loss，system、user 与 tool 消息全部掩码。16×H100，开 context parallel 与 gradient checkpointing，单步约 2.5 分钟，2 epoch 约 12 小时，每 50 步保存一次 checkpoint。

**问题（追问）：epoch 为什么取 2？checkpoint 怎么选？**

回答：1 epoch 时行为指标只改善约一半；3 epoch 时 val loss 在第二个 epoch 后段开始回升，学生复述训练轨迹中具体文件名的情况增多。选点看 val loss 与行为指标两项，取 val loss 低点附近、盲改次数与工具报错率没有反弹的 checkpoint。

**问题：项目做了多久？一共训练了几次？**

回答：项目历时约 4 个月。单次蒸馏训练为 16×H100、2 epoch 约 12 小时；配比扫描四档加最终训练共 5 次训练，约 60 小时；注入标注另用 8×H100，约 5 小时/千条轨迹。

**问题：增强样本占比为什么取 25%？各档有什么区别？**

回答：成功轨迹 1,730 条固定，增强样本按注入版与压缩段约 3:1 增减，扫描 15%、25%、35%、45% 四档，每档在 96 个 held-out 任务上评测 3 次取均值。15% 档每条轨迹盲改次数为 3.6，改善有限；25% 档为 3.1；35% 档为 2.9，但约 11% 的评测轨迹在相邻两轮之间交替出现注入风格的回顾与无回顾的直接调用；45% 档交替比例升至约 24%，接口签名错位率反而回升。取 25%，入训样本中增强样本 580 条，占 25.1%。

**问题（追问）：45% 档接口签名错位率反而回升，原因是什么？怎么验证的？**

回答：45% 档的接口签名错位率反而回升，同时注入风格与直接调用的交替比例约 24%。假设是增强样本占比过高后，学生把注意力分给了回顾文本的写法，实现阶段对规格中接口签名的核对减少。验证方法是抽取 45% 档签名错位的评测轨迹，统计错位发生前的轮次：大部分错位发生在一段回顾之后的首次编辑，回顾中列出了待实现模块，没有引用规格中的签名。另做一组对照：保持 45% 占比，但注入版只保留完成宣告点的回顾，签名错位率回落到接近 25% 档的水平，说明回升与中间位置的回顾密度有关。

**问题：怎么确认行为指标的改善来自注入和压缩样本，不是数据量增加带来的？**

回答：结果表按逐项累加组织，同一超参、同一评测集：初版数据（成功轨迹原样打包）每条轨迹盲改次数 5.0，加导出校验与归因筛选后 4.4，加过程监督注入后 3.9，加压缩恢复样本后 3.1，合计下降 38%。另做数据量对照：把增强样本换成同等数量的成功轨迹重复采样，盲改次数只到 4.3，说明下降主要来自增强样本的内容。压缩样本的作用还单独看了触发压缩的任务，压缩后第一个动作是重读或执行测试的比例由约 41% 升至约 78%。

**问题：总分没有提升，怎么说明增强有效？**

回答：96 个 held-out 任务的均分差异在 3 次评测的波动范围内，行为指标单独报告：盲改次数下降 38%，接口签名错位率下降 62%，工具报错率减半，最长盲改由约 8 轮降至约 4 轮，宣告完成前未执行任何测试的轨迹占比由 23% 降至 9%。得分变化按训练前是否依赖答案获取分组拆分，一轮表观增益中约六成来自残留的答案获取样本，此后答案获取扫描从离线检查前移到打包环节。仓库级任务的均分受任务难度与探索预算限制，行为改善先于得分改善出现。

**问题（追问）：如果训练后总分反而大幅下降，你会怎么排查？**

回答：先排除训练侧异常，看 train loss 与 val loss 是否与历史 run 同分布，checkpoint 是否选在 val loss 回升之后。再把评测任务按训练前是否依赖答案获取分组，分别看得分变化：如果下降集中在训练前靠下载目标包源码得分的任务，其余任务基本持平，说明训练消除了这类行为，分数回到真实水平。最后看行为指标剖面，盲改、签名错位与工具报错是否同时变差；三项同时变差才说明训练数据本身有问题，此时回查最近一版增强样本的质量门通过率与答案获取扫描结果。实际遇到过方向相反的情况：一轮出现表观增益，按同样的分组拆分后约六成来自残留的答案获取样本，此后答案获取扫描从离线检查前移到打包环节。

**问题：如果学生换成更大的 MoE 模型，或者轨迹数量翻倍，这套方案要怎么调整？**

回答：换成更大的学生（例如 MoE 模型）时，配比结论需要重新扫描，大模型对增强样本风格的敏感度不同；teacher 要比学生高一个规模档，注入模型也可能需要换成更强的旗舰；训练侧要冻结 router 或加负载均衡项，长序列下的专家负载不均会放大。轨迹数量翻倍时，导出、归因与注入都是逐条处理，线性扩展即可；注入标注是瓶颈，8×H100 约 5 小时/千条，需要增加推理卡或只对完成宣告点与测试执行点注入；压缩样本数量随长轨迹数增加，可以把切分阈值保持 5 万 token 不变。

### 3.3 通用概念的本人配置

**问题：SFT 中只对 assistant 计 loss，在你的项目里具体怎么掩码？**

回答：项目二的样本按 chat template 展开后，system、user 与 tool 消息的 token 标签设为 -100，只有 assistant 消息（含 tool_calls 的 JSON 与注入文本）计 loss。工具返回由环境产生，计 loss 会让模型学习预测工具结果，推理时表现为不调用工具就臆造执行结果。压缩恢复样本中摘要以 user 消息形式出现，同样不计 loss。

**问题：你用 YaRN 扩展上下文时，配置是什么？**

回答：Qwen3-32B 原生 32,768 位置，YaRN 因子 4，扩到 131,072，即 128K。训练与推理都开启同一 rope scaling 配置；YaRN 是静态缩放，对短文本有轻微影响，项目中通用代码评测的变化在 0.5pp 以内。

## 4. 跨项目与全局理解

**问题：两个项目放在一起，你对代码 Agent 后训练数据最核心的认识是什么？**

回答：判分可信是数据可用的前提。项目一把期望值从模型预测改为参考实现对照，抽检缺陷率由 28% 降至 1.9%；项目二发现低分的首要原因是自测与判分验证方式不一致，判分用的是上游测试，模型自写的测试全绿并不代表通过。两个项目都在判分前删除模型自写的测试与配置，在新容器中执行隐藏测试，训练集与评测集按仓库切分。数据质量的第二个层面是过程质量：结果正确的轨迹里仍有未验证就宣告完成的行为，需要在数据中补上状态核对的示范。

**问题：项目一造出的 1.4 万条函数级任务，直接用来做项目二的仓库级轨迹蒸馏，可以提升长程能力，对吗？**

回答：这个前提不成立。函数级任务的输入是单个函数的签名与规格，几轮交互即可完成，产生的轨迹不包含包结构规划、跨模块一致性与长程验证这些仓库级任务的核心行为，不能替代仓库级轨迹。项目二的轨迹来自独立的仓库级任务库。两类数据可以混合训练：函数级任务提供短程、高密度的可验证样本，训练接口规格理解与签名对齐，这与仓库级任务中最常见的接口签名错位直接相关；混合时需要控制配比，避免短轨迹样本拉低学生在长任务上的交互轮数。

**问题：如果要在这两个项目基础上加 RL，你会怎么设计？**

回答：函数级任务适合先做 RL：reward 取隐藏测试通过率，以 GRPO 为例每题采样一组回答，组内 advantage 为 $A_i=(r_i-\bar r)/(\sigma_r+\epsilon)$，组内全对或全错的题没有梯度，因此用 SFT 后模型对每题多次采样的通过率分档，剔除全对与全错的题。判分在新容器中执行，候选对测试文件与配置的修改在判分前丢弃，读取隐藏测试路径的行为把 reward 置零。仓库级任务做 RL 成本高：单条 rollout 百轮、数万 token，每组采样 8 条即数十万 token，再加容器构建与整库测试；reward 在 collection 报错时直接为 0，十分稀疏。更稳妥的顺序是先用项目二的 SFT 数据打好行为基础，再在函数级与中等规模的仓库级任务上做 RL。

**问题：两个项目里，哪些环节最容易让数据看起来很好、实际上有问题？**

回答：项目一是判分测试过浅：只断言能导入、有某属性的测试，空实现也能通过，一次执行通过率很高但没有区分度，排查方法是看断言类型分布并要求测试在空实现上失败。项目二有两处：一是答案获取，轨迹下载目标包源码后得分很高，按总分筛选会把这类轨迹当成最好的数据，必须按实际执行的工具调用字段扫描并整条剔除；二是统计口径，在按低分筛出的子集上统计会得出与全量相反的结论。

**问题：如果只能保留一个模块，你会保留哪个？为什么？**

回答：项目一保留等价性判分，它决定任务能否被信任，切片与插桩影响的是成本与覆盖深度，没有可信判分，后续模块的产出都不可用。项目二保留过程监督注入，归因显示低分的首要原因是验证方式不一致，注入直接针对完成宣告前的核对，宣告完成前未执行任何测试的轨迹占比由 23% 降至 9%；压缩恢复样本只影响触发压缩的长任务，覆盖面更窄。

### 5.2 模型与算法手撕

#### 1. Multi-Head Attention

出处：[Attention Is All You Need](https://arxiv.org/abs/1706.03762)；GQA 变体 [GQA: Training Generalized Multi-Query Transformer](https://arxiv.org/abs/2305.13245)。

核心思想：把 d_model 拆成 h 个头，每个头在自己的子空间做 scaled dot-product attention，不同头学不同的模式，最后拼回投影。

实现代码：

```python
import torch, torch.nn as nn, torch.nn.functional as F, math

class MultiHeadAttention(nn.Module):
    def __init__(self, d_model=512, num_heads=8, dropout=0.1):
        super().__init__()
        assert d_model % num_heads == 0
        self.d_model, self.num_heads = d_model, num_heads
        self.head_dim = d_model // num_heads
        self.Wq = nn.Linear(d_model, d_model)
        self.Wk = nn.Linear(d_model, d_model)
        self.Wv = nn.Linear(d_model, d_model)
        self.Wo = nn.Linear(d_model, d_model)
        self.dropout = nn.Dropout(dropout)

    def forward(self, x, mask=None):
        B, T, _ = x.shape
        q = self.Wq(x).view(B, T, self.num_heads, self.head_dim).transpose(1, 2)
        k = self.Wk(x).view(B, T, self.num_heads, self.head_dim).transpose(1, 2)
        v = self.Wv(x).view(B, T, self.num_heads, self.head_dim).transpose(1, 2)
        att = (q @ k.transpose(-2, -1)) / math.sqrt(self.head_dim)
        if mask is not None:
            if not mask.bool().any(dim=-1).all():
                raise ValueError("Each query row needs at least one visible key")
            att = att.masked_fill(mask == 0, float('-inf'))
        att = self.dropout(F.softmax(att, dim=-1))
        out = (att @ v).transpose(1, 2).reshape(B, T, self.d_model)
        return self.Wo(out)

# causal mask: torch.tril(torch.ones(T, T, dtype=torch.bool)).view(1,1,T,T)
```

复杂度：时间 O(T²·d)（注意力的 T² 主导），显存 O(T²)（att 矩阵）。[FlashAttention](https://arxiv.org/abs/2205.14135) 不落 T² 矩阵，tiling 在 SRAM 内完成 softmax，显存降到 O(T)。

**问题（追问）：张量维度怎么变的？**

回答：投影后是 (B,T,d)，view 成 (B,T,h,d_k) 把头维拆出来，transpose(1,2) 得 (B,h,T,d_k) 让头维进 batch 旁边、注意力在 (T,T) 上算；并头是逆操作 transpose(1,2) 后 reshape 回 (B,T,d)。维度变换链为 (B,T,d) → (B,h,T,d_k) → 注意力计算 → (B,h,T,d_k) → 并头回 (B,T,d)；投影矩阵形状不变（d×d），仅逻辑重排。

**问题（追问）：为什么除 √d_k？**

回答：在 q、k 各维相互独立、均值 0、方差均为 1 的近似假设下，点积方差为 d_k，除以 √d_k 后为 1。一般情形下单项 q_i k_i 的方差是两者方差的乘积，不能仅由零均值推得归一后方差为 1。缩放用于避免 softmax 过于尖锐；稳定 softmax 的减 max 主要解决指数上溢，不能替代温度/尺度控制。

**问题（追问）：改成 GQA 怎么改？**

回答：Wk/Wv 的输出维度从 d_model 改为 num_kv_groups·d_k，拆组后用 repeat_interleave(h // num_kv_groups, dim=1) 扩到 h 组参与计算；Wq 与 Wo 不变。MQA 是 num_kv_groups=1 的特例。改动的实质是 K/V 的头数减少、计算时广播回 h 组；推理时 KV cache 只按 num_kv_groups 存储，缓存量为 MHA 的 num_kv_groups/h。

**问题（追问）：不用 nn.Linear 手写？**

回答：q = x @ Wq + bq，Wq 是 (d,d) 参数、bq 是 (d,) 参数；初始化用 xavier_uniform 或 kaiming，偏置置零。nn.Linear 的本质是矩阵乘加偏置，手写时直接展开即可。

#### 2. GRPO Loss

出处：[DeepSeekMath](https://arxiv.org/abs/2402.03300) §4.1.1–4.1.2；改进对照 [DAPO](https://arxiv.org/abs/2503.14476)、[GSPO](https://arxiv.org/abs/2507.18071)。下例保留组内 std，采用 token mean，是 GRPO 风格的归一化变体，不是原文的逐回答 mean，也不是去掉 std 的 Dr. GRPO。

核心思想：同一 prompt 采样 G 条回答，组内 reward 标准化作优势（替代 critic），token 级重要性比率加 clip 与 KL 惩罚。

实现代码：

```python
import torch

def grpo_loss(old_logps, new_logps, rewards, ref_logps, completion_mask,
              beta=0.04, clip=0.2):
    # old_logps/new_logps/ref_logps: (G, L)；rewards: (G,)；completion_mask: (G, L)
    old_logps = old_logps.detach().float()
    ref_logps = ref_logps.detach().float()
    new_logps = new_logps.float()
    rewards = rewards.detach().float()
    # 掩码位置先置零，避免 exp 溢出后 inf * 0 产生 NaN
    active = completion_mask.bool()
    old_logps = old_logps.masked_fill(~active, 0)
    ref_logps = ref_logps.masked_fill(~active, 0)
    new_logps = new_logps.masked_fill(~active, 0)
    adv = (rewards - rewards.mean()) / (rewards.std(unbiased=False) + 1e-4)  # 单个 prompt 内总体 std
    adv = adv.unsqueeze(1)
    ratio = torch.exp(new_logps - old_logps)
    pg1 = ratio * adv
    pg2 = torch.clamp(ratio, 1 - clip, 1 + clip) * adv
    pg_loss = -torch.min(pg1, pg2)
    kl = torch.exp(ref_logps - new_logps) - (ref_logps - new_logps) - 1
    count = completion_mask.sum()
    if count.item() <= 0:
        raise ValueError("No policy-generated target tokens")
    return ((pg_loss + beta * kl) * completion_mask).sum() / count  # token mean；原始 response mean 为另一种归一
```

复杂度：这里只计算 loss 张量，时间与额外空间为 O(G·L)，不包含模型前反向、词表 logits 与 KV cache。G 是单组回答数，不是 prompt 组数；同长度下 G 翻倍约使生成 token 量翻倍，墙钟仍取决于 batching、前缀共享与环境等待。使用真实训练时还需保证 behavior logprob 与温度、截断采样协议一致，并在非掩码位置监测极端 ratio 与非有限值。

**问题（追问）：全对/全错的组怎么办？**

回答：组内完整 reward 相同时 task advantage 为零，task PG 项没有信号；启用的 KL 项仍可能产生梯度。+1e-4 只避免除零，不能创造优势。可按算法协议补采有效组，或使用经过验证的稠密信号，但要监测补采引入的任务选择偏差。稠密配方不能只按终局全对或全错判断整组是否退化。代码仅处理单个 prompt 的 G 条序列，多 prompt 时需按 group 维分别计算统计量。

**问题（追问）：KL 为什么不放进 reward？**

回答：放进 reward 后会被组内 mean/std 标准化改变——KL 的绝对大小信息被抹掉，组内排序也可能改变（一条任务得分更高的轨迹可能因 KL 项被反超）。所以 DeepSeekMath 把 KL 用 Schulman 的 k3 估计逐 token 直接加进 loss，与 advantage 解耦。k3 无偏的条件与原因：token 采样自当前策略 π_θ 时，指数项 π_ref/π_θ 的期望为 1，对数项的期望为 −KL(π_θ‖π_ref)，减 1 后期望恰为 KL；在同一批 rollout 上做多步更新后样本来自旧策略，该估计不再严格无偏。

**问题（追问）：和 PPO 的 loss 差在哪？**

回答：PPO 与 GRPO 的 clipped surrogate 同构，主要差别在 advantage 来源及是否训练 critic。[GSPO](https://arxiv.org/abs/2507.18071) §4 用 s_i=exp(mean_t(new_logp−old_logp)) 构造序列目标，逐回答取 mean(min(s_i A_i,clip(s_i)A_i))。直接对 s_i 求导自然包含 1/L_i，不能随意广播后改用 batch token mean，否则长短回答权重发生变化；逐 token 实现还需正确的 stop-gradient 构造。论文在其 MoE 配方上报告更稳定，不保证所有任务优于 GRPO，clip 超参也不能原样搬用。

#### 3. SFT Loss（含 mask 与 shift）

核心思想：交叉熵只在 completion token 上计算——位置 t 的 logits 预测位置 t+1 的 token，因此 logits 取前 T−1 位、labels 取后 T−1 位对齐；prompt 与 padding 位置的标签置 -100，由 ignore_index 跳过。

实现代码：

```python
import torch
import torch.nn.functional as F

def sft_loss(logits, input_ids, prompt_mask, attention_mask, segment_ids=None):
    # logits: (B, T, V)；input_ids / prompt_mask / attention_mask: (B, T)
    # prompt_mask=1 表示 prompt 位置；attention_mask=0 表示 padding 位置
    labels = input_ids.clone()
    labels[prompt_mask.bool()] = -100            # 先在原始坐标系屏蔽 prompt
    labels[attention_mask == 0] = -100           # 再屏蔽 padding
    shift_logits = logits[:, :-1]                # 位置 t 的 logits 预测位置 t+1 的 token
    shift_labels = labels[:, 1:]
    shift_labels = shift_labels.clone()
    # 左 padding 的前一个位置不能作为有效预测位置
    shift_labels[attention_mask[:, :-1] == 0] = -100
    if segment_ids is not None:
        shift_labels = shift_labels.clone()
        shift_labels[segment_ids[:, 1:] != segment_ids[:, :-1]] = -100
    count = (shift_labels != -100).sum()
    if count.item() == 0:
        raise ValueError("No supervised target tokens")
    return F.cross_entropy(
        shift_logits.float().reshape(-1, shift_logits.size(-1)),
        shift_labels.reshape(-1), ignore_index=-100, reduction="sum") / count
```

**问题（追问）：shift 是先做还是后做？**

回答：先 mask 再 shift。mask 在原始坐标系下完成：prompt 末位对应的预测目标是第一个 completion token，若先 shift 再用未同步 shift 的 prompt_mask 去屏蔽，这个位置会被误置为 -100，模型得不到“从 prompt 末尾生成回答第一个 token”的监督。这类错误不会让 loss 曲线出现异常，只表现为首 token 分布失真，需要用构造样例逐 token 断言来发现。

**问题（追问）：多轮对话/工具调用场景 mask 怎么改？**

回答：工具返回、用户和 system token 排除出目标，assistant 的思考、调用与答复按训练协议监督。整条轨迹只出现一次时可监督所有正确 assistant 轮；按轮拆成多条样本时，历史轮作为条件、只监督当前目标段，避免重复加权。teacher forcing 始终读取数据中的真实前缀，mask 不会令前缀变成模型在线生成。segment_ids 的跨界标签屏蔽还不足以隔离 packing 样本，模型前向需同时使用相应 attention 边界。常见 HF causal LM 已内部 shift，传 labels 时不能再手工 shift 一次。对全部目标被掩码的 batch 显式报错，避免 NaN 或无声丢失监督。

**问题（追问）：loss 分母是 token 数还是样本数？**

回答：SFT 常用 token mean：全批有效目标 token 的 CE 之和除以目标 token 数。样本 mean 是每条先平均、再对样本平均，令每条样本总权重相等、长样本单 token 权重较小；不能据此断言短样本实际梯度必然主导。RL 需要另讲：原始 GRPO 按各回答长度归一，[Dr. GRPO](https://arxiv.org/abs/2503.20783) §3.1–3.2 改为固定长度分母并去掉组内 std；DAPO 改为 batch 有效 token 分母，但该分母仍随采样长度变化，不能称为完全无偏。梯度累积与多卡训练还必须按整个有效 batch 的目标 token 数归一，不能把各 microbatch 均值无权相加。

#### 4. RoPE 旋转位置编码

出处：[RoFormer](https://arxiv.org/abs/2104.09864)；外推 [YaRN](https://arxiv.org/abs/2309.00071)。

核心思想：q、k 按维度两两配对做二维旋转，内积只依赖相对位置差；高频对管局部、低频对管长程。

实现代码：

```python
import torch

def rope_cache(T, head_dim, base=10000.0, device='cpu'):
    if T <= 0 or head_dim <= 0 or head_dim % 2 or base <= 0:
        raise ValueError("Require positive T/base and even positive head_dim")
    inv_freq = 1.0 / (base ** (torch.arange(0, head_dim, 2, device=device).float() / head_dim))
    t = torch.arange(T, device=device).float()
    freqs = torch.outer(t, inv_freq)
    return torch.cos(freqs), torch.sin(freqs)

def apply_rope(x, cos, sin, position_ids=None):
    # x: (B, h, T, d_h)，采用相邻偶奇配对，须与 checkpoint 的配对约定一致
    T = x.size(-2)
    if x.size(-1) % 2:
        raise ValueError("RoPE head dimension must be even")
    if position_ids is None:
        position_ids = torch.arange(T, device=x.device)
    ids = torch.as_tensor(position_ids, device=cos.device, dtype=torch.long)
    if ids.shape[-1] != T or (ids < 0).any() or (ids >= cos.size(0)).any():
        raise ValueError("position_ids must fit the cache and sequence length")
    cos, sin = cos[ids].to(x.device, x.dtype), sin[ids].to(x.device, x.dtype)
    if ids.ndim == 2:                            # (B, T) -> (B, 1, T, d_h/2)
        cos, sin = cos.unsqueeze(1), sin.unsqueeze(1)
    x1, x2 = x[..., 0::2], x[..., 1::2]
    out = torch.empty_like(x)
    out[..., 0::2] = x1 * cos - x2 * sin
    out[..., 1::2] = x1 * sin + x2 * cos
    return out
```

**问题（追问）：为什么是相对位置？**

回答：旋转矩阵正交，$R_m^T R_n=R_{n-m}$，所以位置旋转引入的因子只依赖位置差。q、k 的内容表示仍受上下文影响，不能说整个注意力分数与内容或绝对上下文无关。相对距离在训练窗口之外仍有定义，但不保证模型能泛化到未训练长度。decode 时必须使用新 token 的真实 position_ids，不能每次从位置 0 重算；相邻配对与半维配对两种实现都可成立，不能与 checkpoint 混用。

**问题（追问）：训练 8K 推 128K 怎么办？**

回答：NTK-aware 插值通过放大 base 改变各维频率：高频维（波长远小于训练长度）几乎不变，保住局部分辨率；低频维（波长超过训练长度，训练中未转满一周）被拉伸，使更远的位置落回训练时见过的相位范围，免训练即可获得一定倍数的外推，倍数增大后困惑度上升。YaRN 在按波长分段插值之上加注意力温度项：长上下文下参与 softmax 的 key 变多、注意力分布变平，注意力 logits 乘以 1/t，推荐取 √(1/t)=0.1·ln(s)+1（s 为扩展倍数，s=8 时约 1.21，实现上等价于 q、k 各乘该系数），该式是在 LLaMA 上拟合得到的经验式；再配少量长文微调可扩到 128K。工业上扩窗通常配合长文数据继续训练，免训练外推用于过渡。

**问题（追问）：RoPE 与 KV cache / MLA 的关系？**

回答：MLA 缓存低秩潜向量 c_KV 与一路解耦的位置 key。内容 key 的上投影矩阵 W_UK 可吸收到 Q 侧；若对完整 key 直接施加随位置变化的 RoPE，旋转矩阵与上投影一般不对易，无法统一吸收。此时需要在计算时恢复 key，或者存储恢复并旋转后的完整 key，后者失去原有 cache 压缩收益；并非使用 RoPE 就必须每步重算所有历史 key。DeepSeek-V2 将小维度 RoPE 分量单独缓存，使内容分量仍可吸收。

#### 5. 带 KV Cache 与 causal mask 的自回归 Attention

出处：[Efficient Memory Management for LLM Serving with PagedAttention](https://arxiv.org/abs/2309.06180)。

核心思想：decode 阶段每步只有 1 个新 q，K/V 从缓存读，注意力只在 (1, T_total) 上算，把每步 O(T²) 降为 O(T)。

实现代码：

```python
import torch, math

def decode_step(x_new, Wq, Wk, Wv, Wo, cache_k, cache_v, num_heads=8):
    # 教学版不含 RoPE、padding、GQA；连续多 token 输入用下右对齐的因果 mask
    old_len = cache_k.size(2)
    q = Wq(x_new).unflatten(-1, (num_heads, -1)).transpose(1, 2)
    k = Wk(x_new).unflatten(-1, (num_heads, -1)).transpose(1, 2)
    v = Wv(x_new).unflatten(-1, (num_heads, -1)).transpose(1, 2)
    cache_k = torch.cat([cache_k, k], dim=2)
    cache_v = torch.cat([cache_v, v], dim=2)
    att = (q @ cache_k.transpose(-2, -1)) / math.sqrt(q.size(-1))
    q_pos = old_len + torch.arange(q.size(2), device=q.device)
    k_pos = torch.arange(cache_k.size(2), device=q.device)
    att = att.masked_fill(k_pos[None, :] > q_pos[:, None], float('-inf'))
    out = (att.softmax(-1) @ cache_v).transpose(1, 2).flatten(-2)
    return Wo(out), cache_k, cache_v
```

**问题（追问）：KV cache 显存多大？**

回答：缓存量等于 2（K 与 V）× 层数 × batch × 序列长 × KV 头数 × d_k × 每元素字节数（bf16 为 2 字节）。算例：每 token 每层为 2 × 32 头 × 128 维 × 2 字节 = 16 KiB，乘 32 层得每 token 512 KiB，32K 序列约 16 GiB（MHA）。GQA 按 KV 头数与 Q 头数之比缩小（32 个 Q 头配 8 个 KV 头时为 1/4，约 4 GiB）；MLA 只缓存低秩 c_KV 与解耦的 RoPE 分量。

**问题（追问）：decode 步为什么不用显式 causal mask？**

回答：每个请求一次仅追加一个 token、cache 不含未来位置且没有 padding 时，历史与当前 key 都合法，无需显式因果 mask。一次追加多个 token（chunked prefill、推测解码验证）时，新块内部仍要因果屏蔽；变长 batch 还需 padding/长度 mask。上例按历史长度构造下右对齐 mask，避免非方形 attention 中把第一个新 query 错对齐到 cache 的位置 0。生产实现用预分配或分页 cache，不反复 torch.cat 复制全部历史。

**问题（追问）：PagedAttention 解决什么？**

回答：静态连续 cache 的两个问题——按最大长度预留导致的内部碎片（预留 32K 实际用 8K），以及多请求间的外部碎片；vLLM 把 cache 切成固定大小的页、按需分配、逻辑连续物理离散，显存利用率大幅提升，还支持 prefix 共享（系统提示词复用）。

#### 6. RMSNorm 与 LayerNorm

出处：[Root Mean Square Layer Normalization](https://arxiv.org/abs/1910.07467)。

核心思想：LayerNorm 是去均值加方差归一加仿射；RMSNorm 去掉均值中心化，只用均方根缩放。

实现代码：

```python
import torch, torch.nn as nn

class RMSNorm(nn.Module):
    def __init__(self, d, eps=1e-6):
        super().__init__()
        self.weight = nn.Parameter(torch.ones(d))
        self.eps = eps
    def forward(self, x):
        z = x.float() if x.dtype in (torch.float16, torch.bfloat16) else x
        rms = z.pow(2).mean(-1, keepdim=True).add(self.eps).rsqrt()
        return (z * rms * self.weight).to(x.dtype)

class LayerNorm(nn.Module):
    def __init__(self, d, eps=1e-5):
        super().__init__()
        self.weight = nn.Parameter(torch.ones(d))
        self.bias = nn.Parameter(torch.zeros(d))
        self.eps = eps
    def forward(self, x):
        z = x.float() if x.dtype in (torch.float16, torch.bfloat16) else x
        mu = z.mean(-1, keepdim=True)
        var = z.var(-1, keepdim=True, unbiased=False)
        return ((z - mu) / torch.sqrt(var + self.eps) * self.weight + self.bias).to(x.dtype)
```

**问题（追问）：RMSNorm 为什么敢去掉均值中心化？**

回答：RMSNorm 原文的消融显示去掉中心化后效果基本不变——归一化的主要作用是控制激活尺度，去掉均值归约省一次计算与访存。eps 的作用是防止除零并保持数值稳定，常见取值为 1e-6 或 1e-5，随实现而定；LayerNorm 的 1e-5 是 PyTorch 默认值。实现上用 rsqrt 一次完成倒数开方。

**问题（追问）：Pre-norm vs Post-norm？**

回答：现代 LLM 普遍采用 Pre-norm——归一化放在残差分支内部，主干是恒等通路，深层梯度不衰减，对 warmup 的依赖较低；Post-norm 的归一化在残差相加之后，主路径每层都被重新缩放，深层训练稳定性差，依赖 warmup 与初始化。这是现代模型可以稳定堆叠到上百层的结构原因。

#### 7. PPO Advantage + Clip Loss

出处：[Proximal Policy Optimization](https://arxiv.org/abs/1707.06347)。

核心思想：GAE 用 value 网络与 TD 残差指数加权折衷偏差与方差；ratio clip 限制单步更新幅度。

实现代码：

```python
import torch

@torch.no_grad()
def compute_gae(rewards, old_values, dones, last_value=0.0, gamma=0.99, lam=0.95):
    # rollout 结束后计算一次并固定；old_values 为采样时 critic 的输出
    # dones[t]=1 表示第 t 步后真终止；因步数上限被截断时 last_value 传入 V(s_T) 自举
    T = rewards.shape[0]
    adv = torch.zeros_like(rewards)
    lastgae = 0.
    for t in reversed(range(T)):
        next_v = old_values[t + 1] if t + 1 < T else last_value
        nonterminal = 1 - dones[t]
        delta = rewards[t] + gamma * next_v * nonterminal - old_values[t]
        lastgae = delta + gamma * lam * nonterminal * lastgae
        adv[t] = lastgae
    returns = adv + old_values                   # value 的回归目标，同样固定
    return adv, returns

def ppo_loss(values, old_values, old_logps, new_logps, adv, returns,
             clip=0.2, eps_v=0.1, vf_coef=0.5):
    # adv / returns / old_values / old_logps 来自 rollout，不带梯度；values / new_logps 由当前网络给出
    ratio = torch.exp(new_logps - old_logps)
    pg = -torch.min(ratio * adv,
                    torch.clamp(ratio, 1 - clip, 1 + clip) * adv).mean()
    v_clip = old_values + torch.clamp(values - old_values, -eps_v, eps_v)
    vf = torch.max((values - returns) ** 2, (v_clip - returns) ** 2).mean()
    return pg + vf_coef * vf
```

**问题（追问）：GAE 的 λ 调大调小意味着什么？**

回答：λ=0 使用单步 TD，对 critic 误差较敏感，通常方差较低；λ=1 在完整终止轨迹上得到折扣蒙特卡洛回报减 V(s)，在 on-policy 与合法 baseline 等条件下可用于无偏的相应策略梯度估计。有限 rollout 末端仍自举时，λ=1 也保留末端 critic 的偏差。标准 PPO 更新中 advantage、returns、old_values 与 old_logps 固定且 detach，避免回归目标随当前预测一起移动；不能说任何形式的重算都完全没有梯度。上例只处理一段连续 rollout，截断在段末；拼接多段环境时需分别记录 bootstrap mask 与 GAE 递推边界，不能把 reset 后的新状态当成截断的后继状态。

**问题（追问）：轨迹因步数上限被截断与真正终止，自举有什么区别？**

回答：真终止时后继状态的价值为 0，dones 置 1 切断自举；因步数上限被截断时环境并未终止，需要用 V(s_T) 作为 last_value 自举，否则回报被系统性低估。实现上分别记录 terminated 与 truncated 两个标志，只有 terminated 才把后继价值置零；二者混用同一个 done 标志是常见的实现错误。

#### 8. Forward KL 与 Reverse KL（梯度推导）

出处：[MiniLLM](https://arxiv.org/abs/2306.08543)。

核心思想：forward KL 在 teacher 样本上取期望，mean-seeking，学生被要求覆盖 teacher 的全部模式；reverse KL 在学生样本上取期望，mode-seeking，适合容量较小的学生，但梯度估计方差大。

推导要点：

```
forward:  ∇θ KL(p‖qθ) = − Σ p·∇θ log qθ ≈ − E_{y~p}[∇θ log qθ(y)]
          → 直接用 teacher 样本加权学生的 logprob 梯度（SFT 即其特例）

reverse:  ∇θ KL(qθ‖p) = ∇θ Σ qθ·(log qθ − log p)
          = E_{y~qθ}[(log qθ(y) − log p(y))·∇θ log qθ(y)]  （求导多出的常数项因 E[∇θ log qθ]=0 而消失）
          → 可用学生采样的 score-function 估计；也可精确求和或在支撑覆盖的 proposal 上重加权
          → 学生采样时等价于以 detach(log p(y) − log qθ(y)) 为回报的 REINFORCE
```

**问题（追问）：蒸馏选哪个？为什么？**

回答：forward KL 倾向覆盖教师模式，reverse KL 倾向集中于教师高概率模式，都是受模型族与优化条件影响的倾向，不是“小学生必须 reverse KL”的定律。序列采样式 reverse KL 需处理 score-function 梯度与方差；固定前缀下可直接对词表分布求和，也能在具有支撑覆盖的其他 proposal 上用重要性采样，并非只能用学生样本。OPD 的核心是学生访问状态、教师在这些状态上监督，不限定只能用 reverse KL；Thinking Machines 的配方使用采样 token 的教师 logprob 及即时负 log-ratio advantage，不要求取得完整词表 logits。它缓解 exposure bias，不保证完全消除。

#### 9. 梯度下降求算术平方根

核心思想：求 √a 等价最小化 L(w) = (w² − a)²，用解析梯度 4w(w²−a) 迭代。

实现代码：

```python
def sqrt_by_gd(a, tol=1e-9, max_iter=10000):
    import math
    a = float(a)
    if not math.isfinite(a) or a < 0 or tol <= 0 or max_iter <= 0:
        raise ValueError("Require finite non-negative a and positive tolerance/iterations")
    if a == 0:
        return 0.0
    w = max(float(a), 1.0)                       # 初值取在 √a 右侧，迭代全程保持 w ≥ √a > 0
    for _ in range(max_iter):
        if abs(w - a / w) <= tol * w:           # 避免 w² 在极大输入下上溢
            return w
        # 与 lr=1/(12w²)、grad=4w(w²-a) 的梯度步代数等价，但不显式算 w³
        w = (2.0 / 3.0) * w + (a / w) / 3.0
    raise RuntimeError("not converged")
# sqrt_by_gd(8.) ≈ 2.8284
```

**问题（追问）：步长怎么取才能保证收敛？和牛顿法相比如何？**

回答：损失是四次多项式，二阶导 L''(w)=12w²−4a 随 w 增大，固定步长无法同时适配远离根与接近根两个阶段：根附近 L''(√a)=8a，稳定条件是 lr<1/(4a)；初值取 a 时首步梯度约为 4a³，同一步长会直接越过零点，收敛到负根或发散。实现中把初值取在 √a 右侧（max(a,1)），每步按局部平滑常数的上界取步长 lr=1/(12w²)，此时 w 单调下降且不会越过 √a，根附近每步误差收缩到约 1/3，为线性收敛。牛顿法 w ← (w + a/w)/2 对任意正初值收敛且为二阶收敛，迭代步数更少；梯度下降只使用一阶信息，收敛阶更低。

#### 10. 有效数字（状态机，LeetCode 65）

核心思想：把"数字/小数点/e/正负号"的合法转移显式建成状态机，每条转移可枚举、可逐一构造测试。

实现代码：

```python
def is_valid_number(s: str) -> bool:
    s = s.strip()
    states = [
        {'digit': 1, 'sign': 2, 'dot': 3},
        {'digit': 1, 'dot': 4, 'e': 5},
        {'digit': 1, 'dot': 3},
        {'digit': 4},
        {'digit': 4, 'e': 5},
        {'sign': 6, 'digit': 7},
        {'digit': 7},
        {'digit': 7},
    ]
    cur, has_digit = 0, False
    for ch in s:
        kind = ('digit' if '0' <= ch <= '9' else 'sign' if ch in '+-'
                else 'dot' if ch == '.' else 'e' if ch in 'eE' else None)
        if kind == 'digit': has_digit = True
        if kind is None or kind not in states[cur]:
            return False
        cur = states[cur][kind]
    return has_digit and cur in (1, 4, 7)
```

**问题（追问）：为什么状态机不用正则？**

回答：约束是结构化的——点号与 e 各只能出现一次、e 之后必须跟整数、符号只出现在特定位置。该语言是正则语言，正则同样可解；选状态机的原因是转移表可逐条核对，一条长正则可读性差、难以验证，".5"、"5."、"1e+5"、".e1" 等边界情况容易遗漏。验证方式是对每个边界样例走一遍转移，确认其所在状态与最终是否停在接受态。

#### 11. 快速排序 partition 与 quickselect（第 k 小）

核心思想：partition 把 pivot 归位、左侧全小右侧全大；quickselect 只递归含目标下标的一侧，期望 O(n)。

实现代码：

```python
import random

def partition(a, lo, hi):
    p = random.randint(lo, hi)
    a[p], a[hi] = a[hi], a[p]          # 随机 pivot 换到末尾，防有序输入退化
    pivot = a[hi]
    i = lo                             # 不变量：[lo, i) 均 < pivot
    for j in range(lo, hi):
        if a[j] < pivot:
            a[i], a[j] = a[j], a[i]
            i += 1
    a[i], a[hi] = a[hi], a[i]          # pivot 归位
    return i

def quickselect(a, k):                 # 第 k 小，k 从 1 计
    if not isinstance(k, int) or not 1 <= k <= len(a):
        raise IndexError("k out of range")
    lo, hi = 0, len(a) - 1
    while lo <= hi:
        p = partition(a, lo, hi)
        if p == k - 1:
            return a[p]
        if p > k - 1:
            hi = p - 1
        else:
            lo = p + 1
    raise IndexError("k out of range")
```

**问题（追问）：为什么要随机 pivot？**

回答：固定取首或尾元素时，接近有序的输入会让每次划分一侧为空，比较次数退化到 O(n²)；随机化后坏划分的概率与输入分布解耦。理想对半划分下 quickselect 的比较次数为 n + n/2 + n/4 + … ≈ 2n，随机 pivot 的期望为 O(n)（求中位数时约 3.4n），快排整体期望 O(n log n)。另一种常用做法是三数取中。

**问题（追问）：和堆解法怎么选？**

回答：quickselect 期望 O(n) 但原地改数组、最坏 O(n²)；大小为 k 的堆 O(n log k)，不改原数组且支持流式到达。一次性静态数组用 quickselect，k 远小于 n、数据流式或不允许改输入时用堆。注意 Python 的 heapq 是最小堆，求第 k 大时维护大小 k 的最小堆、堆顶即答案。

**问题（追问）：partition 实现的关键点有哪些？**

回答：三处。循环不变量：[lo, i) 存放小于 pivot 的元素，i 是下一个写入位。归位步骤：循环结束后把 pivot 与 a[i] 交换，遗漏该步时 pivot 停留在末尾、返回的下标无意义。循环条件：quickselect 的 while 需写成 lo <= hi，写成 lo < hi 时区间收缩到单元素会直接跳出而不返回该元素。全部元素相同时该 partition 每次划分一侧为空，退化为 O(n²)，重复元素多的输入改用三路划分。用 [3,1,2] 与 [2,2,2] 各走一遍可以覆盖上述情形。

#### 12. Top-k / Top-p 采样

核心思想：logits 先除以 temperature，再按固定个数（top-k）或累计概率阈值（top-p）截断候选集；两者同时使用时先做 top-k 并在保留集合上重新归一，再在该分布上做 top-p，最后归一化采样。

实现代码：

```python
import torch

def sample_topk_topp(logits, temperature=1.0, top_k=0, top_p=1.0):
    assert temperature > 0 and 0.0 < top_p <= 1.0
    logits = logits / temperature                # 温度作用在 softmax 之前
    if top_k > 0:
        k = min(top_k, logits.size(-1))
        kth = logits.topk(k).values[..., -1, None]
        logits = logits.masked_fill(logits < kth, float('-inf'))   # 与第 k 名并列的 token 一并保留
    probs = torch.softmax(logits, dim=-1)        # top-k 截断后在保留集合上归一
    if top_p < 1.0:
        sp, si = torch.sort(probs, descending=True, dim=-1)
        keep = sp.cumsum(-1) - sp < top_p        # 累计概率到达阈值之前的 token 保留，首个 token 恒保留
        probs = torch.zeros_like(probs).scatter(-1, si, sp * keep)
        probs = probs / probs.sum(-1, keepdim=True)
    return torch.multinomial(probs, 1).squeeze(-1)
```

**问题（追问）：top-k 与 top-p 的本质差别？**

回答：top-k 的候选数固定，与分布形状无关——分布尖锐时尾部小概率 token 仍被保留，分布平坦时又截去过多候选；top-p 按累计概率自适应候选数，尖锐分布只保留一两个，平坦分布保留几十个。两者常同时开启，顺序为先 k 后 p；开放生成常用 top_p 0.8–0.95、temperature 0.7–1.0。

**问题（追问）：temperature 为什么不能在采样后调？**

回答：temperature 除的是 logits、必须在 softmax 之前，它改变的是分布形状——T 大于 1 变平（熵升高）、小于 1 变尖、趋 0 等价 argmax。采样只是按既定分布抽样，事后无法改形状。所以"温度调高更随机"的准确说法是高温拉平了 token 间的概率差。

**问题（追问）：截断后为什么要重新归一化？**

回答：截断把部分概率置零，总和不再为 1。multinomial 按权重比例抽样，不归一也能得到同样的样本，但先 k 后 p 时必须在 top-k 的保留集合上归一后再计算累计概率，否则 top-p 的阈值作用在未归一的概率质量上，保留集合偏大。显式归一还让返回的 probs 可直接用于 logprob、熵等统计。HuggingFace 的实现是各处理器依次把被截断 token 的 logit 置为 −inf，最后统一 softmax，效果等价于逐步在保留集合上归一。

#### 13. DPO Loss（sigmoid 形式）

出处：[DPO](https://arxiv.org/abs/2305.18290)。

核心思想：把 RLHF 目标闭式改写成分类损失——隐式奖励取 β 乘策略与参考模型的 logprob 差，偏好对分差过 sigmoid 取负对数。

实现代码：

```python
import torch
import torch.nn.functional as F

def dpo_loss(pi_logp_w, pi_logp_l, ref_logp_w, ref_logp_l, beta=0.1):
    # 四个输入均为 (B,)：整条回答的 token logprob 之和
    ref_logp_w, ref_logp_l = ref_logp_w.detach(), ref_logp_l.detach()
    logit_w = beta * (pi_logp_w - ref_logp_w)
    logit_l = beta * (pi_logp_l - ref_logp_l)
    loss = -F.logsigmoid(logit_w - logit_l).mean()
    with torch.no_grad():
        acc = (logit_w > logit_l).float().mean()  # 偏好对排序准确率，监控用
    return loss, acc
```

**问题（追问）：β 的作用与量级？**

回答：β 在 DPO 推导的 KL 正则化 RL 目标中控制奖励与参考约束的相对尺度；实现中也缩放偏好 logit 与梯度。较大 β 对应更强的理论参考约束，但有限数据、有限步数下实际 KL 不保证对 β 单调，sigmoid 饱和也不保证策略始终接近参考。原文常用 β=0.1。两条回答 logprob 同时下降可能只反映 rejected 下降更快，不能直接推出全分布似然下降或唯一修复方式；应联合看独立偏好胜率、参考 KL、chosen 似然、长度和 LR 扫描。

**问题（追问）：为什么不需要显式奖励模型？**

回答：Bradley-Terry 偏好模型下 KL 约束的最优策略有闭式解 π*(y) ∝ π_ref(y)·exp(r(y)/β)，反解出 r(y) = β·log(π*/π_ref) 加配准常数；代回偏好概率 σ(r_w − r_l) 后常数抵消，损失里只剩策略与参考模型的 logprob 差——奖励模型被参数化消掉了，这就是"direct"的含义。

**问题（追问）：和 GRPO 的适用边界？**

回答：标准离线 DPO 使用固定偏好对；GRPO 通常在线采样并接入结果奖励。执行验证器也可构造 DPO 偏好对，judge 分数也可用于在线 RL，不能按反馈来源硬划分算法。取舍看是否需要探索当前策略的新行为、环境可交互性、数据覆盖与预算。IPO、KTO、SimPO 的目标和数据要求各有区别，KTO 不是必须使用成对偏好的 DPO 换名版。

#### 14. softmax 数值稳定版

核心思想：减行最大值再取指数，数学上与原版等价，消除大 logits 的 exp 上溢。

实现代码：

```python
import torch

def stable_softmax(x, dim=-1):
    z = x.float() if x.dtype in (torch.float16, torch.bfloat16) else x
    if torch.isnan(z).any() or torch.isposinf(z).any():
        raise ValueError("NaN/+inf logits are unsupported")
    if not torch.isfinite(z).any(dim=dim).all():
        raise ValueError("Each row needs at least one finite logit")
    m = z.max(dim=dim, keepdim=True).values
    e = torch.exp(z - m)                         # 最大指数项为 e^0 = 1
    return (e / e.sum(dim=dim, keepdim=True)).to(x.dtype)
```

**问题（追问）：减 max 为什么不改变结果？**

回答：分子分母同乘 e^{−m} 不改数学值，有限最大值下最大指数项为 1、其余不超过 1，可防 exp 上溢。小概率项下溢对常规归一化分布的影响可能很小，但在 logprob、KL、尾部采样与梯度中仍有影响，不能称为无害；全 −inf 行会出现 −inf−(−inf)=NaN，上例显式拒绝。

**问题（追问）：训练里为什么用 log_softmax 而不是先 softmax 再取 log？**

回答：分两步时小概率项 e^{x−m} 下溢成 0，再取 log 得到 −inf 丢精度；log_softmax 内部按 x_i − m − log(Σe^{x−m}) 一步算，log-sum-exp 同样走减 max 技巧。F.cross_entropy 就是 log_softmax 加 NLL 的融合实现，手写交叉熵时直接组合这两个原语即可。

**问题（追问）：和 FlashAttention 的在线 softmax 什么关系？**

回答：分块计算时看不到全局最大值，就维护运行最大值 m 与归一分母 l，每来一块用 e^{m_old−m_new} 给已累积的结果换底重缩放——本质是这套减 max 技巧的流式版本。

#### 15. Beam Search（含 length penalty）

核心思想：每步保留累计分数最高的 B 条前缀；logprob 加性累计天然偏好短序列，用长度惩罚调和。

实现代码：

```python
import torch

def beam_search(next_logit_fn, bos, eos, beam=4, max_len=20, alpha=0.6):
    # CPU 教学版；完整服务实现还需缓存重排、批处理与安全停止上界
    if beam <= 0 or max_len <= 0 or alpha < 0:
        raise ValueError("Require positive beam/max_len and non-negative alpha")
    def lp(n):                                   # GNMT 长度惩罚，n 为已生成 token 数（含 eos，不含 bos）
        return ((5.0 + n) / 6.0) ** alpha
    seqs = torch.tensor([[bos]])                 # 活跃前缀 (n_active, t)
    scores = torch.zeros(1)                      # 累计 logprob
    finished = []                                # (惩罚后分数, token 列表)
    for step in range(1, max_len + 1):
        logp = torch.log_softmax(next_logit_fn(seqs), dim=-1)    # (n_active, V)
        V = logp.size(-1)
        cand = (scores[:, None] + logp).flatten()
        top = cand.topk(min(2 * beam, cand.numel()))  # 留余量：EOS 不占用下一步活跃 beam
        beam_idx = torch.div(top.indices, V, rounding_mode='floor')
        tok = top.indices % V
        new_seqs = torch.cat([seqs[beam_idx], tok[:, None]], dim=1)
        ended = tok == eos
        for s, sc in zip(new_seqs[ended], top.values[ended]):
            finished.append((sc.item() / lp(step), s.tolist()))  # 结束序列移入完成池，不再扩展
        seqs, scores = new_seqs[~ended][:beam], top.values[~ended][:beam]
        if seqs.size(0) == 0:
            break
    for s, sc in zip(seqs, scores):              # 到达 max_len 仍未结束的前缀按当前长度计分
        finished.append((sc.item() / lp(s.size(0) - 1), s.tolist()))
    return max(finished, key=lambda x: x[0])[1]
```

**问题（追问）：为什么需要 length penalty？**

回答：logprob 为负且逐 token 累加，序列越长累计值越小，未归一的分数系统性偏向短序列。GNMT 的长度惩罚 lp(Y)=((5+|Y|)/6)^α 随长度单调增，分数除以它后长序列的排名被抬升（α 常取 0.6–1.0）。同一步的活跃前缀等长、惩罚相同，惩罚起作用的位置是不同长度的完成序列之间、以及完成序列与仍在扩展的前缀之间的比较。

**问题（追问）：beam 是不是越大越好？**

回答：beam 增大到一定程度后质量常出现下降：累计概率最高的序列倾向于短、通用、重复，搜索越充分越接近这类高概率低信息量的输出；显存与耗时随 beam 线性增长。开放式生成通常使用采样，受限生成（翻译、结构化输出、工具参数）使用较小的 beam（2–4）。

**问题（追问）：已结束的序列如何处理？停止条件怎么定？**

回答：生成 eos 的序列移入完成池，不再扩展；候选筛选保留额外名额以补足未结束的活跃 beam。上例不因完成池凑满 beam 就提前停，而是在活跃为空或达到 max_len 时结束；有限 beam 本身仍是近似搜索。更早停止需用活跃前缀的可达分数上界与完成池目标排名比较，考虑长度惩罚与剩余长度，不能只比较当前累计分数。min_length 未到时可屏蔽 eos。

#### 16. AdamW 单步更新

出处：[AdamW](https://arxiv.org/abs/1711.05101)（Decoupled Weight Decay Regularization）。

核心思想：一阶、二阶动量做偏差校正后按自适应步长更新；weight decay 与梯度解耦，直接乘在参数上、不进动量。

实现代码：

```python
import torch

@torch.no_grad()
def adamw_step(p, g, m, v, t, lr=1e-3, betas=(0.9, 0.999), eps=1e-8, wd=0.01):
    # m、v 初始为 zeros_like(p)，t 从 1 计
    b1, b2 = betas
    m.mul_(b1).add_(g, alpha=1 - b1)             # 一阶动量
    v.mul_(b2).addcmul_(g, g, value=1 - b2)      # 二阶动量
    m_hat = m / (1 - b1 ** t)                    # 偏差校正
    v_hat = v / (1 - b2 ** t)
    p.mul_(1 - lr * wd)                          # 解耦 decay：不进 m/v
    p.addcdiv_(m_hat, v_hat.sqrt().add_(eps), value=-lr)
```

**问题（追问）：AdamW 与 Adam 加 L2 的差在哪？**

回答：L2 把 wd·p 加进梯度，随后被二阶动量的平方根相除——梯度大的参数等效衰减被缩小，正则强度与损失曲面耦合；AdamW 把衰减直接施加在参数上，不经过动量。PyTorch 实现中每步衰减量为 lr·wd·p，LLM 训练 wd 常取 0.01–0.1。

**问题（追问）：偏差校正去掉会怎样？**

回答：m、v 从零初始化产生估计偏差，校正分别除以 $1-\beta_1^t$ 与 $1-\beta_2^t$。去掉校正时，忽略 epsilon 的首次更新幅度相对校正更新为 $(1-\beta_1)/\sqrt{1-\beta_2}$，可能放大也可能缩小；默认 0.9/0.999 时约为 3.16 倍，不能仅凭 v 从零开始断言所有配置都放大。短训练尤其需要正确的 step 计数与状态恢复。

**问题（追问）：哪些参数不做 weight decay？**

回答：归一化层的 gain 与所有 bias 不做衰减——它们的尺度直接决定归一化与偏移的功能，向零衰减会破坏这一功能。实现上通常按参数维度分组：一维参数 wd=0，二维及以上的权重矩阵做衰减。embedding 是否衰减因实现而异，按维度分组的实现会对 embedding 做衰减。

#### 17. cosine 学习率 schedule

核心思想：warmup 段线性升到峰值，随后按余弦半波从峰值衰减到下限，总步数需预先定死。

实现代码：

```python
import math

def cosine_lr(step, total_steps, peak=1e-4, warmup=500, min_lr=0.0):
    if total_steps <= 0 or not 0 <= warmup < total_steps:
        raise ValueError("Require total_steps > 0 and 0 <= warmup < total_steps")
    if step < 0 or not 0 <= min_lr <= peak:
        raise ValueError("Invalid step or learning-rate bounds")
    step = min(step, total_steps)
    if step < warmup:
        return peak * step / warmup              # 线性 warmup
    t = (step - warmup) / max(total_steps - warmup, 1)
    return min_lr + 0.5 * (peak - min_lr) * (1 + math.cos(math.pi * t))
```

**问题（追问）：什么时候需要 warmup，什么时候可以直接接续调度？**

回答：新建优化器、较大数据分布变化或较高初始 LR 时可用短 warmup 缓冲更新，并用 loss、梯度和参数更新范数确认稳定性。恢复同一运行的完整 optimizer 与 scheduler 状态时，可以从当前 LR 接续，不自动重复 warmup；若改变数据或优化目标，仍需验证直接接续是否稳定。warmup 是上升区间，stable 是恒定区间，二者不可混称，也不是所有训练都必须具有。

**问题（追问）：cosine 与 WSD 怎么选？**

回答：cosine 的衰减曲线由总步数决定，训练预算变更后需要重新规划整条曲线；[WSD](https://arxiv.org/abs/2404.06395)（warmup-stable-decay）主体段为常数学习率，只在末段约 10% 的步数内快速衰减，stable 段的 checkpoint 可以随时续训、追加预算或更换数据配比。多阶段续训与扩窗场景适合 WSD，预算固定的单次训练两者均可。

**问题（追问）：min_lr 设 0 还是留底？**

回答：取值依配方，不限于非零下限。Llama 3 405B 主训练为 8e-5→8e-7，DeepSeek-V3 主训练为 2.2e-4→2.2e-5；额外退火可能降到零，不能把主调度终点与最终附加阶段混用。SFT 也可用零终点 cosine，不因小数据就必须留底。decay 段 loss 下降不保证下游最优，反弹可能来自数据、数值或统计波动；用固定验证和预算对照选调度。

#### 18. LoRA 前向与合并

出处：[LoRA](https://arxiv.org/abs/2106.09685)。

核心思想：冻结 W，增量 ΔW 用低秩乘积 BA 近似（r≪d），缩放 α/r；部署时把 BA 加回 W，推理零额外开销。

实现代码：

```python
import torch, torch.nn as nn, math

class LoRALinear(nn.Module):
    def __init__(self, d_in, d_out, r=8, alpha=16):
        super().__init__()
        self.W = nn.Linear(d_in, d_out, bias=False)
        self.W.weight.requires_grad_(False)      # 冻结基座
        self.A = nn.Linear(d_in, r, bias=False)
        self.B = nn.Linear(r, d_out, bias=False)
        nn.init.kaiming_uniform_(self.A.weight, a=math.sqrt(5))
        nn.init.zeros_(self.B.weight)            # B 置零：初始 ΔW=0，从基座出发
        self.scale = alpha / r
        self.merged = False

    def forward(self, x):
        out = self.W(x)
        if not self.merged:                      # 合并后旁路低秩分支，避免增量被计算两次
            out = out + self.B(self.A(x)) * self.scale
        return out

    @torch.no_grad()
    def merge(self):
        if self.merged:                          # 防止重复合并
            return
        # nn.Linear 算 x @ Wᵀ，故 ΔW 矩阵 = B.weight @ A.weight，形状 (d_out, d_in)
        self.W.weight += (self.B.weight @ self.A.weight) * self.scale
        self.merged = True
```

**问题（追问）：为什么 B 置零、A 随机初始化？**

回答：B=0 使初始 ΔW=0；第一步 ∂L/∂A 含 B，因此为零，而 ∂L/∂B 可经随机 A 非零，B 更新后 A 才开始收到梯度。若 A/B 同时为零，两者都可能无法启动。r 与 α 随任务和更新规模扫描，不能只凭常见范围保证有效。

**问题（追问）：α/r 这个缩放在解决什么？**

回答：α/r 控制增量支路尺度，但并不严格把更新幅度与 r 解耦；初始化方差、优化器、目标模块和训练动态仍影响尺度。α 不是优化器 LR，改变 α 会同时改变前向与因子梯度。原始 LoRA 用 α/r，rsLoRA 用 α/√r 改善高秩扩展，需按实现分别说明。

**问题（追问）：合并零开销的前提与不能合的场景？**

回答：合并到兼容精度的单一 W 后没有额外低秩支路算子。多 adapter 并发切换时通常保持分支，也可为少量固定 adapter 预生成独立合并权重，以存储换计算。QLoRA 并非不能合：可反量化后合并保存高精度权重，或重新量化，后者有量化误差且需验证；不能保证与未合并量化路径严格等价。

#### 19. FlashAttention 分块思想（伪代码）

出处：[FlashAttention](https://arxiv.org/abs/2205.14135)。

核心思想：Q/K/V 分块搬进 SRAM，用在线 softmax（运行最大值 + 归一因子）逐块累积输出，T×T 注意力矩阵从不落 HBM。

伪代码：

```
输入 Q, K, V（T×d），Q 按 Bq 分块，K/V 按 Bk 分块
for 每个 Q 块 Q_i:
    O_i ← 0（Bq×d）；l_i ← 0（Bq）；m_i ← −inf（Bq）
    for 每个 K/V 块 K_j, V_j:
        S ← Q_i @ K_jᵀ / √d                  # 只物化 SRAM 可容纳的 (Bq, Bk)
        S ← 应用该块的 causal / padding mask
        跳过全屏蔽行，避免 −inf−(−inf)；有效行执行下列更新
        m_new ← max(m_i, rowmax(S))
        P ← exp(S − m_new)
        l_i ← l_i · exp(m_i − m_new) + rowsum(P)
        O_i ← O_i · exp(m_i − m_new) + P @ V_j
        m_i ← m_new
    O_i ← O_i / l_i                            # 行分母必须 > 0
    写回该 Q 块的输出
```

**问题（追问）：省的是什么、没省什么？**

回答：显存从 O(T²) 降到 O(T)——注意力矩阵不写回 HBM；FLOPs 不变，仍为 O(T²d)。提速来自 IO 感知：HBM 访问量从标准实现的 Θ(Td+T²) 降到 Θ(T²d²/M)（M 为 SRAM 容量），注意力在 GPU 上属于访存受限算子，访存减少直接转化为耗时下降。反向传播依靠重算：只保存输出 O 与 (l, m)，需要时重算 P，用计算换显存。

**问题（追问）：exp(m − m_new) 这步在干什么？**

回答：新块的局部最大值可能比之前大，已按旧 m 缩放的累积值 O、l 与新块不在同一尺度，统一乘 e^{m_old−m_new} 换底，保证任意时刻所有指数项共用同一个减去的最大值——即 stable softmax 的流式版本。

**问题（追问）：decode 阶段为什么常用别的 kernel？**

回答：decode 每步只有一个 q，没有 T² 矩阵可省，瓶颈变成 KV cache 的读取带宽；flash-decoding 类实现沿 T 维切分并行、各部分结果做 log-sum-exp 合并，paged kernel 则配合分页 KV cache 做显存管理。FlashAttention 的主战场是 prefill 与训练的大块 Q。

#### 20. MoE Router（top-k gating + 负载均衡 loss）

核心思想：router 对 token 打分过 softmax，只派给 top-k 个专家；aux loss 用负载与路由概率的乘积惩罚倾斜，防专家塌缩。

实现代码：

```python
import torch
import torch.nn.functional as F

def moe_router(x, W_gate, k=2, aux_coeff=0.01):
    # x: (N, d)，W_gate: (E, d)
    logits = x @ W_gate.T                        # (N, E)
    probs = F.softmax(logits, dim=-1)
    topv, topi = probs.topk(k, dim=-1)           # (N, k)
    # top-1 保留选中概率，避免主任务的 router 梯度被归一成常数 1
    gates = topv if k == 1 else topv / topv.sum(-1, keepdim=True)
    f = torch.zeros_like(probs).scatter_(1, topi, 1.0).mean(0) / k   # 各专家负载占比，和为 1
    P = probs.mean(0)                                            # 各专家平均路由概率
    aux = aux_coeff * probs.size(1) * (f * P).sum()              # Switch 式 E·Σf·P
    return topi, gates, aux
```

**问题（追问）：aux loss 为什么用 f 与 P 的乘积？**

回答：f 与 P 都均匀时 E·Σf_e P_e=1，这是期望的均衡状态，不是该乘积对所有可实现 f/P 的全局最小值保证。top-k 派发不可微，梯度经 P 流向 router，固定当前 f 时负载大的专家对应更大的概率惩罚。离散派发与平均概率可能错位，实际仍需监控负载；只统计 f 无普通反传路径，只约束平均 P 也不保证实际 top-k 派发均匀。

**问题（追问）：top-k 内为什么要重新归一？**

回答：top-k 内归一使混合权重和为 1，稳定输出尺度；有些架构保留原概率或加 routing scale，也同样可行。k=1 时归一会使 gate 恒为 1，选中专家输出对 router 概率的主任务梯度消失；Switch 保留选中 softmax 概率，因此存在尺度变化但保留学习路径，上例按此处理。

**问题（追问）：aux loss 与 z-loss 的分工与量级？**

回答：aux loss 管派发均衡，z-loss 是每 token 的 log-sum-exp 平方均值，管 router logits 的数值尺度。Switch 的均衡系数 1e-2、ST-MoE 的 z-loss 系数 1e-3 是各自实验设置，不是统一默认。z-loss 不等于路由熵正则：softmax 对所有 logits 加同一常数不变，log-sum-exp 却改变，因此不能说它必然把路由变均匀。系数过大可能干扰主任务，要分别消融。

#### 21. 划分数组为两个相等和子集（子集和 DP）

出处：LeetCode 416（Partition Equal Subset Sum），Hot 100 动态规划类。

核心思想：先求总和，为奇数直接不可分；否则问题等价于"是否存在子集和等于 sum/2"，用 0-1 背包可行性 DP——每个数只用一次，内层必须倒序遍历。

实现代码：

```python
def can_partition(nums):
    # 此扩展接口接受非负整数；LeetCode 原题限定至少两项正整数
    if any(not isinstance(x, int) or x < 0 for x in nums):
        raise ValueError("Require non-negative integer inputs")
    if len(nums) < 2:
        return False
    total = sum(nums)
    if total % 2:
        return False                        # 总和为奇数，不可能均分
    target = total // 2
    dp = [False] * (target + 1)
    dp[0] = True                            # 空集和为 0
    for x in nums:
        for j in range(target, x - 1, -1):  # 倒序：保证每个数只用一次
            dp[j] = dp[j] or dp[j - x]
    return dp[target]
```

复杂度：时间 O(n·target)，空间 O(target)（target = sum/2）。

**问题（追问）：为什么内层要倒序遍历？**

回答：内层 j 从 target 往 x 倒序，保证 dp[j−x] 取自"尚未使用当前数"的上一轮状态，即每个数只用一次——这是 0-1 背包与完全背包的分界；写成正序会让同一个数在本轮被重复选取，退化成完全背包。这也是面试中最常被追问的一个点。

**问题（追问）：边界与变体怎么处理？**

回答：原题是至少两项正整数；上例扩展到非负整数，空数组与单元素返回 false，至少两项时零不改变可达和。允许负数时可用集合 DP，或对“可达和的下标范围”做 offset；不能把所有元素整体加常数，因为子集元素个数不同会改变等和关系。bitset `dp |= dp << x` 可加速非负整数版本；要输出分组需记录前驱或回溯。
