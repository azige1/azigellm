### 1.1 环境合成的来源轨迹回放校验

**🗣️ 话术——环境合成的来源轨迹回放校验**：coding agent 同时推断语义、编写实现与测试时，实现和测试会共同接受同一个错误，自生成测试通过率高而语义保真度低。方案为校验证据改用真实系统采集的交互轨迹，把生成的环境放回原始轨迹逐步回放，每步比较状态差分与返回字段，只有全部关键步一致才入池。失败项连同首个分歧步回传修复，上限 3 轮。修复轮数扫描过 1、3、5 三档，1 轮时入池 1,042 个，5 轮时只多 21 个、成本增加 58%。1,480 个候选环境保留 1,146 个，独立抽检的工作流保真度由 77.8 提升至 90.6。

**动机**：环境合成的常见校验是由同一 coding agent 再写一组测试。测试通过率看起来很高，但它验证的是实现与作者理解一致，作者的理解如果错了，测试同样会通过。例如工单关闭时应同步更新指标表，agent 未写这一逻辑，自己写的测试也不会检查它。这类环境进入 RL 后，策略在错误动力学上得到高分，重放到真实系统时失效。问题发生在环境入库环节，一旦入库，后续的任务、verifier 和轨迹都建立在错误语义上，修复成本会逐级放大。

**做法**：第一步，生成规格。按业务流程种子生成 1,480 个环境规格，每个环境平均 16.4 张表、31 个工具。第二步，生成实现。coding agent 编写数据库 schema、种子数据与 MCP 工具。第三步，构造回放证据。从 6 套真实系统采集的 523,000 次工具调用日志中按流程取真实轨迹，并把实体映射到合成环境的种子数据。第四步，逐步回放。每步比较三项：工具是否成功、状态差分四元组是否一致、返回关键字段是否一致。第五步，修复。把首个分歧步的上下文与期望差分回传 coding agent，修复后重跑全部轨迹。

数值演算：1,480 个候选，首次回放通过 935 个（935 / 1,480 = 63.2%）；修复 1 轮后累计 1,042 个（70.4%）；3 轮后累计 1,146 个（77.4%）。平均修复轮数为 0.84。5 轮时累计 1,167 个，只增加 21 个，成本增加 58%。未通过的 334 个环境中，约六成是规则复杂、语义无法稳定复现的流程，暂不入池。

**取值依据**：修复上限定为 3 轮。1 轮时入池环境偏少，复杂流程被系统性过滤，跨系统任务占比由 41% 降到 28%；5 轮时修复开始过拟合回放轨迹，新增环境的保真度只有 79。回放比较粒度定为差分四元组，只比较工具成败时约 12% 的语义错误会漏过，比较全部返回文本时时间戳与排序造成大量假失败。

**收益**：独立抽检 100 个环境，工作流保真度由 77.8 提升至 90.6，对照组为同一批规格、只换校验证据的自生成测试版本。首次通过率低于自生成测试的 81.4%，因为更严格的证据暴露了更多语义错误。环境保真度直接影响策略迁移，后续 held-out 成绩建立在这批环境上。

**适用边界与代价**：要求存在可映射的真实轨迹，没有来源轨迹的流程无法入池。实体映射由 LLM 完成，映射错误会造成假失败，约占首次失败的 9%。回放校验覆盖轨迹走过的路径，轨迹之外的分支仍可能出错。整体构建成本约为自生成测试的 1.7 倍。

### 1.2 闭世界状态差分断言的 verifier 构建

**🗣️ 话术——闭世界状态差分断言的 verifier 构建**：只检查目标字段的 verifier 放过额外改动，策略顺带写错无关记录仍能得满分。方案为判定改在初末状态差分上执行声明式断言，差分中每处变化必须被某条断言解释或属于显式忽略字段，其余一律计为未声明副作用。忽略字段全局维护 14 个，扫描过 6、14、全部时间类与计数类三档，6 个时 9.7% 的合法轨迹被误判，放宽到全部时漏检增加。人工抽检 500 条判定，verifier 误判率由 13.8% 降到 2.6%，以该 verifier 筛选轨迹使 held-out Pass@1 提升 2.1。

**动机**：逐字段 verifier 的写法是列出目标字段的期望值。这种写法有两类漏洞：一是开放世界假设，没写到的字段不管对错都放行，agent 改错了其他客户的记录也能通过；二是判定依赖 verifier 作者穷举，合成任务数量上万，无法逐题人工检查。策略训练时这类漏洞会被放大，因为 RL 只看 reward，顺带的破坏性写入完全不受惩罚。判分问题应在 verifier 构建时解决，放到训练中用过程 reward补救的成本更高，也更容易被绕开。

**做法**：判定公式为：

$$
\text{Pass}(\tau)=G(S_{\text{final}})\cdot\text{clean}(\tau)\cdot\mathbb 1\big[\forall a\in A,\ \text{sat}(a,\Delta S)=1\big]
$$

第一步，计算规范差分。在隔离副本上得到各表的新增、删除、更新实体。第二步，写断言。LLM 根据参考解生成断言，每条包含差分类型、实体表、实体绑定、字段与取值约束、期望数量；$G$ 为目标 DSL 的终态判定。第三步，闭世界检查。差分中每个变化必须被至少一条断言解释，或只涉及忽略字段，否则 $\text{clean}=0$。第四步，自测。参考解回放须通过，no-op 与空提交须不通过，并加一条在无关表写入的扰动回放，须判为不干净。

隐藏工作流产生的合法副作用通过隐藏规则库自动补入断言，例如工单更新触发 `metric_instance` 变化。

数值演算：500 条抽检中，逐字段 verifier 判错 69 条，误判率 13.8%，其中 52 条为漏判未声明副作用，17 条为字段格式差异导致的误拒；闭世界 verifier 判错 13 条，误判率 2.6%，主要集中在备注字段的自由文本。候选任务经这道检查减少 3,010 道。

**取值依据**：忽略字段定为 14 个，包括更新时间、修订计数、审计序号等系统自动维护字段。取 6 个时，系统计数字段被判为副作用，9.7% 的合法轨迹被误判；把全部时间类与计数类字段都忽略时，业务字段如到期日、库存数被放过，漏检增加到 6.1%。扰动回放定为 1 条，增加到 3 条只再发现 0.4% 的问题。

**收益**：人工抽检误判率由 13.8% 降到 2.6%。以该 verifier 重新筛选 teacher 轨迹后，held-out Pass@1 由 36.8 提升至 38.9，提升 2.1。项目二 reward 的未声明副作用档也由它提供判定信号，agent 文字声明完全不参与判定。

**适用边界与代价**：要求状态完整落在可比较的数据库中，外部系统的副作用无法进入差分。系统自动维护的字段需要逐系统梳理，遗漏一个就会产生批量误判，所以新增系统时要先用 no-op 轨迹校准忽略列表。闭世界判定偏严，合理的额外操作（例如顺手补备注）也会被判不干净，项目二将其设为中间档，不按失败处理。单次判定约 40ms，可以忽略。

### 1.3 目标 DSL 判分与子目标锁存回放

**🗣️ 话术——目标 DSL 判分与子目标锁存回放**：逐题编写的 Python verifier 难以静态检查，且只给终态 0/1，组内常无分差。方案为判分改用 eq、in、all_of、any_of、count 五种算子的目标 DSL，任务编译时回放参考解确认初态不满足目标且终态满足。子目标在初态副本上只回放已提交的写操作并锁存，结果分为完成、部分完成、未完成、错误宣告、超步、放弃六类。子目标数扫描过 3、5、8 三档，3 个时组内分差不足，8 个时 DSL 生成失败率 11%，定为 5 个。SFT 模型在任务池上的零方差组占比由 38.2% 降到 26.7%。

**动机**：Python verifier 每题一段代码，生成错误难以发现，也无法批量分析任务结构。更重要的问题在 reward 粒度：只有终态 0/1 时，同一任务的 8 条 rollout 经常全错，组内 advantage 为零，RL 预算被浪费。长程任务尤其如此，完成了前 4 个步骤的轨迹和完全没做的轨迹得到同样的分数。子目标如果按终态计算，又会忽略中途完成后被破坏的情况，或者把撤销操作算作进度；如果按过程计算，容易被反复尝试刷出。因此需要一种可静态检查的判分语言和一套明确的进度语义。

**做法**：第一步，表达式定义。DSL 支持五种算子，字段可沿外键上溯，例如 `ticket.TK-0857.customer.account_manager`。第二步，编译门禁。规格校验实体引用与类型，要求初始快照不满足目标，要求参考解步数小于步数上限，并逐步回放参考解确认最终满足。第三步，子目标回放。在初态快照的临时副本上只回放已提交的写操作，每执行一步计算全部子目标，满足后锁存，不随后续动作撤销。第四步，结果分类：

| 结果 | 判定 |
| --- | --- |
| complete | 终态满足目标 |
| partial | 终态不满足，有子目标锁存 |
| incomplete | 无子目标锁存，正常结束 |
| error | agent 宣告完成但终态不满足 |
| exceeded | 超出步数上限 |
| abandoned | agent 主动放弃 |

数值演算：一道任务 5 个子目标，8 条 rollout 终态全部失败，但锁存数分别为 0、1、1、2、2、3、3、4。锁存比例 $r=k/5$，reward 按 $0.10+0.20r$ 映射到部分完成档，取值 0.10 至 0.26，组内出现分差，advantage 不再为零。

**取值依据**：子目标数定为 5（允许 3 至 8）。固定 3 个时分辨率不足，零方差组占比 31.6%；固定 8 个时 LLM 拆分质量下降，DSL 生成失败率 11%，零方差组只再降到 26.1%。DSL 覆盖 92% 的任务，其余 8% 涉及文本语义，保留 Python verifier 并单独抽检。

**收益**：SFT 模型在任务池上 8 次采样的零方差组占比由 38.2% 降到 26.7%，同一批 2,400 道任务对照。部分完成结果为项目二提供了组内分差，项目二开训时的有效组率比二值判分高约 11 个百分点。

**适用边界与代价**：DSL 只表达结构化状态，文档正文质量这类判断需要 rubric 另行处理。锁存语义可能reward中途完成又破坏的轨迹，因此部分完成只作中间档，终局 complete 依然以终态为准。子目标来自 LLM 拆分，拆分粒度不均时会让部分任务的进度分虚高，须按任务族抽检。编译回放使每个任务增加约 6 秒，24,600 道候选累计约 41 小时，64 并发约 40 分钟。

### 1.4 隐藏规则约束的欠指定任务合成

> A 题名：隐藏规则约束的欠指定任务合成

**🗣️ 话术——隐藏规则约束的欠指定任务合成**：随机组合工具生成的任务指令直白、ID 直接给出，隐藏规则几乎不被触发，模型学不到先查询再判断的行为。方案为生成时以已验证规则作约束，要求参考解经过规则触发条件，并控制 ID 是否需要查询、目标是否存在歧义两个维度，再经五道质量门过滤，其中第一道拒绝初始状态已满足目标的候选。隐藏规则任务占比扫描过 20%、38%、60% 三档，60% 时 teacher 通过率降到 53%、可用任务减少，定为 38%。候选 24,600 道入池 10,860 道，隐藏规则切片 Pass@1 由 21.9 提升至 28.3。

**动机**：常规任务合成从工具组合出发写指令，指令往往把目标 ID 与操作步骤写全，agent 照着调用就能通过。这种任务训练出的模型遇到真实请求时两类能力不足：一是不会先查询定位实体，二是看不到操作的连带影响。例如分配第四件资产会让用户权限降级，后续审批因此失败，模型不会提前检查。环境回放校验时已从来源轨迹中归纳并确认 1,793 条隐藏规则，这份知识可以直接用来构造能暴露连带影响盲区的任务，避免随机采样覆盖不到。

**做法**：第一步，抽取任务骨架。从规则出发，要求参考解至少经过一条隐藏规则的触发条件，例如让用户资产数恰好越过阈值。第二步，设置两个难度维度。信息可得性：指令是否给出 ID，71% 的任务要求先查询；歧义度：是否存在干扰实体，分无歧义、需核对一个字段、需跨表核对三档。第三步，生成指令与断言。第四步，经五道质量门：

| 门 | 判定 | 淘汰数 |
| --- | --- | --- |
| 初始状态检查 | 初态不得满足目标 | 2,040 |
| 参考解回放 | 编译期回放通过 | 3,220 |
| verifier 一致性 | 自测与扰动回放通过 | 3,010 |
| 泄漏与近重复 | 指令不含答案，工作流签名去重 | 2,590 |
| 可解性与难度 | teacher 16 次至少通过 1 次，SFT 模型 16 次通过不超过 12 次 | 2,880 |

数值演算：2,040 + 3,220 + 3,010 + 2,590 + 2,880 = 13,740，24,600 − 13,740 = 10,860，留存 44.1%。切分为 SFT 3,660、RL 6,720、held-out 480，三者之和 10,860。隐藏规则任务占 38%，约 4,127 道。

**取值依据**：隐藏规则任务占比定为 38%。20% 时隐藏规则切片 Pass@1 只升到 25.2；60% 时 teacher 通过率由 71% 降到 53%，可用于 SFT 的成功轨迹减少，整体 Pass@1 反降 0.6。要求查询 ID 的比例由任务合成自然形成，上限不设硬约束。难度带上限取 12/16，排除 SFT 模型已掌握的任务，留给 RL 的任务保持组内分差。

**收益**：隐藏规则切片（84 道 held-out 任务）Pass@1 由 21.9 提升至 28.3，提升 6.4；整体 held-out Pass@1 由 38.9 提升至 40.6，提升 1.7。初始状态门单独消融时，整体下降 1.2，这类任务让模型不操作也能得分。

**适用边界与代价**：依赖隐藏规则库，规则错误会合成出错误任务，因此只使用经回放确认的规则。规则集中在少数系统时任务分布会偏斜，要按系统配额采样。难度筛选用到 SFT 模型，模型更新后需要重估。末道门进入 13,740 道，teacher 与 SFT 模型各 16 次，共约 44 万条 rollout，是五道门中成本最高的一道。

### 1.5 错误片段分流的轨迹合成与 loss mask

**🗣️ 话术——错误片段分流的轨迹合成与 loss mask**：只保留一次成功的干净轨迹时，模型学不到报错后的恢复；错误动作计入 loss 又会强化错误。方案为 teacher 轨迹按步标注环境故障、可纠正错误、未解决失败与编造四类：环境故障与编造整条剔除，占 21%；可纠正错误留在上下文但屏蔽 loss，平均每条 1.7 段；未解决失败从最后正确状态由 teacher 续写，共 2,140 条。续写比例扫描过 0、4.6%、12% 三档，12% 时续写段风格与原段差异增大、验证集无提升。46,400 条轨迹入训 31,891 条，报错后两步内恢复率由 46% 提升至 69%。

**动机**：teacher 成功轨迹大多是一条直线，学生部署后遇到工具报错时没有可模仿的样本，表现为重复同一调用或直接结束。保留失败轨迹又有风险：错误动作参与 loss 会强化错误，环境故障和编造会污染数据。工程上常见的做法是按整条轨迹成败二分，这会同时舍弃含有效纠错过程的样本，也会放进编造内容。错误类型决定处理方式，分流需要细到步级别。

**做法**：第一步，回放一致检查。轨迹在环境中重放，分数不一致的丢弃，留存 87%，46,400 × 0.87 ≈ 40,368 条。第二步，步级标注。规则识别退出状态与报错，judge 判断错误是否被纠正：E0 环境故障、E1 可纠正错误、E2 未解决失败、E3 编造。第三步，分流。E0、E3 整条剔除，分别占 9.2% 与 11.8%，留存 79%，得到 31,891 条。第四步，掩码。错误片段为错误动作的 thinking 与工具调用，其后的报错返回照常保留在上下文：

$$
L=-\frac{\sum_t m_t\log\pi(x_t\mid x_{<t})}{\sum_t m_t},\quad
m_t=\begin{cases}1 & x_t\text{ 属于 assistant 且不在错误片段内}\\0 & \text{其他}\end{cases}
$$

第五步，续写。E2 轨迹从最后一个正确状态交给 Qwen3.5-397B-A17B 续写，通过 verifier 的 2,140 条保留。

数值演算：31,891 条中 E2 续写占 2,140 / 31,891 = 6.7%。按全部轨迹算掩码比例：平均 1.7 段、每段约 310 token，assistant token 平均约 12,400，屏蔽比例约 4.2%。消费 token = 31,891 × 37,000 × 2 ≈ 2.36B，global batch 约 2.37M token，997 步。

**取值依据**：续写比例上限取 6.7%（占入训），相当于保留 E2 中续写成功的部分。不续写时恢复率只有 58%；放宽 verifier 使比例到 12% 时，续写段由另一模型生成，风格差异增大，验证集无提升，部分样本反而学到无依据的跳步。错误片段起点取 thinking 开头，只屏蔽工具调用时模型仍会学到错误推理。

**收益**：held-out 上工具报错后两步内恢复的比例由 46% 提升至 69%，Pass@1 由 40.6 提升至 42.3，提升 1.7，AutomationBench v1.0.6 累计由 30.1 提升至 37.6。

**适用边界与代价**：错误标注依赖 judge，E1 与 E2 的边界存在约 6% 的分歧，抽检时按保守方向处理。可纠正错误必须有环境真实返回的报错内容才可信，编造的报错一律按 E4 剔除。续写轨迹约占 teacher 总调用量的 9%。掩码边界错误会悄然改变 loss，每次改模板后要人工核对 5 条 token 级标签。

### 2.1 终态记录的确定性 reward 与档位单调性

**🗣️ 话术——终态记录的确定性 reward 与档位单调性**：reward 含回复文本判分时，策略学会未完成即宣告完成，这类轨迹占 18.6%。方案为 reward 依据终态记录、状态差分与结构化事件，agent 的文字声明不进入评分，六档得分为完成且干净 1.0、未声明副作用 0.35、部分完成 0.10 至 0.30、合理放弃 −0.15、截断 −0.50、错误写入 −0.85，基础设施失败不产生梯度。截断得分扫描过 0、−0.25、−0.50 三档，0 高于合理放弃时策略学会拖满预算。改动后宣告未完成轨迹占比降到 6.4%，Pass@1 由 45.4 提升至 47.9。

**动机**：GRPO baseline 的 reward 是任务完成度、回复质量与效率的加权和，回复质量由 LLM judge 打分。这种 reward 有两类问题。其一，可被利用：训练约 80 步后，回复中出现大量“已全部完成”的总结，judge 分上升而任务完成率不涨，未完成即宣告完成的轨迹占比达到 18.6%。其二，加权和允许用高分项掩盖错误写入，策略改错一条记录仍可能得到 0.6 以上。这两类问题都来自评价对象过宽，reward 需要回到可验证的事实上。

**做法**：第一步，确定评价对象。评分只看三类事实：终态记录是否满足目标 DSL、差分是否干净、子目标锁存数。agent 的回复文本与自我陈述全部不进入 reward。第二步，定义档位：

| 档位 | 条件 | reward |
| --- | --- | --- |
| 完成且干净 | 目标满足，差分全部可解释 | 1.0；含文本产物的任务为 0.40 + 0.60S，见 2.4 |
| 完成但有未声明副作用 | 目标满足，clean = 0 | 0.35 |
| 部分完成 | 目标未满足，锁存比例 r | 0.10 + 0.20r |
| 合理放弃 | 主动放弃且未发生写入 | −0.15 |
| 截断 | 触达轮数或窗口上限 | −0.50 |
| 错误写入 | 触发禁止动作或写错目标实体 | −0.85 |
| 基础设施失败 | 环境或服务故障 | 不产生梯度 |

档位互斥，判定优先级依次为基础设施失败、错误写入、截断、主动放弃、完成、部分完成，例如触发禁止动作后即使目标满足也记错误写入。

第三步，三项检查。单调性：相邻档位不得倒置。反例检查：过程项先在难任务上找反例。第三条路检查：小规模再训练后统计各档频次变化，确认策略没有转向未设想的行为。

数值演算：部分完成的上限为 $0.10+0.20\times 1=0.30$，子目标全部锁存但终态被破坏时也封顶在这里，低于未声明副作用档 0.35，也就是说把事情做完但带副作用，仍优于只完成部分。合理放弃与截断相差 0.35，超过组内常见 reward 标准差 0.22，策略能够区分。

**取值依据**：截断得分定为 −0.50。取 0 时截断高于合理放弃，策略拖到预算耗尽，平均轮数由 31 升到 39；取 −0.25 时仍有 12% 的轨迹拖到上限。未声明副作用档定为 0.35，取 0.6 时策略不在意副作用，干净完成率不升；取 0.1 时低于部分完成，策略倾向停在部分完成。

**收益**：未完成即宣告完成的轨迹占比由 18.6% 降到 6.4%，统计口径为每步全部轨迹中 `outcome=error` 的比例。held-out Pass@1 由 45.4 提升至 47.9，提升 2.5。去掉回复 judge 后，rollout reward 服务的成本下降约七成。

**适用边界与代价**：要求验收目标可以表达为结构化终态，写进系统字段的文本产物由 2.4 的 rubric 判定。reward 不看回复后，面向用户的回复写作质量缺少约束，训练后抽检回复可读性下降约 3%。档位表是人工设计的，换场景要重新做三项检查。部分完成依赖子目标质量，子目标拆分偏差会影响中间档。

### 2.2 teacher 调幅的 step 级 advantage 与退化组补偿

> A 题名：teacher 调幅的 step 级 advantage 与退化组补偿

**🗣️ 话术——teacher 调幅的 step 级 advantage 与退化组补偿**：环境回报只有轨迹级信号，单元素组与零方差失败组几乎不产生 step 级梯度。方案为引入 Qwen3.5-397B-A17B 给出 step 级偏好：组内按 teacher log-prob 排名，单元素组用师生 log-prob 差经批内标准化后以 tanh 压界。环境 advantage 写作 $A^{env}=A^E+0.5A^S$，总 advantage 为 $A^{env}+\lambda\tilde L_T|A^{env}|+\mu\mathbb 1_{deg}\tilde L_T$，调幅项只改变幅度、不改变符号，退化项只在回报完全相同的失败组生效。λ 扫描过 0.1、0.3、0.6 三档，0.1 时增益约 0.9，0.6 时动作分布向 teacher 靠拢、entropy 过快下降，定为 0.3；μ 取 0.1。该点使 Pass@1 由 47.9 提升至 50.6。

**动机**：长程任务一条轨迹有几十个动作，episode advantage 让它们共享一个符号，成功轨迹里的冗余读取和失败轨迹里的正确查询都得不到区分。GiGPO 用相同状态分组给 step 级信号，但业务状态几乎不重复，很多步落入单元素组，没有比较对象。另一类问题是零方差失败组，开训时约占 18%，组内 8 条轨迹回报完全相同，这些任务恰恰是模型最需要学习的。直接加蒸馏 loss 可以补信号，但 teacher 不适合当前任务时会把策略拉离环境回报的方向。

**做法**：第一步，分组路由。路由放在零方差过滤之前：组内 reward 有差异的为混合组，含全部未完成但子目标进度不同的组，走 RL；组回报标准差不超过 0.01 且全部完成的为全通过组，advantage 为零，本步不产生更新；组回报标准差不超过 0.01 且未完成的为零方差失败组，走 teacher 补偿。第二步，计算总 advantage：

$$
A_{\text{total}}(a_t)=A^{env}(a_t)+\lambda\cdot\tilde L_T(a_t)\cdot|A^{env}(a_t)|+\mu\cdot\mathbb 1_{\text{deg}}\cdot\tilde L_T(a_t),\quad A^{env}=A^E+0.5A^S
$$

第一项为环境 advantage，决定方向；第二项的 $|A^{env}|$ 保证 teacher 只改变幅度，当 $|\tilde L_T|\le 1$ 且 $\lambda<1$ 时，前两项之和的符号与 $A^{env}$ 相同；第三项是独立的 teacher 更新，只在零方差失败组生效，这类组 $A^E=0$，方向由 teacher 决定，不属于符号保持的范围。

teacher 偏好 $\tilde L_T$ 的构造分两路。组内成员不少于 2 个时，取动作段长度归一化的 teacher log-prob，按序数秩映射到 $[-1,1]$。单元素组用差值 $\Delta=\log\pi_T-\log\pi_\theta$，这个差值的期望为负，先做 batch 级 z-score 修正，再截断到 $[-3,3]$，以 tanh 压界。

teacher 部署：Qwen3.5-397B-A17B，16×H100，与学生共享 tokenizer，只打分不生成，训练步内与参考模型前向并发。

数值演算：某成功轨迹 $A^{env}=0.8$，一次写前核对动作在组内排名靠前，$\tilde L_T=0.6$，则 $A=0.8+0.3\times0.6\times0.8=0.944$；同轨迹一次重复读取 $\tilde L_T=-0.8$，$A=0.8-0.192=0.608$，两者符号相同、幅度不同。零方差失败组 $A^{env}=0$，一个正确查询 $\tilde L_T=0.7$，$A=0.1\times0.7=0.07$，一个无效调用 $\tilde L_T=-0.9$，$A=-0.09$。

**取值依据**：λ 定为 0.3。取 0.1 时增益约 0.9 个点；取 0.6 时动作分布快速靠近 teacher，前 80 步 entropy 下降 31%，有效组率提前回落。μ 定为 0.1，取 0.3 时零方差失败组贡献的梯度范数超过混合组，策略开始优先拟合 teacher；取 0.03 时无可测增益。排名方式选序数秩，minmax 在组内极差小于 0.1 nats 时会把多数动作压到边界。

**收益**：held-out Pass@1 由 47.9 提升至 50.6，提升 2.7，是 RL 阶段单项增益较大的一项。零方差失败组的任务在下一轮采样中转为混合组的比例由 21% 升到 34%，这些任务重新进入有效梯度。

**适用边界与代价**：要求 teacher 与学生同 tokenizer，并在目标任务上确实更强，teacher 能力不足时信号变成噪声，开训前须在任务池上核对 teacher 通过率。teacher 服务占 16 张卡，训练步时增加约 11%，服务超时时该批次退回纯环境 advantage。对长度敏感，动作段长度差异大时要做长度归一化。teacher 偏好来自模型自身判断，无法替代环境验证，所以非退化组保持环境 advantage 的符号，退化项系数也限定在 0.1。

### 2.3 规范化报错 anchor 的 GiGPO step 级分组

**🗣️ 话术——规范化报错 anchor 的 GiGPO step 级分组**：GiGPO 按观测文本分组时，时间戳与记录 ID 使第二步之后几乎都是单元素组，单元素组占比 94%。方案为以去除 ID、时间与数值后的规范化报错模板作 step 级 anchor，同一报错状态下的不同恢复动作进入同组比较，无报错步不计 step 级 advantage。初始实现里第 0 步 anchor 与 episode 组重合，advantage 被重复计入，定位后把首步排除。规范化粒度扫描过只去 ID、去 ID 与时间、再去数值三档，第一档单元素组 83%，第三档组内混入不同语义的报错，取第三档加字段名保留。单元素组占比降到 58%，Pass@1 由 50.6 提升至 52.4。

**动机**：GiGPO 的 step 级 advantage要求同一状态下存在多个动作，比较它们的回报差。办公任务的观测包含时间戳、记录 ID 与分页游标，几乎不重复，分组退化，step 级 advantage大面积失效。与此同时，真正决定长程任务成败的时刻往往是报错之后：策略是换参数、换工具，还是重复调用。这些时刻有天然的等价性，同一类报错的恢复动作可以比较，所以可以用报错类型定义状态等价。

**做法**：第一步，抽取报错。工具返回 `isError` 或 verifier 报错时取错误文本，无报错步打上 `no_error`，不进入 step 级分组。第二步，规范化：

```text
原始：HTTP 409: ticket TK-0857 locked by workflow WF-2231 at 2026-08-14T09:21
模板：HTTP 409: ticket <ID> locked by workflow <ID> at <TIME>
```

替换规则覆盖 ID、时间、数值、路径，保留错误码、字段名与工具名。第三步，分组。键为 `hash(模板, 工具名, 已锁存子目标数)`，同任务内按键聚合。相同报错不等于完全相同的决策状态，这是一种近似状态聚合，加入进度条件后按组内 reward 方差抽检异质性。第四步，step advantage。组内按折扣回报计算：

$$
A^S_t=\frac{G_t-\bar G_{\text{group}}}{\sigma_{\text{group}}+\epsilon}
$$

单元素组 $A^S_t=0$。第五步，组合为环境 advantage：$A^{env}=A^E+0.5A^S$，再进入 teacher 调幅。

初始实现的问题：第 0 步还没有发生交互，anchor 恒为任务本身，step 组与 episode 组完全重合，同一advantage 被计入两次，前 30 步 reward 上升更快而 held-out 没有提升。定位方式是比较 $A^S_0$ 与 $A^E$ 的相关系数，得到 0.98。修复后排除 $t=0$。

数值演算：一步采样 320 条 Root 轨迹，平均 31 轮，共约 9,920 步，其中报错步约 14%，约 1,390 步。分组后 58% 为单元素组，约 806 步；其余 584 步属于约 170 个组，平均组大小约 3.4。按观测字符串分组时只有约 83 步（6%）属于多成员组，step 级梯度覆盖提升约 6 倍。

**取值依据**：规范化取去 ID、时间、数值并保留字段名。只去 ID 时时间戳仍使单元素组占 83%；再把字段名也去掉时，“预算不足”和“权限不足”被归到同一组，组内比较失去语义。step advantage权重 0.5，取 1.0 时前期波动加大，取 0.25 时增益减半。

**收益**：单元素组占比由 94% 降到 58%，分母为报错步。held-out Pass@1 由 50.6 提升至 52.4，提升 1.8。报错后重复同一调用的比例由 23% 降到 11%，这一读数与项目一的恢复样本方向一致。

**适用边界与代价**：只覆盖报错步，无报错的决策不受益，这部分由 teacher 调幅覆盖。报错文本要有足够结构，自由文本报错规范化效果差。去掉数值后余额、权限等状态差异被合并，回报差不能完全归因于动作。模板表需要随系统更新维护。第 0 步排除后，首步选择完全由 episode advantage决定。分组计算增加的耗时不足步时的 1%。

### 2.4 agentic rubric 的环境探查生成与文本产物 reward

**🗣️ 话术——agentic rubric 的环境探查生成与文本产物 reward**：终态 reward 只检查文本字段是否写入，工单回复与邮件正文内容空洞仍判完成，任务全部完成的组也因回报相同不产生梯度。方案为 rollout 前由 rubric agent 只读探查初始环境，为 1,290 道含文本产物的任务生成冻结且对策略不可见的 rubric，平均 11 条，权重 1 至 3；实体与数值条目编译为状态查询，语义条目由 judge 只看产物判定。完成且干净档 reward 改为 $0.40+0.60S$，其余档位不读取 $S$。基础分扫描过 0.40、0.55、0.70 三档，0.70 时切片增益只有 2.1，0.40 是保持档位单调的取值。初版条目写死措辞，人工合格产物均分只有 0.58，改为只约束事实与规约后升到 0.86。文本切片 Pass@1 由 36.4 提升至 41.9，整体 Pass@1 由 52.4 提升至 53.5。

**动机**：2.1 把回复文本移出 reward 后，评分只看结构化事实。工单回复、邮件正文、审批说明这类写进系统字段的文本产物，字段非空就算目标满足。RL 中期抽检完成且干净的轨迹，这类产物 31% 内容空洞或与记录不符，例如回复里没有处理结论，退款金额与订单不一致。同时这类任务到后期 8 条全部完成时回报相同，advantage 为零，不产生梯度。逐题手写 verifier 判断不了语义；整篇 LLM judge 打分会把 2.1 排除的评分波动带回来；不看环境直接写 rubric 时条目只能泛泛而谈，写不出「退款金额须与该订单记录一致」这样的具体判据。

**做法**：第一步，标注范围。任务元数据标出含自由文本字段的任务，训练集 1,290 道（19.2%），held-out 96 道（20%）。第二步，生成 rubric。rubric agent 读取任务指令与 schema，用只读工具查询该任务的初始环境，上限 20 轮，平均 14 轮，看不到参考解与目标 DSL。输出分事实一致、业务规约、内容完整三轴，每条只判一件事，权重取 1、2、3，不允许写死措辞：

```json
{"task_id": "env0417-t26", "items": [
  {"id": "r3", "axis": "fact", "weight": 3, "check": "state",
   "query": "SELECT amount FROM refund WHERE ticket_id='TK-0857'",
   "rule": "正文中的退款金额等于查询结果"},
  {"id": "r7", "axis": "norm", "weight": 2, "check": "judge",
   "text": "说明后续处理人与答复时限"}
]}
```

第三步，判定。平均 11 条中 4.3 条编译为状态查询，由程序判定；6.7 条语义条目由 judge 判定，judge 只看任务指令、条目与产物文本，不看轨迹与 agent 的回复。每条记 0 或 1，文本分 $S=\sum w_is_i/\sum w_i$。第四步，接入 reward。只有完成且干净档读取 $S$：

$$
r=0.40+0.60\,S
$$

下限 0.40 高于未声明副作用档的 0.35，六档单调不变。其他档位不读取 $S$，文本写得再好也不能弥补任务未完成。文本分只进入 episode reward，经 episode advantage 传递，step 项仍只来自报错 anchor。

把 rubric 分用作在线 reward 时的三类风险与处置：

| 风险 | 现象 | 处置 |
| --- | --- | --- |
| reward hacking | step 60 起产物长度 P50 涨到初始的 1.8 倍，切片分不涨 | 抽取文本中的 ID 与金额回查状态，查不到时按权重 3 的条目记不通过，长度 P50 回落到 1.1 倍 |
| 判分非平稳 | 重新生成 rubric 后同一产物的分数漂移 | 训练全程冻结 rubric、judge 权重与提示，版本写进运行清单 |
| 信用分配 | 文本分差无法定位到具体动作 | 只作用于 episode 项，不另设 step 项，避免与报错 anchor 重复计入 |

judge 选型：训练 judge 用 Qwen3.5-397B-A17B，复用 teacher 的 16×H100 服务，teacher 打分结束后错峰判定。它的规模高于 policy，400 条条目级金标上假阳性率 1.7%。评测 judge 保持 GLM-5，held-out 的 rubric 由人工定稿，训练 rubric、训练 judge 都不参与评测。

初始实现的问题：初版 rubric 把模板里的措辞写进条目，人工合格产物均分只有 0.58，同一产物判两次的判定翻转率为 11%。排查时先用 200 份人工写的合格产物作探针，再按条目统计不通过率，发现集中在写死措辞的条目。改为只约束事实与规约，并删除翻转率高的条目后，人工合格产物均分升到 0.86，判定翻转率降到 2.4%。

数值演算：某产物总权重 23，未通过条目权重 3 与 2，$S=18/23=0.78$，$r=0.40+0.60\times0.78=0.87$；同一任务另一条轨迹 $S=1$，$r=1.0$，组内分差恢复。每步 40 道任务约 7.7 道含文本产物，Root 轨迹约 62 条，其中完成且干净约 34 条，每条 6.7 个语义条目，每步约 228 次条目判定，增加约 4% 步时。切片提升 5.5，切片占 held-out 的 $96/480=20\%$，折合整体 $5.5\times0.2=1.1$。

**取值依据**：基础分定为 0.40。低于 0.35 时干净完成可能低于带副作用完成，档位倒置；取 0.55 时切片增益 3.4，取 0.70 时 2.1，分差不足以形成梯度。探查上限定为 20 轮，平均用到 14 轮；取 8 轮时切片增益 3.7，完全不探查时只有 2.6，取 30 轮时平均轮数只增加到 15，成本增加，增益不变。

**收益**：文本切片 Pass@1 由 36.4 提升至 41.9，提升 5.5；整体 held-out Pass@1 由 52.4 提升至 53.5，提升 1.1，高于评测门限 0.9。完成且干净轨迹中产物空洞或与记录不符的比例由 31% 降到 12%。含文本产物的全通过组中 63% 恢复了组内分差，重新产生梯度。

**适用边界与代价**：只覆盖含文本产物的任务。rubric 质量依赖生成 agent，过度指定会误伤合格产物，要持续用人工合格产物作探针监控。开训前生成一次，按单轮约 9 秒、并发 32 计算约 1.4 小时；任务初态变化时要重新生成。judge 判定增加约 4% 步时，服务超时时该批次的 $S$ 按语义条目缺失处理，只用可编译条目计算。语义条目的判定上限取决于 judge 能力，假阳性率高于 2% 时暂停使用语义条目。

### 2.5 轨迹窗口的分阶段扩展

> A 题名：轨迹窗口的分阶段扩展

**🗣️ 话术——轨迹窗口的分阶段扩展**：直接用 128K 窗口时前 50 步 rollout p95 时长 41 分钟，全程用短窗口又使长任务大量截断，截断率 11.3%。方案为窗口按 64K、96K、128K 三档扩展，升档判据为成功轨迹长度 P90 超过窗口 85% 且截断率连续 30 步高于 4%，升档 step 为 110 与 230。扩窗后失败轨迹更早触顶，尾部负梯度放大，升档后 40 步把梯度裁剪阈值由 1.0 降到 0.6 并开启重复检测。阈值扫描过 75%、85%、95% 三档，75% 时过早升档，95% 时截断率超过 8%。截断率降到 3.6%，Pass@1 由 53.5 提升至 54.6，纯训练时间比全程 128K 减少 23%。

**动机**：长程 RL 的窗口是一个成本与能力的权衡。开训即用最大窗口，早期策略产生大量无效长轨迹，rollout 长尾把整批时间拉长，推理池利用率低于四成。全程 64K 时，31 轮平均任务勉强够用，但 40 轮以上的任务大量触发截断，策略被迫提前收尾。还有一个容易忽略的问题：窗口放大后，失败轨迹的长度比成功轨迹涨得更快，先撞到新上限，序列尾部全是负 advantage 的 token，梯度集中在尾部，出现重复生成与尾部乱码。

**做法**：第一步，判据。每 10 步计算成功轨迹长度 P90 与截断率：

$$
\text{expand}=\big(\text{P90}_{\text{succ}}>0.85W\big)\wedge\big(\text{trunc}>4\%\ \text{持续 30 步}\big)
$$

第二步，升档。满足判据时窗口升一档，同时调整序列并行度与 micro batch。第三步，稳定期。升档后 40 步内梯度裁剪阈值由 1.0 降到 0.6，开启重复检测，连续重复超过阈值时提前终止轨迹，按截断计分。第四步，恢复。稳定期内尾部乱码率低于 1% 时恢复原设置。

记录示例：

```json
{"step": 230, "window": 96000, "len_p90_succ": 83100, "trunc_rate": 0.051,
 "decision": "expand_to_128000", "stabilize": {"steps": 40, "clip": 0.6, "repeat_stop": true}}
```

数值演算：96K 窗口下，升档判据要求成功轨迹 P90 超过 $0.85\times 96000=81600$，记录中 83,100 满足条件。全程 128K 的估算步时约 1,080 秒，分阶段平均 830 秒，比值约 0.77，纯训练时间由约 102 小时降到约 78.4 小时，减少 23%；单次约 90.0 小时另含有效利用率折算与两次故障恢复。

**取值依据**：P90 阈值定为 85%。取 75% 时第一次升档提前到 step 62，rollout 长尾回到原来水平；取 95% 时升档滞后，截断率超过 8% 后才动作。稳定期定为 40 步，取 20 步时第二次升档后尾部乱码率回升到 2.4%；取 80 步时裁剪偏紧，学习变慢。

**收益**：截断率由 11.3% 降到 3.6%，以最终版本在 held-out 上统计。Pass@1 由 53.5 提升至 54.6，提升 1.1。纯训练时间减少 23%。尾部乱码率由 3.1% 降到 0.6%。

**适用边界与代价**：起步窗口要覆盖 SFT 后输出长度的 P99，否则短窗口 RL 会使模型失去长任务能力。升档时序列并行度变化需要重建数据加载，每次loss约 6 分钟。重复检测阈值过低时会打断合法的批量写入，要按工具类型放宽。判据依赖成功轨迹，成功率过低时 P90 不可靠，开训前通过率需高于 30%。

## 三、项目三：多 harness 评测协议与回退归因

> **🎯 项目整体话术**：长程 agent 的 checkpoint 比较有三个常见问题：单次 rollout 的差异小于噪声，判分只看终态放过过程违规，分数涨跌分不清来自版本漂移还是能力变化。项目三在开源多 harness 评测框架上建立五个环节：运行清单与 judge replay、约束下成功率判分、judge 金标校准、配对统计、单因素回退归因。这套协议统一验收项目一、项目二的版本，配对五遍把差值判定门限由 6.3pp 降到 0.9pp，judge 假阳性率由 7.4% 降到 1.8%。本人负责约束下判分与回退归因，参与 judge 校准与统计工具实现。

**🏗️ 业界标准 pipeline**

agent 评测的通用流程为 benchmark 选型、隔离与去污、运行、判分、统计与归因。公开框架通常提供任务定义、沙箱运行与 judge 判分，统计多为单次均值。本项目以开源多 harness 评测框架为骨架，保留任务与 judge 接口，补上运行清单、过程约束判分、judge 校准和配对统计，评测规格由三层组成：自建 held-out、公开办公与通用 benchmark、三种 harness。

### 3.1 运行清单与 judge replay 的版本固定

**🗣️ 话术——运行清单与 judge replay 的版本固定**：模型、harness、工具返回截断、环境快照、判分提示任一变化都会改变分数，事后无法区分版本漂移与能力变化。方案为每次运行写入记录 12 个版本字段的运行清单并计算哈希，除模型字段外清单不一致的结果不进入对比；judge 或提示升级时 replay 已存轨迹重判，替代重新 rollout。清单字段由 7 个扩到 12 个，补上截断上限、日期上下文等漂移源。一次 ALE Overall 上 1.6 的提升经清单比对定位为截断上限由 4K 改到 8K，并非模型变化。judge 升级一次 replay 约 1.44 万条轨迹，只重跑判分，不占用 rollout 卡时。

**动机**：评测在项目中持续数月，期间工具、提示、环境都在变。分数上涨时，团队天然倾向归因于模型，而实际可能只是截断上限放宽或者系统提示改动。这类漂移难以在结果层面发现，只能依靠运行时记录。judge 也会更新，如果每次都重新 rollout，41 个候选版本的历史结果无法对比，成本也不可接受。这个问题落在评测基础设施层，缺少版本固定时后续统计检验都失去意义。

**做法**：第一步，定义清单。12 个字段：模型、harness、工具列表哈希、工具返回截断、系统提示、日期上下文、环境快照、任务集、最大轮数、judge 模型、判分提示、种子列表。第二步，计算哈希。`run_hash` 由除模型外的全部字段得到。第三步，比较门禁。对比脚本读取两个版本的清单，哈希不同时拒绝输出差值，只给出字段差异。第四步，轨迹与判分分离。rollout 产物落盘，判分结果带 judge 版本，judge 升级时只重跑判分。第五步，重判校验。replay 后抽样比对旧版结果，翻转率超过 8% 时要求人工复核差异条目。

数值演算：一个版本的全量评测包括 480 × 5 = 2,400 条 held-out rollout、两个公开集约 1.2 万条，约 1.44 万条。judge 升级时 replay 这些轨迹，只付判分成本：rollout 需要约 6 小时 × 24 卡 = 144 卡时，判分只需约 0.5 小时 API 调用。

**取值依据**：字段数定为 12。最初 7 个字段只覆盖模型、harness、环境、任务、judge、种子、最大轮数，漏掉截断与日期这两个后来实际造成漂移的来源。继续增加到操作系统、依赖版本时，哈希频繁变化而分数不变，比较门禁被绕过，因此这些字段只记录、不计入哈希。翻转率告警线取 8%，5% 时正常 judge 升级也频繁告警，12% 时一次提示错误未被发现。

**收益**：41 个候选版本的结果全部可比。一次 ALE Overall 上 1.6 的提升被定位为截断上限变化，恢复统一配置后差值消失。judge 升级时不再占用 144 卡时的 rollout。

**适用边界与代价**：清单只能记录已知字段，未列入的漂移源仍然存在。比较门禁使紧急实验的产出变慢，需要允许显式豁免并在报告中标注。轨迹落盘占用存储，全量约 3TB，按版本保留。replay 只适用于判分依赖产物的 benchmark，依赖在线交互的评测仍要重跑。

### 3.2 约束下成功率与调用顺序判分

**🗣️ 话术——约束下成功率与调用顺序判分**：终态通过的轨迹可能写前未读取，或中途越权后再撤销，只看终态的成功率无法发现。方案为判分在终态检查之外增加工具调用先后顺序断言，例如写操作之前必须读取目标记录，并以成功且全程未违规计通过。断言范围扫描过全部写操作、高风险写操作、仅禁止动作三档，全部写操作时误报 8.1%，仅禁止动作漏掉写前未核对，取高风险写操作。RL 后成功率 54.6 对应约束下成功率 47.3，SFT 阶段为 42.3 与 33.1，差值由 9.2 缩小到 7.3，主要来自写前未核对。

**动机**：办公任务的终态判分有一个盲区：不看过程。一条轨迹可能未核对就写入，碰巧写对；也可能先改错再改回，终态干净，但线上这类中间状态已经触发了工作流。闭世界 verifier 只比较初末差分，同样看不到撤销过的写入。上线时用户关心的是全程安全，所以成功率需要一个考虑过程的版本，否则 RL 可能提升成功率的同时维持甚至增加违规行为。

**做法**：指标定义为：

$$
\text{TSRUC}=\frac1{|\mathcal U|}\sum_{u}G(u,S_{\text{final}})\cdot\big(1-V(u,\tau)\big)
$$

$G$ 为终态是否达成，$V$ 为轨迹内是否发生过违规，分母为全部任务。第一步，定义断言。`tool_call_precedence` 验证器声明顺序约束，形式为 `before(read_record(x), write_record(x))`。第二步，范围。11 类高风险写操作要求前置读取与权限核对，禁止动作全程不得出现。第三步，判定。遍历轨迹事件流，读取断言只认成功调用，禁止动作检查全部调用尝试。第四步，切片。违规按类型统计。

数值演算：480 道任务五遍共 2,400 条，RL 版本成功 1,310 条（1,310 / 2,400 = 54.6%），其中违规 175 条，约束下通过 1,135 条（47.3%）。差值 7.3 的构成：写前未核对 4.1、未授权字段写入后撤销 1.9、顺序错误 1.3，合计 7.3。SFT 版本差值 9.2，其中写前未核对 5.6。

**取值依据**：断言范围定为高风险写操作，共 11 类。全部写操作时，低风险的追加类调用被误报，误报率 8.1%；只保留禁止动作时，占比最大的写前未核对完全漏掉。读取窗口取同一轨迹内任意先行读取，要求紧邻读取时并行调用场景产生约 6% 的误判。

**收益**：报告中同时给出成功率与约束下成功率，$G$ 与 Pass@1 使用同一判定，RL 带来的提升在约束口径下为 14.2 个点，大于成功率的 12.3 个点。差值只统计成功且违规的轨迹，因此另报全部轨迹的违规率，由 16.8% 降到 13.5%。World of Workflows 专项上约束下成功率由 7.8 提升至 11.6，用于观察隐藏工作流场景。

**适用边界与代价**：断言需要按工具类别人工定义，新增工具要补约束。顺序断言能发现过程违规，不判断读取是否真正被使用。约束过严会把合理做法计为违规，因此每类断言上线前用 teacher 轨迹回测，误报率须低于 3%。指标比成功率低，向外沟通时要说明口径。

### 3.3 判分金标校准与 judge 解析修正

**🗣️ 话术——判分金标校准与 judge 解析修正**：rubric 判分的错误会直接写进 checkpoint 选择。方案为以 600 条人工双标样本校准 judge，统计混淆矩阵与人际一致性差距，评测 judge 取与被测模型不同家族的 GLM-5，只看产物不看轨迹，提示词迭代目标设为假阳性率优先。解析层兼容代码围栏与包装 JSON，解析失败率由 4.6% 降到 0.4%。校准样本量扫描过 200、600、1,200 三档，200 时 κ 的区间宽度 0.14，1,200 时只比 600 窄 0.03。judge 假阳性率由 7.4% 降到 1.8%，judge κ 由 0.87 升到 0.94，人际 κ 为 0.95。

**动机**：ALE 与部分自建任务含 rubric 条目，需要 LLM judge。judge 假阳性直接抬高分数，还会把差的 checkpoint 选出来。常见的评估只报一致率，掩盖了假阳性与假阴性的不对称。另一个问题是工程性的：judge 返回常带代码围栏或说明文字，脚本解析失败时一律记 0，模型明明通过却被判失败，这部分噪声与模型能力无关。

**做法**：第一步，抽样。按任务族与结果分层抽取 600 个 rubric 条目，两名标注者独立判定，分歧项由第三人裁决。第二步，度量。计算混淆矩阵、Cohen's κ、人际 κ 差距，并检查位置偏差与长度偏差。第三步，隔离。评测 judge 取 GLM-5，与被测的 Qwen 家族不同，输入只含任务、rubric 与产物，不给轨迹，避免被 agent 的陈述影响。第四步，提示迭代。针对假阳性条目修改判定说明，要求先引用产物中的证据再给结论。第五步，解析修正。采用平衡括号扫描抽取 JSON，容忍围栏与前后说明，确实无法解析时重试并单独计数。

数值演算：600 条中金标失败 271 条，初版 judge 判通过 20 条，假阳性率 20 / 271 = 7.4%；校准后判通过 5 条，假阳性率 1.8%。金标通过 329 条，假阴性由 19 条（5.8%）变为 14 条（4.3%）。总一致率由 93.5% 升到 96.8%。按混淆矩阵计算的未加权 κ 由 0.87 升到 0.94。

**取值依据**：校准样本定为 600 条。200 条时 κ 的 95% 区间宽度 0.14，无法区分提示版本；1,200 条时宽度只比 600 条窄 0.03，标注成本翻倍。提示迭代以假阳性率优先，因为假阳性抬高分数、影响选点，假阴性只让成绩偏保守。

**收益**：judge 假阳性率由 7.4% 降到 1.8%，κ 由 0.87 升到 0.94，距人际 κ 0.95 只差 0.01。解析失败率由 4.6% 降到 0.4%，修正后同一批产物 ALE Overall 复算上升 0.3，这部分不计为模型提升，全部版本按同一解析规则重判。

**适用边界与代价**：金标只代表抽样分布，任务族变化要补标。600 条双标约需 40 人时。跨家族 judge 成本更高，走 API 调用。只看产物会漏掉依赖过程的判断，这部分由调用顺序判分负责。judge 提示升级后必须走 replay 重判，保证历史版本可比。

### 3.4 配对差值门限与 task 级 bootstrap 检验

**🗣️ 话术——配对差值门限与 task 级 bootstrap 检验**：480 题单遍独立比较时，差值的 95% 区间半宽约 6.3pp，项目中多数单项增益都低于这一水平。方案为评测前按任务数、遍数与不一致率计算判定门限，固定五遍并按题配对，以 task 级 bootstrap 区间判定，低于门限的差异记持平。遍数扫描过 1、3、5、8 四档，门限依次为 2.0、1.2、0.9、0.7pp，8 遍成本增加 60% 只再降 0.2pp，定为五遍。门限降到 0.9pp 后，一项 0.7pp 的训练改动未被采纳。

**动机**：RL 项目的单项增益通常在 1 至 3 个点。480 题上一个二值指标的标准误约 2.3 个点，两版本独立比较时差值的 95% 区间半宽约 6.3 个点，小于这一水平的差异都不可靠。按单次分数排序很可能选中噪声，消融表也站不住。按题配对可以去掉题目难度带来的方差，多遍采样可以降低采样噪声，门限要在实验之前算好，防止事后挑选。

**做法**：第一步，计算门限。这里要区分两个量：判定门限是差值的 95% 区间半宽，用来判断观测差异是否可信；最小可检测差异是功效规划量，回答多大的真实差异能以 80% 概率检出。单遍未配对的半宽为：

$$
h=1.96\sqrt{2p(1-p)/n}=1.96\sqrt{0.5/480}\approx 6.3\text{pp}
$$

配对时方差由相邻版本的不一致率 $d$ 决定：$h=1.96\sqrt{d/(mn)}$，$m$ 为遍数。这个式子假设差异主要来自采样噪声，实际判定以 task 级 bootstrap 为准。第二步，固定协议。每题五遍，种子列表写入运行清单。第三步，统计。逐题计算五遍均值差，做 10,000 次 task 级 bootstrap 得到 95% 区间；exact McNemar 作为辅助，把每题五遍取多数决后得到二值配对结果。第四步，判定。均值差低于门限或区间跨零记为持平。第五步，多重比较。一轮消融超过 3 组对比时做 Holm 校正。

数值演算：$d=0.05$、$n=480$ 时，单遍配对 $h=1.96\sqrt{0.05/480}=2.0$pp；五遍配对 $h=1.96\sqrt{0.01/480}=0.9$pp。同一方差下 80% 功效的最小可检测差异为 $2.8\sqrt{0.01/480}=1.3$pp。

**取值依据**：遍数定为五遍。1 遍门限 2.0pp，3 遍 1.2pp，5 遍 0.9pp，8 遍 0.7pp，成本与遍数成正比。项目二最小的单项增益为 1.1，门限需要低于这一数值，所以至少五遍。bootstrap 重采样次数取 10,000，1,000 次时区间端点波动约 0.1pp。

**收益**：门限由 6.3pp 降到 0.9pp。项目二的六个增量全部高于门限，其中两项 1.1 低于 80% 功效的 1.3pp，各追加一次独立种子复测确认方向。一项工具返回按需压缩的改动差值 0.7pp，区间跨零，记为持平未采纳。项目一的 SFT 配方选择也按同一协议判定。

**适用边界与代价**：五遍使单版本评测时间增至约 6 小时，所以训练中的快速评测仍用 96 题子集，只作趋势参考。门限依赖不一致率估计，策略差异变大时要重算。配对要求两版本任务集完全一致。结论推广到新环境时还要考虑环境级聚类。持平不代表没有效果，只代表当前样本量下无法分辨。

### 3.5 单因素对照的回退归因与 harness 组件消融

**🗣️ 话术——单因素对照的回退归因与 harness 组件消融**：某 checkpoint 在 AutomationBench 上回落 2.4 而 held-out 上升。方案为按噪声、评测设置、harness、训测差异、分布偏移、真实回退的顺序逐一设单因素对照，每次只改一项，修正后下降消失才确认原因。排查定位为评测 harness 缺少日期上下文，时间条件类任务大量失败，补齐后回落消失。另把 harness 拆成写前校验、报错提示、观察预算、上下文压缩、skill 注入五个开关逐一移除，贡献依次为 3.1、2.2、1.4、0.4、0.2pp，后两项低于门限记持平。

**动机**：公开集回退是训练中最常遇到也最难解释的现象。常见做法是看到回退就调整训练，这样可能把评测配置问题当成能力问题，花掉一轮训练的成本。同时，agent 成绩来自模型与 harness 的共同作用，不拆开就不知道提升属于谁，换 harness 后可能大幅回落。两件事都要求把归因变成有固定顺序的单因素实验。

**做法**：第一步，排除噪声。按配对协议复测，确认差值超过门限。第二步，检查评测设置。比对运行清单。第三步，检查 harness。在另外两种 harness 上复测。第四步，检查训测差异。对比训练与评测的系统提示、工具列表、日期上下文与截断配置。第五步，检查分布。按任务族拆分，看下降是否集中。第六步，判定真实回退。前五步排除后，以行为指标比较两版本。每步只改一项，修复后下降消失才确认。

本次案例读数：

| 步骤 | 对照 | 结果 |
| --- | --- | --- |
| 噪声 | 五遍配对复测 | −2.4，区间不跨零 |
| 评测设置 | 清单比对 | 模型外字段相同 |
| harness | CLI harness 复测 | 同样下降 2.1 |
| 训测差异 | 补日期上下文 | 回落消失，+2.6 |

根因为评测 harness 的系统提示未注入当前日期。新版本 RL 后更倾向先判断时间条件，缺少日期时反复查询后放弃；老版本不判断，碰巧通过部分任务。

组件消融：以完整 harness 为参照，同一模型、同一批任务逐一关闭单个组件。

| 移除组件 | Pass@1 变化（pp） | 判定 |
| --- | --- | --- |
| 写前校验 | −3.1 | 有效 |
| 报错提示 | −2.2 | 有效 |
| 观察预算 | −1.4 | 有效 |
| 上下文压缩 | −0.4 | 持平 |
| skill 注入 | −0.2 | 持平 |

数值演算：五项合计 −7.3，而同时移除五项后实测 −6.1，差 1.2 来自组件间重叠，因此单项贡献不能直接相加。

**取值依据**：排查顺序按成本从低到高，噪声与设置检查不需要额外 rollout，真实回退结论放在最后。单因素对照每次只改一项，一次改两项时无法判断哪项生效。组件数定为五个，再细分时单项差值低于门限，失去分辨力。

**收益**：一次 2.4 的回落在一天内定位，避免了一轮约 90 小时的重训。组件消融给出 harness 贡献，写前校验贡献 3.1pp，转而作为工具协议固定下来；上下文压缩与 skill 注入因增益持平，从默认配置中移除以降低复杂度。

**适用边界与代价**：单因素对照要求配置可以独立切换，耦合的组件无法分离。真实回退的确认需要行为证据，分数本身不足以说明原因。组件消融按固定模型执行，未进入 RL 验证，组件与训练的交互不在结论范围内。每次完整排查约占用 24 张卡半天。
