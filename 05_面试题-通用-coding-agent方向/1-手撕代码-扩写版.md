## 模型手撕 Top 10

### 1. Multi-Head Attention

出处：[Attention Is All You Need](https://arxiv.org/abs/1706.03762)；GQA 变体 [GQA: Training Generalized Multi-Query Transformer](https://arxiv.org/abs/2305.13245)。

核心思想：把 d_model 拆成 h 个头，每个头在自己的子空间做 scaled dot-product attention，不同头学不同的模式，最后拼回投影。

**先看输入、输出和步骤：** `x` 是一批长度为 `T` 的序列，形状为 `(B,T,d_model)`；`B` 是样本数，`T` 是 token 数，`d_model` 是每个 token 的向量宽度。返回值仍是 `(B,T,d_model)`。`mask` 若提供，必须能广播到注意力分数 `(B,h,T,T)`；这里约定 1 表示允许关注、0 表示屏蔽。代码依次做线性投影、拆分 head、算每个 query 对每个 key 的分数、把分数变成概率、按概率混合 value，最后合并各 head。

实现代码：

```python
import torch, torch.nn as nn, torch.nn.functional as F, math

class MultiHeadAttention(nn.Module):
    def __init__(self, d_model=512, num_heads=8, dropout=0.1):
        super().__init__()
        assert d_model % num_heads == 0
        self.d_model, self.num_heads = d_model, num_heads
        self.head_dim = d_model // num_heads
        self.Wq = nn.Linear(d_model, d_model)
        self.Wk = nn.Linear(d_model, d_model)
        self.Wv = nn.Linear(d_model, d_model)
        self.Wo = nn.Linear(d_model, d_model)
        self.dropout = nn.Dropout(dropout)

    def forward(self, x, mask=None):
        B, T, _ = x.shape
        q = self.Wq(x).view(B, T, self.num_heads, self.head_dim).transpose(1, 2)
        k = self.Wk(x).view(B, T, self.num_heads, self.head_dim).transpose(1, 2)
        v = self.Wv(x).view(B, T, self.num_heads, self.head_dim).transpose(1, 2)
        att = (q @ k.transpose(-2, -1)) / math.sqrt(self.head_dim)
        if mask is not None:
            att = att.masked_fill(mask == 0, float('-inf'))
        att = self.dropout(F.softmax(att, dim=-1))
        out = (att @ v).transpose(1, 2).reshape(B, T, self.d_model)
        return self.Wo(out)

# causal mask: torch.tril(torch.ones(T, T, dtype=torch.bool)).view(1,1,T,T)
```

**沿张量走一遍：** 若 `B=1,T=3,d_model=4,h=2`，每个头宽 `d_k=2`。Q/K/V 各自先是 `(1,3,4)`，拆头并转置后是 `(1,2,3,2)`；`q @ k.transpose(-2,-1)` 得到 `(1,2,3,3)`，最后两个维度分别表示“哪个 query 位置”和“要看哪个 key 位置”。分数按 `$`qk^\top/\sqrt{d_k}`$` 缩放，`mask==0` 的分数改成负无穷，softmax 后这些位置概率为 0。若用下三角 causal mask，第 3 个 token 可看前两个 token 和自己，不能看未来位置。概率 `(1,2,3,3)` 乘 V `(1,2,3,2)` 得 `(1,2,3,2)`；转回 `(1,3,2,2)` 并合并两个 head，才恢复 `(1,3,4)`。

**边界与复杂度：** 主计算约为 $`\mathcal{O}(B\cdot T^2\cdot d_{\mathrm{model}})`$，分数矩阵占 $`\mathcal{O}(B\cdot h\cdot T^2)`$ 空间。`d_model` 不能被 `num_heads` 整除时，构造器的断言会失败；mask 若把某一行的所有 key 都屏蔽，softmax 会遇到全负无穷并产生 NaN；mask 形状若不能广播也会报错。做 padding mask 时还要确保每个 query 至少有一个可见位置，不能误把未来 token 或 padding 当作可见 key。

复杂度：时间 O(T²·d)（注意力的 T² 主导），显存 O(T²)（att 矩阵）。[FlashAttention](https://arxiv.org/abs/2205.14135) 不落 T² 矩阵，tiling 在 SRAM 内完成 softmax，显存降到 O(T)。

**问题（追问）：张量维度怎么变的？**

回答：投影后是 (B,T,d)，view 成 (B,T,h,d_k) 把头维拆出来，transpose(1,2) 得 (B,h,T,d_k) 让头维进 batch 旁边、注意力在 (T,T) 上算；并头是逆操作 transpose(1,2) 后 reshape 回 (B,T,d)。维度变换链为 (B,T,d) → (B,h,T,d_k) → 注意力计算 → (B,h,T,d_k) → 并头回 (B,T,d)；投影矩阵形状不变（d×d），仅逻辑重排。

**问题（追问）：为什么除 √d_k？**

回答：q、k 各分量独立同分布时点积方差等于 d_k 乘单分量方差，d_k=64/128 时点积量级大，softmax 进入饱和区（梯度趋近零）；除 √d_k 把方差归一到 1。如果追问"为什么不是 d_k"——标准差是 √d_k，除以它正好归一；再追问"softmax 饱和为什么不好"——饱和区梯度趋零，注意力权重学不动，训练早期就停滞。

**问题（追问）：改成 GQA 怎么改？**

回答：Wk/Wv 的输出维度从 d_model 改为 num_kv_groups·d_k，拆组后用 repeat_interleave(h // num_kv_groups, dim=1) 扩到 h 组参与计算；Wq 与 Wo 完全不变。进一步问 MQA 就是 num_kv_groups=1 的特例。改写的本质是"K/V 的头数变少、计算时广播回 h 组"，推理时的 KV cache 只按 num_kv_groups 存，这就是省显存的来源。

**问题（追问）：不用 nn.Linear 手写？**

回答：q = x @ Wq + bq，Wq 是 (d,d) 参数、bq 是 (d,) 参数；初始化用 xavier_uniform 或 kaiming，偏置置零。nn.Linear 的本质是矩阵乘加偏置，手写时直接展开即可。

### 2. GRPO Loss

出处：[DeepSeekMath](https://arxiv.org/abs/2402.03300) §4.1.4；改进对照 [DAPO](https://arxiv.org/abs/2503.14476)、[GSPO](https://arxiv.org/abs/2507.18071)。

核心思想：同一 prompt 采样 G 条回答，组内 reward 标准化作优势（替代 critic），token 级重要性比率加 clip 与 KL 惩罚。

**先看输入、输出和步骤：** `old_logps`、`new_logps`、`ref_logps` 和 `completion_mask` 都是 `(G,L)`：G 条回答，每条补全最多 L 个 token；logprob 是对应 token 的对数概率，mask 中 1 表示这个 token 属于要计入 loss 的回答部分。`rewards` 是 `(G,)`，每条回答一个分数。函数返回一个标量 loss。顺序是先在同一组回答之间标准化 reward，再把每条回答的优势广播到它的 token 上，用新旧策略概率比构造策略梯度项，最后加参考策略约束并按有效 token 数求平均。

实现代码：

```python
import torch

def grpo_loss(old_logps, new_logps, rewards, ref_logps, completion_mask,
              beta=0.04, clip=0.2):
    # old_logps/new_logps/ref_logps: (G, L)；rewards: (G,)；completion_mask: (G, L)
    adv = (rewards - rewards.mean()) / (rewards.std(unbiased=False) + 1e-4)  # 总体 std（除 G），1e-4 仅为数值保护
    adv = adv.unsqueeze(1)
    ratio = torch.exp(new_logps - old_logps)
    pg1 = ratio * adv
    pg2 = torch.clamp(ratio, 1 - clip, 1 + clip) * adv
    pg_loss = -torch.min(pg1, pg2)
    kl = torch.exp(ref_logps - new_logps) - (ref_logps - new_logps) - 1
    return ((pg_loss + beta * kl) * completion_mask).sum() / completion_mask.sum()  # DAPO 式 token-level 归一；DeepSeekMath 原文为 response-level（先按 1/|o| 逐条平均再对 G 平均）
```

**把 loss 拆开看：** 对每个 prompt 的 G 个 reward，代码减去组均值、除以总体标准差（`unbiased=False`，分母对应 G 而不是 G−1），得到 `(G,)` 优势，再 `unsqueeze(1)` 成 `(G,1)`，这样同一回答的优势会广播到该回答的 L 个 token。重要性比率是 `$`r_t=\exp(\ell_t^{\mathrm{new}}-\ell_t^{\mathrm{old}})`$`，等于新策略给这个已采样 token 的概率除以采样时旧策略的概率；ratio 大于 1 表示新策略更偏好它，小于 1 表示更不偏好。两个候选策略目标分别用原 ratio 和裁剪后的 ratio，`min` 取更保守的目标，前面的负号把“最大化奖励”改成优化器通常执行的“最小化 loss”。KL（衡量两个概率分布差异的散度）项按 token 计算，mask 再把 padding / 非回答位置去掉。

**小例子与边界：** 假设同一 prompt 得到两条回答，reward 为 `[1,0]`，标准差非零时优势分别是一正一负；第一条的所有有效 token 都收到鼓励方向，第二条都收到抑制方向，但各 token 的力度仍由自己的 ratio 和 clip 决定。若 G=1，组内优势必为 0；若一组 reward 全相同，也没有可区分的组内信号。`completion_mask` 全为 0 时分母为 0，会得到 NaN；极端的 `new_logps-old_logps` 也可能使指数溢出。计算量和缓存量均随有效 token 数 `G·L` 线性增长。

复杂度：显存 O(G·L)（G 条 rollout 的 logprob 缓存）；组数 G 翻倍则 rollout 算力翻倍。两种归一口径的差异见 SFT 一题的 token mean 讨论。

**问题（追问）：全对/全错的组怎么办？**

回答：std 接近零，advantage 全为零、没有梯度——代码里的 +1e-4 只是数值保护，训练上靠 DAPO 的 Dynamic Sampling 过滤这类组并补采。如果自己项目里有软信号（验证器分、部分通过的稠密化），也可以让"部分正确的失败"之间拉开差距、恢复组内方差，这是与过滤正交的另一条路线：过滤靠换题恢复梯度信号，软信号靠拉开差距恢复组内方差；有可打分验证器的任务优先软信号，只有对错奖励的任务用动态采样过滤。

**问题（追问）：KL 为什么不放进 reward？**

回答：放进 reward 会被组内 mean/std 标准化污染——KL 的绝对大小信息被抹掉，还改变了组内排序（一条本该更好的轨迹可能因 KL 项被反超）。所以 DeepSeekMath 把 KL 用 k3 估计逐 token 直接加进 loss，与 advantage 完全解耦。k3 无偏的直觉：对指数项取期望是 1、对数项的期望就是负 KL，减 1 补齐。

**问题（追问）：和 PPO 的 loss 差在哪？**

回答：ratio 加 clip 的 surrogate 部分完全同构；差别是优势来源（GAE 换成组内标准化）、没有 value loss。进一步问 GSPO：把 token 级 ratio 换成序列级几何平均再整体 clip，代码改动是 ratio 先按序列聚合、clip 后再广播回 token 维——长轨迹训练更稳，因为个别 token 的极端 ratio 不再各自劫持梯度。

### 3. SFT Loss（含 mask 与 shift）

核心思想：交叉熵只在 completion token 上计算——label 右移一位对齐 next-token 预测，prompt 与 padding 位置置 -100 由 ignore_index 跳过。

**先看输入、输出和步骤：** `input_ids` 形状是 `(B,T)`，每个位置是 token ID；`logits` 是 `(B,T,V)`，V 为词表大小，表示每个位置对“下一个 token”的未归一化打分；`prompt_mask` 是 `(B,T)`，1 表示该位置原本属于 prompt。函数返回一个标量交叉熵。核心对齐原则是 `$`\mathrm{logits}_t\text{ 预测 }y_{t+1}`$`，所以目标 labels 要左移一格，logits 则去掉最后一格；先在原始 token 坐标中 mask prompt，再 shift，才能保留第一个回答 token 的监督。

实现代码：

```python
import torch
import torch.nn.functional as F

def sft_loss(logits, input_ids, prompt_mask):
    labels = input_ids.clone()
    labels[prompt_mask.bool()] = -100
    labels[:, :-1] = labels[:, 1:].clone()  # 先 mask 再 shift，保住第一个 completion token 的监督
    labels[:, -1] = -100
    logits = logits[:, :-1]
    return F.cross_entropy(
        logits.reshape(-1, logits.size(-1)), labels.reshape(-1),
        ignore_index=-100)
```

**小例子：** 假设一条序列是 `[BOS, P, A, B]`，前两个位置是 prompt，则先把 prompt 对应的 labels 变成 `[-100,-100,A,B]`。右移后 labels 是 `[-100,A,B,-100]`，同时只保留原 logits 的前三个位置。这样 logits 位置 1（此时模型已经读到 `P`）学着预测回答首 token `A`，位置 2 学着预测 `B`；位置 0 对应 prompt 的目标 `P`，标签为 `-100`，会被忽略。原 logits 的最后一个位置也被丢弃。`-100` 是交叉熵的“忽略标签”哨兵值，不是词表里的 token。

**padding 与边界（原代码的适用前提）：** 这段函数没有单独接收 `attention_mask`，因此 padding 位置必须已经被合并进传入的 mask（或数据根本没有 padding），否则 pad token 可能被当成训练目标；真实批处理通常要明确对 padding labels 也置 `-100`。序列长度小于 2 或整批目标都被 mask 时，没有有效预测项，mean loss 可能是 NaN。mask 形状必须和 `input_ids` 一致；误把回答首 token 也 mask 会让模型学不到从 prompt 接出回答的第一步。

**问题（追问）：shift 是先做还是后做？**

回答：先 mask 再 shift。mask 必须在原始坐标系下完成：prompt 末位对应的目标恰好是第一个 completion token，若先 shift 再用未同步 shift 的 prompt_mask 去 mask，这个位置会被误置 -100，模型学不到"从 prompt 末尾接出回答的第一个词"。loss 曲线无异常但首 token 分布失真，属于典型的静默 bug。

**问题（追问）：多轮对话/工具调用场景 mask 怎么改？**

回答：判据始终是"这个 token 是不是当前策略生成的"——工具返回、环境 observe、系统注入的 token 全部置 -100；模型自己写的思考与调用参数进损失。多轮中历史轮次作为上下文时，只训当前轮的目标段，避免同一段被反复计入损失造成过度加权。追问"mask 写错会怎样"：少 mask 一段，模型学会复述工具输出交差（reward hacking 的一种）；多 mask 一段，丢真实决策信号——所以 mask 逻辑要配单元测试，构造样例逐 token 断言。

**问题（追问）：loss 分母是 token 数还是样本数？**

回答：token mean——所有有效 token 的损失取平均，是标准做法。样本 mean（每条先各自平均再对样本平均）会让长样本的每个 token 权重被摊薄（1/L_i，样本越长单 token 权重越小），短样本主导梯度。Dr.GRPO 指出的长度偏置正源于按回答长度归一：错误回答越长、每 token 分摊的负优势惩罚越小，模型倾向把错答案写长；DAPO 改按 batch 总 token 数归一消掉这个系统性偏置，长回答不再被降权。

### 4. RoPE 旋转位置编码

出处：[RoFormer](https://arxiv.org/abs/2104.09864)；外推 [YaRN](https://arxiv.org/abs/2309.00071)。

核心思想：q、k 按维度两两配对做二维旋转，内积只依赖相对位置差；高频对管局部、低频对管长程。

**先看输入、输出和步骤：** `rope_cache(T, head_dim)` 为 T 个位置预先生成 cos/sin 表，形状各为 `(T, head_dim/2)`；`apply_rope(x, ...)` 的 `x` 可带 batch/head 等前缀维，末两维必须是 `(T, head_dim)`，输出形状不变。代码采用相邻维配对：第 0、1 维一对，第 2、3 维一对……每对看作二维平面向量，按该位置对应的角度旋转。通常对 attention 的 Q 和 K 应用 RoPE，使它们的点积带有位置信息；不是把位置向量直接加到 token embedding 上。

实现代码：

```python
import torch

def rope_cache(T, head_dim, base=10000.0, device='cpu'):
    inv_freq = 1.0 / (base ** (torch.arange(0, head_dim, 2, device=device).float() / head_dim))
    t = torch.arange(T, device=device).float()
    freqs = torch.outer(t, inv_freq)
    return torch.cos(freqs), torch.sin(freqs)

def apply_rope(x, cos, sin):
    T = x.size(-2)
    cos, sin = cos[:T].to(x.device), sin[:T].to(x.device)
    x1, x2 = x[..., 0::2], x[..., 1::2]
    out = torch.empty_like(x)
    out[..., 0::2] = x1 * cos - x2 * sin
    out[..., 1::2] = x1 * sin + x2 * cos
    return out
```

**把一个维度对手算出来：** 在某位置，若某一对输入是 `(x_even,x_odd)=(1,0)`，该对角度为 90°，旋转结果就是 `(0,1)`。实际角度是 `$`\theta_{t,j}=t\,\omega_j`$`，由位置 `t` 和该维度对的 `inv_freq` 决定；`rope_cache` 用 `outer(t, inv_freq)` 一次生成所有位置和维度对的角度。`x[...,0::2]` 取每对的偶数维，`x[...,1::2]` 取奇数维；对应的二维旋转是 `$`(x_{2j}\cos\theta-x_{2j+1}\sin\theta,\;x_{2j}\sin\theta+x_{2j+1}\cos\theta)`$`，省略号表示前面的 batch/head 维保持不变。位置差性质来自旋转矩阵的复合关系，因此 Q 在位置 m、K 在位置 n 的点积只依赖 `$`n-m`$`。

**边界与形状：** head_dim 必须是正偶数；奇数维会让偶数/奇数切片长度不同，无法按当前公式相乘。cache 的位置数必须覆盖输入序列长度，否则 cos/sin 与 x 的时间维无法对齐；批次或 head 维则依赖 PyTorch 广播规则。小例子检查时可先只用一个二维 pair、两个位置，确认位置 0 角度为 0（输入不变），再检查位置 1 是否按对应角度旋转。生成与应用的主要开销均与 `$`T\,d_{\mathrm{head}}`$` 成正比，cache 也需保存同阶的 cos/sin。

**问题（追问）：为什么是相对位置？**

回答：旋转矩阵正交，$`R_m^T R_n = R_{n-m}`$，所以 $`(R_m q)\cdot(R_n k) = q^T R_{n-m} k`$ 只依赖位置差——位置 m 处的 q 与位置 n 处的 k 打分，等于把 q 旋转 (n−m) 后再打分，与绝对位置无关。这带来两个性质：外推时相对距离仍然有定义（绝对编码没有）；训练时不同绝对位置的同距离样本共享统计。

**问题（追问）：训练 8K 推 128K 怎么办？**

回答：NTK-aware 缩放 base——高频对转角大、管局部分辨，几乎不动；低频对转角小、管长程，拉伸它去覆盖更远的位置，等效频率空间的非线性插值，免训练可外推两到四倍。YaRN 在此之上加注意力温度补偿：长上下文下 key 数量变多、softmax 熵升高、分布变平，q、k 同乘 mscale=0.1·ln(s)+1（等效注意力温度 1/t，√(1/t)=0.1 ln s + 1，s=8 时约 1.21）把锐度拉回训练水平，再配少量继续训练可到 128K 以上。工业标准仍是 mid-train 分段扩窗继续训练，外推只做应急。

**问题（追问）：RoPE 与 KV cache / MLA 的关系？**

回答：位置相关的旋转无法进 MLA 的低秩压缩：RoPE 必须按位置作用在完整 K 上，而 MLA 只缓存逐 token 的低秩潜向量 c_KV（跨 head 共享）、用时再上投影，位置旋转无法预先折进低秩投影。所以 MLA 把 RoPE 解耦成一条独立小维度的逐位置共享键，与 c_KV 一起缓存。核心结论是"低秩压缩与位置编码不可兼容"。

### 5. 带 KV Cache 与 causal mask 的自回归 Attention

出处：[Efficient Memory Management for LLM Serving with PagedAttention](https://arxiv.org/abs/2309.06180)。

核心思想：decode 阶段每步只有 1 个新 q，K/V 从缓存读，注意力只在 (1, T_total) 上算，把每步 O(T²) 降为 O(T)。

**先看输入、输出和步骤：** `x_new` 是当前刚生成的单个 token 表示，形状应为 `(B,1,d_model)`；过去缓存 `cache_k/cache_v` 通常是 `(B,h,T_past,d_k)`。四个投影层把新 token 变成 Q/K/V，K/V 追加到缓存；Q 只和包含当前 token 在内的全部历史 K 做点积，得到 `(B,h,1,T_past+1)` 分数，再按这些权重混合 V。输出经合头和 `Wo` 后为 `(B,1,d_model)`；另返回更新后的 K/V 缓存供下一步继续用。

实现代码：

```python
import torch, math

def decode_step(x_new, Wq, Wk, Wv, Wo, cache_k, cache_v, num_heads=8):
    q = Wq(x_new).unflatten(-1, (num_heads, -1)).transpose(1, 2)
    k = Wk(x_new).unflatten(-1, (num_heads, -1)).transpose(1, 2)
    v = Wv(x_new).unflatten(-1, (num_heads, -1)).transpose(1, 2)
    cache_k = torch.cat([cache_k, k], dim=2)
    cache_v = torch.cat([cache_v, v], dim=2)
    att = (q @ cache_k.transpose(-2, -1)) / math.sqrt(q.size(-1))
    out = (att.softmax(-1) @ cache_v).transpose(1, 2).flatten(-2)
    return Wo(out), cache_k, cache_v
```

**小例子与 causal mask：** 若此前已有 2 个 token 的缓存，这一步把第 3 个 token 的 K/V 追加后，cache 长度变成 3；每个 head 的新 Q 只产生 3 个分数，softmax 后对这 3 个历史位置加权。这里不需要额外 triangular causal mask，因为 query 只有当前 token，而 cache 只含过去和当前，不含未来；若把接口改成一次输入多个新 token，就必须处理这些新 token 之间的因果关系，不能直接套用这段逻辑。

**边界与复杂度：** 每个新 token 的注意力工作量随已有上下文长度线性增长，约 $`\mathcal{O}(B\cdot T_{\mathrm{total}}\cdot d_{\mathrm{model}})`$；K/V cache 总空间约 $`\mathcal{O}(B\cdot h\cdot T_{\mathrm{total}}\cdot d_k)`$，且 K、V 各存一份。输入长度必须为 1，cache 的 batch/head/每头维度要与投影一致；空 cache 也要有正确的零长度形状。此简化实现用 `torch.cat` 每步复制旧 cache，单步拷贝也随上下文增长，整段 decode 的复制成本会累积；生产实现通常预分配 cache 并原位写入。

**问题（追问）：KV cache 显存多大？**

回答：K、V 两侧乘层数乘 batch 乘序列长乘头数乘 d_k 再乘 2 字节（bf16）。推导：每 token 每层 cache = 2（K/V）× 32 头 × 128 维 × 2 字节 = 16 KB，乘 32 层得每 token 512 KB，乘 32K 序列 ≈ 16 GB（MHA）。GQA 除以 KV 组数（8 组时约 4 GB）、MLA 只存低秩 c_KV 加解耦 RoPE 键——这就是两者存在的理由。

**问题（追问）：decode 步为什么不用显式 causal mask？**

回答：decode 时新 token 的 q 只对全部历史 K/V 打分，天然满足因果约束（历史都已生成完毕），无需构造上三角掩码；mask 只在 prefill（一次输入整段 prompt）时需要。

**问题（追问）：PagedAttention 解决什么？**

回答：静态连续 cache 的两个问题——按最大长度预留导致的内部碎片（预留 32K 实际用 8K），以及多请求间的外部碎片；vLLM 把 cache 切成固定大小的页、按需分配、逻辑连续物理离散，显存利用率大幅提升，还支持 prefix 共享（系统提示词复用）。

### 6. RMSNorm 与 LayerNorm

出处：[Root Mean Square Layer Normalization](https://arxiv.org/abs/1910.07467)。

核心思想：LayerNorm 是去均值加方差归一加仿射；RMSNorm 去掉均值中心化，只用均方根缩放。

**先看输入、输出和步骤：** 两个模块都接收形状 `(...,d)` 的浮点张量，对最后一个特征维做归一化，并返回相同形状。`weight` 是长度 d 的可训练缩放参数；LayerNorm 还额外有偏置 `bias`。RMSNorm 先算最后一维的均方根，再用其倒数缩放原值；LayerNorm 先减均值，再除以标准差，最后做可训练的缩放和平移。

实现代码：

```python
import torch, torch.nn as nn

class RMSNorm(nn.Module):
    def __init__(self, d, eps=1e-6):
        super().__init__()
        self.weight = nn.Parameter(torch.ones(d))
        self.eps = eps
    def forward(self, x):
        rms = x.pow(2).mean(-1, keepdim=True).add(self.eps).rsqrt()
        return x * rms * self.weight

class LayerNorm(nn.Module):
    def __init__(self, d, eps=1e-5):
        super().__init__()
        self.weight = nn.Parameter(torch.ones(d))
        self.bias = nn.Parameter(torch.zeros(d))
        self.eps = eps
    def forward(self, x):
        mu = x.mean(-1, keepdim=True)
        var = x.var(-1, keepdim=True, unbiased=False)
        return (x - mu) / torch.sqrt(var + self.eps) * self.weight + self.bias
```

**用两个数对比：** 对 `x=[3,4]`，RMSNorm 的均方根是 `$`\sqrt{(9+16)/2}`$`，所以它主要把整体尺度调到约 1，但不会把均值移到 0；LayerNorm 的均值是 3.5、方差是 0.25，归一化后两个数分别在均值两侧。实际计算在每个 token 的最后一维独立进行，不会把不同 token 或不同样本混在一起。`keepdim=True` 保留长度为 1 的统计维，方便与原张量广播相乘或相减。

**边界与复杂度：** 每个元素只参与常数次运算，时间约 $`\mathcal{O}(\operatorname{numel}(x))`$，额外统计量按每行计算。最后一维宽度必须与 `weight`（及 LayerNorm 的 `bias`）一致；`eps` 用来避免零方差时除零，不能随意设为负值。输入应是浮点数；全零向量在 eps 保护下 RMSNorm 输出仍为零，而 LayerNorm 输出由 bias 决定。RMSNorm 的代码没有 bias，这是它与这里实现的 LayerNorm 的一个实际差别。

**问题（追问）：RMSNorm 为什么敢去掉均值中心化？**

回答：消融显示中心化对效果无显著贡献——归一化的主要作用是控制激活尺度而非位置，去掉均值归约省一次计算与访存，深层网络更稳。追问 eps 的作用：防除零兼数值稳定入口；工程默认 RMSNorm 1e-6（LLaMA-1 实践值，LLaMA-2 起 1e-5）、LayerNorm 1e-5（PyTorch 默认，非 LayerNorm 论文规定）；实现里用 rsqrt 一次完成倒数开方，效率更高。

**问题（追问）：Pre-norm vs Post-norm？**

回答：现代 LLM 全是 Pre-norm——归一化放在残差分支内部，主干恒等直通，深层梯度不衰减，训练基本不需要精细 warmup；Post-norm 归一化在残差相加之后，主路径每层被缩放，深层梯度衰减需要 warmup 补偿。这也是"为什么现代模型能训到上百层"的答案核心。

### 7. PPO Advantage + Clip Loss

出处：[Proximal Policy Optimization](https://arxiv.org/abs/1707.06347)。

核心思想：GAE 用 value 网络与 TD 残差指数加权折衷偏差与方差；ratio clip 限制单步更新幅度。

**先看输入、输出和步骤：** 这里把单条时间轨迹写成一维长度 `T`：`rewards`、`dones`、`values`、`old_values`、`old_logps`、`new_logps` 都按时间步对齐，函数返回策略 loss 加 value loss 的标量。`done=1` 表示该步后 episode 终止，`value` 是 value 网络对状态价值的估计。GAE（广义优势估计）把当前 TD 残差与后续残差折扣累积，以控制优势估计的偏差和方差。代码从最后一步向前回溯，先算 TD 残差 `delta`，再累计 GAE advantage；然后用 `returns=adv+values` 作为 value 目标，最后分别算策略 clip loss 和 value clip loss。

实现代码：

```python
import torch

def ppo_loss(values, old_values, old_logps, new_logps,
             rewards, dones, gamma=0.99, lam=0.95, clip=0.2, eps_v=0.1):
    T = rewards.shape[0]
    adv = torch.zeros_like(rewards)
    lastgae = 0.
    with torch.no_grad():
        for t in reversed(range(T)):
            next_v = values[t + 1] if t + 1 < T else values.new_zeros(())  # 假设轨迹在 T 终止；截断场景需缓存 V(s_T) 自举
            delta = rewards[t] + gamma * next_v * (1 - dones[t]) - values[t]
            lastgae = delta + gamma * lam * (1 - dones[t]) * lastgae
            adv[t] = lastgae
    returns = adv + values
    ratio = torch.exp(new_logps - old_logps)
    pg = -torch.min(ratio * adv,
                    torch.clamp(ratio, 1 - clip, 1 + clip) * adv).mean()
    v_clip = old_values + torch.clamp(values - old_values, -eps_v, eps_v)
    vf = 0.5 * torch.max((values - returns) ** 2, (v_clip - returns) ** 2).mean()  # 内层 0.5 是 MSE 惯例
    return pg + vf  # 外层系数即 value loss 权重
```

**把反向循环走一遍：** 取 `rewards=[1,0]`、`values=[0.5,0.2]`、`dones=[0,1]`，并令 `gamma=0.9, lam=0.5`。最后一步已终止，所以它的 `next_v=0`，TD 残差为 `$`\delta_1=0-0.2=-0.2`$`，这就是最后一步的 GAE。再回到第 0 步，TD 残差为 `$`\delta_0=1+0.9\times0.2-0.5=0.68`$`，并把后续 GAE 按 `$`\gamma\lambda=0.45`$` 折回，得到 `$`A_0=0.68+0.45\times(-0.2)=0.59`$`。因此 advantage 是 `[0.59,-0.2]`，return 是 advantage 加当前 value。`dones[t]` 同时屏蔽跨 episode 的 bootstrap 和跨边界的 GAE 累积。

**边界与复杂度：** 回溯一次，时间 $`\mathcal{O}(T)`$、额外 advantage 空间 $`\mathcal{O}(T)`$。代码假定轨迹在 T 结束，最后 `next_v` 强制为 0；若只是采样片段结束而 episode 尚未结束，应使用片段末状态的 value 自举，否则 advantage 会有偏。当前接口只写单条一维轨迹；传批次需要明确时间维并逐条回溯。ratio 指数若遇到极端 logprob 差可能溢出；`rewards/dones/values` 长度不一致会造成错误或错误对齐。

**问题（追问）：GAE 的 λ 调大调小意味着什么？**

回答：λ 趋向 0 退化为单步 TD——低方差、高偏（优势估计质量完全依赖 value 网络的准确性）；λ 趋向 1 退化为蒙特卡洛——无偏但方差大（整条轨迹的随机性都进梯度）；中间值在偏差与方差之间滑动。追问"GRPO 里这段哪些没了"：values、GAE、value clip loss 全删，advantage 换组内标准化，函数少一半。

### 8. Forward KL 与 Reverse KL（梯度推导）

出处：[MiniLLM](https://arxiv.org/abs/2306.08543)。

核心思想：forward KL（teacher 采样）mean-seeking，覆盖全但把质量赋到学生够不到的区域；reverse KL（student 采样）mode-seeking，适合弱学生但梯度方差大。

**先把符号说清楚：** `p` 表示固定的 teacher 分布，`q_θ` 表示由参数 θ 控制的 student 分布；KL 是一个标量，梯度则与 θ 的参数形状相同。Forward KL 把 p 当作采样分布，比较 teacher 质量落在学生分布上的程度；reverse KL 的采样来自 student，衡量学生把概率放到 teacher 不认可区域时的代价。两者不是把公式简单换个顺序，而是期望所用的分布和梯度形式都不同。

推导要点（白板版）：

```
forward:  ∇θ KL(p‖qθ) = − Σ p·∇θ log qθ ≈ − E_{y~p}[∇θ log qθ(y)]
          → 直接用 teacher 样本加权学生的 logprob 梯度（SFT 即其特例）

reverse:  ∇θ KL(qθ‖p) = ∇θ Σ qθ·(log qθ − log p)
          ≈ E_{y~qθ}[(log qθ(y) − log p(y) + 1)·∇θ log qθ(y)]  （常数 ±1 在期望下等价：E[∇log q]=0，取 −1 是控制变量写法）
          → 只能用学生自己的样本，reward = −log p 作 REINFORCE → MiniLLM 加梯度修正降方差
```

**用两个类别的小分布建立直觉：** 令 teacher `$`p=(0.8,0.2)`$`，student `$`q=(0.5,0.5)`$`。Forward KL 为 `$`D_{\mathrm{KL}}(p\|q)=0.8\ln(0.8/0.5)+0.2\ln(0.2/0.5)`$`，约为 0.193；reverse KL 为 `$`D_{\mathrm{KL}}(q\|p)=0.5\ln(0.5/0.8)+0.5\ln(0.5/0.2)`$`，约为 0.223。此例里二者数值接近，但一般不会相等。求 forward 梯度时可以从 teacher 抽类别并计算 student 的 logprob 梯度；求 reverse 梯度时从 student 抽类别，并让 `$`\log q-\log p`$` 充当 REINFORCE 权重。式子里的 `+1` 来自对 `q` 求导；由于 `$`\mathbb{E}_{q}[\nabla \log q]=0`$`，在期望中可消去，或作为控制变量降低方差。

**边界与复杂度：** 若能枚举完整的 K 类分布，计算 KL 及其梯度约 $`\mathcal{O}(K)`$；大词表模型通常用采样估计，但梯度会有采样方差。若 teacher 在某个 teacher 有概率的类别上给 student 概率 0，forward KL 会发散；若 teacher 概率为 0 而 student 给出正概率，reverse KL 会发散。实际代码会用有限 logits / logprob 避免直接对 0 取 log，但仍要注意数值精度。不要把这里的分布采样来源混淆：forward 从 p 取样，reverse 从 q 取样。

**问题（追问）：蒸馏选哪个？为什么？**

回答：学生显著弱于 teacher（7B 学 72B）时选 reverse——forward 会强迫小容量学生铺开覆盖 teacher 的全部支撑，在覆盖不到的区域产生幻觉质量；reverse 的 mode-seeking 让学生先抓住强模式。MiniLLM 是这个结论的代表工作，用 policy gradient 优化 reverse KL 并做方差修正。再引申到 OPD：学生在自己分布上拿 teacher 的逐 token 稠密监督，兼得 on-policy 分布与 dense 信号——三种目标（forward/reverse/OPD）各自的适用条件一并给出。

### 9. 梯度下降求算术平方根

核心思想：求 √a 等价最小化 L(w) = (w² − a)²，用解析梯度 4w(w²−a) 迭代。

**先看输入、输出和步骤：** 输入是非负实数 `a`，可选初值 `w0`、学习率、误差阈值和最大迭代次数；输出是一个近似平方根的实数。变量 `w` 是当前猜测。每次先按损失函数的负梯度更新 w，再检查 `w²` 与 a 的差是否足够小；`eps²` 是对平方值残差的停止阈值。初值默认取 1 或 a 的量级，是为了避免从过远的点开始，但这并不保证所有 a、lr 组合都会收敛。

实现代码：

```python
def sqrt_by_gd(a, w0=None, lr=0.001, eps=1e-3, max_iter=10000):
    if a < 0:
        raise ValueError("a must be non-negative")
    w = w0 if w0 is not None else (1.0 if a < 1 else float(a))
    for _ in range(max_iter):
        w -= lr * 4 * w * (w * w - a)
        if abs(w * w - a) < eps * eps:
            break
    return w
# sqrt_by_gd(8.) ≈ 2.8284
```

**手算一次更新：** 令 `a=2,w0=1,lr=0.001`。目标函数和梯度分别是 `$`L(w)=(w^2-a)^2`$` 与 `$`\nabla L(w)=4w(w^2-a)`$`；初始梯度为 `$`4\times1\times(1-2)=-4`$`。梯度下降执行 `$`w_{\mathrm{new}}=w-\mathrm{lr}\cdot\nabla L(w)`$`，所以新值是 1.004，朝正平方根方向移动。随后继续用新的 w 重新计算梯度；只有当 `$`|w^2-a|<\mathrm{eps}^2`$` 才提前停止。这个算法每轮只改一个标量状态，循环不变量可以口述为“w 是当前近似根，下一步使用当前 w 的梯度产生更新后的近似值”。

**边界与复杂度（代码的重要限制）：** 设实际循环次数为 I，时间 $`\mathcal{O}(I)`$、额外空间 $`\mathcal{O}(1)`$。虽然检查了 `a<0`，但 `w0=0` 且 `a>0` 时梯度也是 0，会永远停在错误的驻点；在稳定学习率下，负初值会趋向负平方根而不是通常期望的非负根。若达到 `max_iter` 仍未满足误差条件，函数仍会返回当前值，没有告诉调用方“未收敛”；学习率过大也可能震荡或发散。调用者应验证返回结果，而不能把“返回了数字”当作收敛证明。

**问题（追问）：lr 为什么这么小？**

回答：损失是四次多项式，梯度随 w 的立方增长——首步梯度约 4w₀(w₀²−a)，w₀=a/2 时约 a³/2 量级，lr=1e-3 只对中小量级的 a 稳定，a 上百第一步就震荡发散；所以入口判 a<0 报错、初值按 a 的量级取（a<1 取 1.0、否则取 a），工程上加梯度裁剪或把 lr 按 1/a² 缩放。追问"和牛顿法比"：牛顿法 w ← (w + a/w)/2 对任意正初值全局收敛且二阶速度，几步到位。两者区别——GD 一阶收敛慢但不需要二阶信息，牛顿法快但在非凸情形可能跳到错误根。

### 10. 有效数字（状态机，LeetCode 65）

核心思想：把"数字/小数点/e/正负号"的合法转移显式建成状态机，每条转移可枚举、可逐一构造测试。

**先看状态的含义：** 输入是一段字符串，输出布尔值。`cur` 是当前读到的位置所处的状态；状态表中的键表示下一字符类别，值是读完该字符后进入的新状态。状态 0 是开头，1 是整数部分，2 是开头的正负号之后，3 是小数点但还没读到数字，4 是小数部分已有数字，5 是指数符号 e 之后，6 是指数 e 后的正负号之后，7 是指数数字部分。合法结束状态是 1、4、7；单独停在小数点、e 或符号之后都不合法。

实现代码：

```python
def is_valid_number(s: str) -> bool:
    s = s.strip()
    states = [
        {'digit': 1, 'sign': 2, 'dot': 3},
        {'digit': 1, 'dot': 4, 'e': 5},
        {'digit': 1, 'dot': 3},
        {'digit': 4},
        {'digit': 4, 'e': 5},
        {'sign': 6, 'digit': 7},
        {'digit': 7},
        {'digit': 7},
    ]
    cur, has_digit = 0, False
    for ch in s:
        kind = ('digit' if ch.isdigit() else 'sign' if ch in '+-'
                else 'dot' if ch == '.' else 'e' if ch in 'eE' else None)
        if kind == 'digit': has_digit = True
        if kind is None or kind not in states[cur]:
            return False
        cur = states[cur][kind]
    return has_digit and cur in (1, 4, 7)
```

**沿着循环走一遍：** 对字符串 `"-.5e+2"`，先去掉首尾空白；`-` 进入状态 2，`.` 进入状态 3，`5` 进入状态 4，`e` 进入状态 5，`+` 进入状态 6，`2` 进入状态 7，最终是接受状态且至少见过一个 digit，因此返回 True。对 `"1e+"`，读完 `1e+` 停在状态 6，不是接受状态，所以返回 False。循环不变量是：每读完一个字符，`cur` 精确描述已读前缀的合法结构；遇到没有列出的转移立即拒绝，不必等到结尾再猜。

**复杂度与边界：** 字符只扫描一遍，时间 $`\mathcal{O}(n)`$；状态表固定大小，额外空间 $`\mathcal{O}(1)`$。空字符串、只有符号、只有小数点都被拒绝；`".5"`、`"5."` 和 `"1e+5"` 可接受；`"1e+"`、`".e1"` 不可接受。注意代码使用 `str.isdigit()`，会把某些非 ASCII Unicode 数字也当作 digit；如果题目语法只允许 ASCII `0` 到 `9`，这是现有实现的适用范围问题，未在此处改代码。

**问题（追问）：为什么状态机不用正则？**

回答：约束是结构化的——点号与 e 各只能出现一次、e 之后必须有整数、符号只出现在特定位置。该语言是正则语言，正则同样可解；选状态机是因为转移表可逐条核对，一条长正则难读难验证，边界情况（".5"、"5."、"1e+5"、".e1"）极易漏。配三四个边界样例说明各自落在哪个状态、最终是否停在接受态，是验证状态机正确性的最快方式。

### 11. 快速排序 partition 与 quickselect（第 k 小）

核心思想：partition 把 pivot 归位、左侧全小右侧全大；quickselect 只递归含目标下标的一侧，期望 O(n)。

**先看输入、输出和步骤：** `partition(a,lo,hi)` 在闭区间 `[lo,hi]` 原地重排列表，返回 pivot 最终下标；返回后左侧元素严格小于 pivot，右侧元素大于或等于 pivot。`quickselect(a,k)` 中 k 从 1 开始，返回第 k 小的值，但会改变输入列表顺序。它反复 partition，并只保留可能包含目标下标 `k−1` 的半边；不需要把整个数组排好序。

实现代码：

```python
import random

def partition(a, lo, hi):
    p = random.randint(lo, hi)
    a[p], a[hi] = a[hi], a[p]          # 随机 pivot 换到末尾，防有序输入退化
    pivot = a[hi]
    i = lo                             # 不变量：[lo, i) 均 < pivot
    for j in range(lo, hi):
        if a[j] < pivot:
            a[i], a[j] = a[j], a[i]
            i += 1
    a[i], a[hi] = a[hi], a[i]          # pivot 归位
    return i

def quickselect(a, k):                 # 第 k 小，k 从 1 计
    lo, hi = 0, len(a) - 1
    while lo <= hi:
        p = partition(a, lo, hi)
        if p == k - 1:
            return a[p]
        if p > k - 1:
            hi = p - 1
        else:
            lo = p + 1
    raise IndexError("k out of range")
```

**用 `[3,1,2]` 手跑一次：** 假设随机抽到的 pivot 是 2 并换到末尾。循环开始 `i=lo=0`，`j` 从 lo 扫到 hi−1；遇到 3 不小于 pivot，`i` 不动；遇到 1 小于 pivot，就把它换到 `a[i]` 并令 `i` 加一。扫描结束时 `[lo,i)` 都小于 pivot、`[i,hi)` 都不小于 pivot；最后把 pivot 放到 `a[i]`，得到 `[1,2,3]`，返回位置 1。求第 2 小时目标下标也是 1，于是结束。若 pivot 落在目标左边，循环不变量保证目标只可能在右区间；落在右边则只可能在左区间。

**复杂度与边界：** 随机 pivot 下期望时间 $`\mathcal{O}(n)`$、额外空间 $`\mathcal{O}(1)`$（这里循环实现没有递归栈）；最坏仍可能 $`\mathcal{O}(n^2)`$。空数组、`k<=0` 或 `k>len(a)` 会最终抛 `IndexError`；合法调用也会原地修改列表，若调用者需要保留原顺序应先复制。所有值相等时，由于比较条件是严格 `< pivot`，每次 pivot 都落到当前区间最左侧，仍可能退化到 $`\mathcal{O}(n^2)`$；随机 pivot 并不能解决大量重复值导致的这种退化。

**问题（追问）：为什么要随机 pivot？**

回答：固定取首或尾元素时，接近有序的输入会让每次划分一侧为空，比较次数退到 O(n²)；随机化后坏划分的概率与输入分布解耦，quickselect 期望比较约 2n 次（n + n/2 + n/4 + … 的几何级数），快排整体期望 O(n log n)。工程替代方案还有三数取中。

**问题（追问）：和堆解法怎么选？**

回答：quickselect 期望 O(n) 但原地改数组、最坏 O(n²)；大小为 k 的堆 O(n log k)，不改原数组且支持流式到达。一次性静态数组用 quickselect，k 远小于 n、数据流式或不允许改输入时用堆。注意 Python 的 heapq 是最小堆，求第 k 大时维护大小 k 的最小堆、堆顶即答案。

**问题（追问）：partition 最容易写错哪？**

回答：两处——循环不变量（[lo, i) 存放小于 pivot 的元素，i 是下一个写入位）和最后把 pivot 与 a[i] 交换的归位步骤，漏掉归位 pivot 就永远停在末尾；边界条件 lo <= hi 写成 lo < hi 会在 lo == hi 时跳过划分直接错序。写完用 [3,1,2] 与 [2,2,2] 各手跑一遍即可暴露。

### 12. Top-k / Top-p 采样

核心思想：logits 先除 temperature 过 softmax，再按固定个数（top-k）或累计概率阈值（top-p）截断候选集，重新归一化后采样。

**先看输入、输出和步骤：** `logits` 最后一维是词表大小 V，可为 `(V,)` 或 `(B,V)`；返回每行抽到的一个 token ID，形状分别是标量或 `(B,)`。temperature 改变分布尖锐程度；`top_k>0` 时按概率留下至多 k 个候选，`top_k<=0` 表示关闭 top-k；`top_p<1` 时按从高到低的累计概率选出候选。代码最后重新归一化，让剩余权重和为 1，再调用 `multinomial` 随机抽样。候选被删掉只意味着概率设为 0，不是给 token 改 ID。

实现代码：

```python
import torch

def sample_topk_topp(logits, temperature=1.0, top_k=0, top_p=1.0):
    logits = logits / max(temperature, 1e-5)     # 温度必须作用在 softmax 之前
    probs = torch.softmax(logits, dim=-1)
    if top_k > 0:
        kth = probs.topk(top_k).values[..., -1, None]
        probs = probs.masked_fill(probs < kth, 0.0)
    if top_p < 1.0:
        sp, si = torch.sort(probs, descending=True, dim=-1)
        keep = sp.cumsum(-1) - sp < top_p        # 累计概率超过阈值即截断，至少留 1 个
        probs = torch.zeros_like(probs).scatter(-1, si, sp * keep)
    probs = probs / probs.sum(-1, keepdim=True)  # 截断后重新归一化
    return torch.multinomial(probs, 1).squeeze(-1)
```

**小例子与截断次序：** 假设 softmax 后概率是 `[0.60,0.25,0.15]`。top-k=2 会清零第三项；top-p 再从大到小看累计概率，保留前缀候选，最后重新归一化并抽一个 token。需要注意，这段代码在 top-k 后、top-p 前没有把 `[0.60,0.25,0]` 重新归一化：top-p=0.70 时它会保留前两个（第二项之前的原始累计概率是 0.60）；如果先在 top-k 候选内归一化，分布变成约 `[0.706,0.294,0]`，阈值 0.70 只会留下第一个。也就是说，“top-k 后接 top-p”的具体候选结果依赖过滤顺序和归一口径，当前实现采用未归一化的中间概率。

**边界与复杂度：** `top_k` 必须不超过 V，否则 `topk` 报错；top-p 的有效阈值是 `$`0<top_p\le1`$`，设为 0 或负数会导致候选全被清零，最终除以零；大于等于 1 时本代码不执行 top-p 截断；V 不能为空。相同概率恰好卡在 top-k 阈值时，`probs < kth` 会把并列项都留下，因此候选数可能多于 k。temperature 小于等于 0 时本代码用 `1e-5` 代替，并非报错。softmax/top-k 约需 $`\mathcal{O}(BV)`$，top-p 排序约 $`\mathcal{O}(BV\log V)`$，中间概率占 $`\mathcal{O}(BV)`$ 空间。

**问题（追问）：top-k 与 top-p 的本质差别？**

回答：top-k 候选数固定，不看分布形状——分布尖锐时尾部小概率仍占位，分布平坦时又砍得太狠；top-p 按累计概率自适应候选数，尖锐分布只留一两个、平坦分布保留几十个。工程上两者常同时开，先 k 后 p；开放生成常用 top_p 0.8–0.95、temperature 0.7–1.0。

**问题（追问）：temperature 为什么不能在采样后调？**

回答：temperature 除的是 logits、必须在 softmax 之前，它改变的是分布形状——T 大于 1 变平（熵升高）、小于 1 变尖、趋 0 等价 argmax。采样只是按既定分布抽样，事后无法改形状。所以"温度调高更随机"的准确说法是高温拉平了 token 间的概率差。

**问题（追问）：截断后为什么要重新归一化？**

回答：截断把部分概率置零，总和不再为 1；multinomial 虽按权重比例抽样、结果等价，但显式归一化让返回的 probs 仍可直接用于 logprob、熵、困惑度等下游统计，与 HuggingFace 的实现口径一致。

### 13. DPO Loss（sigmoid 形式）

出处：[DPO](https://arxiv.org/abs/2305.18290)。

核心思想：把 RLHF 目标闭式改写成分类损失——隐式奖励取 β 乘策略与参考模型的 logprob 差，偏好对分差过 sigmoid 取负对数。

**先看输入、输出和步骤：** 四个输入均是 `(B,)`，每个值是整条 chosen（偏好回答）或 rejected（不偏好回答）的 token logprob 之和；返回标量 loss 和标量排序准确率。先计算当前策略相对参考策略对两条回答各自提高了多少，再相减形成偏好 margin；margin 越大，chosen 相对 rejected 的优势越明显，`-logsigmoid` 就越小。参考模型提供基线，不需要额外训练一个显式 reward model。

实现代码：

```python
import torch
import torch.nn.functional as F

def dpo_loss(pi_logp_w, pi_logp_l, ref_logp_w, ref_logp_l, beta=0.1):
    # 四个输入均为 (B,)：整条回答的 token logprob 之和
    logit_w = beta * (pi_logp_w - ref_logp_w)
    logit_l = beta * (pi_logp_l - ref_logp_l)
    loss = -F.logsigmoid(logit_w - logit_l).mean()
    with torch.no_grad():
        acc = (logit_w > logit_l).float().mean()  # 偏好对排序准确率，监控用
    return loss, acc
```

**一对样本走一遍：** 若 chosen 的策略 logprob 比参考模型高 1，而 rejected 的策略 logprob 比参考模型低 1，那么 `logit_w` 为 `$`+\beta`$`、`logit_l` 为 `$`-\beta`$`，margin 是 `$`2\beta`$`，sigmoid 会给 chosen 更高的偏好概率。一般的 margin 可写成 `$`m=\beta[(\ell_w^\pi-\ell_w^{\mathrm{ref}})-(\ell_l^\pi-\ell_l^{\mathrm{ref}})]`$`。若策略和参考模型对两条回答的相对变化完全相同，margin 为 0，loss 是 `$`-\log(0.5)`$`，表示这一对还没有学出偏好差异。`acc` 只检查 margin 是否严格大于 0，用于排序监控，不参与反向传播。

**复杂度与边界：** 在 logprob 已经算好的情况下，每对样本只做常数次运算，时间 $`\mathcal{O}(B)`$、额外空间 $`\mathcal{O}(B)`$。空 batch 的 `.mean()` 会得到 NaN；chosen/rejected 的输入形状不一致会报错或无法配对；ref logprob 在训练时应来自冻结参考模型，避免把参考策略也一起更新。这里对整条回答使用 logprob 总和，因此长度会影响数值，数据对齐和 padding mask 必须在上游正确处理。

**问题（追问）：β 的作用与量级？**

回答：β 控制策略偏离参考模型的容忍度——它是 KL 约束强度的倒数，β 大则隐式奖励对 logprob 差敏感、更新激进易跑偏，β 小则保守、学不动偏好。常用 0.1，在 0.05–0.3 上做消融；监控指标看 acc（训练中应升到 0.6–0.8）与 chosen/reject 两条 logprob 的差值走势。

**问题（追问）：为什么不需要显式奖励模型？**

回答：Bradley-Terry 偏好模型下 KL 约束的最优策略有闭式解 π*(y) ∝ π_ref(y)·exp(r(y)/β)，反解出 r(y) = β·log(π*/π_ref) 加配准常数；代回偏好概率 σ(r_w − r_l) 后常数抵消，损失里只剩策略与参考模型的 logprob 差——奖励模型被参数化消掉了，这就是"direct"的含义。

**问题（追问）：和 GRPO 的适用边界？**

回答：DPO 吃离线偏好对，无采样、无执行反馈，数据是固定的；GRPO 在线采样、可接可验证奖励（单测、数学判分）。能拿到 verifier 信号的任务选 GRPO，只有人工或 judge 偏好对的选 DPO。DPO 已知短板是对长度与分布外样本的偏好外推不稳定，演进线有 IPO、KTO、SimPO 等变体。

### 14. softmax 数值稳定版

核心思想：减行最大值再取指数，数学上与原版等价，消除大 logits 的 exp 上溢。

**先看输入、输出和步骤：** `x` 可以有任意多个维度，`dim` 指定哪一维是类别/词表维；输出形状与输入相同，在该维上的概率和为 1。先保留每行最大值 `m`，算 `$`e^{x-m}`$`，再除以该行指数和。因为分子分母同时乘了同一个正数 `$`e^{-m}`$`，概率不变；减最大值能保证最大指数项 `$`e^0=1`$`，其余不超过 1，从而避免大正数直接 `exp` 溢出。

实现代码：

```python
import torch

def stable_softmax(x, dim=-1):
    m = x.max(dim=dim, keepdim=True).values
    e = torch.exp(x - m)                         # 最大指数项为 e^0 = 1
    return e / e.sum(dim=dim, keepdim=True)
```

**小例子：** 对一行 logits `[1000,1001]`，直接求指数可能溢出；减最大值后变成 `[-1,0]`，两项指数分别是 `$`e^{-1}`$` 和 1，归一化得到约 `[0.269,0.731]`，与原 logits 的 softmax 相同。`keepdim=True` 让 `m` 和分母在被归一化的维度上保留长度 1，因此能正确广播回原形状。

**边界与复杂度：** 每个元素做常数次运算，时间和输出空间都是 $`\mathcal{O}(\operatorname{numel}(x))`$。若归一化维为空，`max` 没有值可取会报错；若整行都是负无穷，`x−m` 会变成 NaN；若含正无穷，也可能出现 `inf−inf`。实际模型还需关注低精度下的下溢，因此交叉熵通常使用融合且数值稳定的 `log_softmax`，而不是对 softmax 结果再取 log。

**问题（追问）：减 max 为什么不改变结果？**

回答：分子分母同乘 e^{−m}：e^{x_i}/Σe^{x_j} = e^{x_i−m}/Σe^{x_j−m}。减完最大项为 e⁰=1、其余不超过 1，上溢消失；下溢只会把本来就接近零的小概率项压成 0，对分布无害。

**问题（追问）：训练里为什么用 log_softmax 而不是先 softmax 再取 log？**

回答：分两步时小概率项 e^{x−m} 下溢成 0，再取 log 得到 −inf 丢精度；log_softmax 内部按 x_i − m − log(Σe^{x−m}) 一步算，log-sum-exp 同样走减 max 技巧。F.cross_entropy 就是 log_softmax 加 NLL 的融合实现，手写交叉熵时直接组合这两个原语即可。

**问题（追问）：和 FlashAttention 的在线 softmax 什么关系？**

回答：分块计算时看不到全局最大值，就维护运行最大值 m 与归一分母 l，每来一块用 e^{m_old−m_new} 给已累积的结果换底重缩放——本质是这套减 max 技巧的流式版本。

### 15. Beam Search（含 length penalty）

核心思想：每步保留累计分数最高的 B 条前缀；logprob 加性累计天然偏好短序列，用长度惩罚调和。

**先看输入、输出和步骤：** `next_logit_fn(seqs)` 接收当前 beam 的 token 序列，返回每条序列下一 token 的 logits `(当前 beam 数,V)`；`bos/eos` 是起始和结束 token ID。函数返回分数最高的一条 token ID 列表。每轮先把 logits 转成 logprob，再加到各 beam 已有的累计分数上；展平所有“旧 beam × 新 token”候选，选分数最高的 beam 个，反推出它们来自哪条旧序列和哪个新 token，拼接成下一轮序列。

实现代码：

```python
import torch

def beam_search(next_logit_fn, bos, eos, beam=4, max_len=20, alpha=0.6):
    seqs = torch.tensor([[bos]])                 # (beam, t)
    scores = torch.zeros(1)                      # 累计 logprob
    for _ in range(max_len):
        logp = torch.log_softmax(next_logit_fn(seqs), dim=-1)   # (beam, V)
        cand = (scores[:, None] + logp).flatten()
        top = cand.topk(beam)
        beam_idx, tok = top.indices // logp.size(-1), top.indices % logp.size(-1)
        seqs = torch.cat([seqs[beam_idx], tok[:, None]], dim=1)
        scores = top.values
        if (seqs[:, -1] == eos).all():
            break
    lp = ((5.0 + seqs.size(1)) / 6.0) ** alpha   # GNMT 长度惩罚
    best = (scores / lp).argmax()                # 搜索内各步 beam 等长，惩罚只在收尾排名起作用
    return seqs[best].tolist()
```

**用很小的搜索树走一轮：** 设 beam=2，第一步模型给 A、B 的概率分别为 0.6、0.4，保留 `[BOS,A]` 与 `[BOS,B]`，分数是各自 logprob。第二步假设 A 后 EOS 概率 0.8、B 后 EOS 概率 0.7，则两条完成候选的概率分别是 `$`0.6\times0.8=0.48`$` 和 `$`0.4\times0.7=0.28`$`（logprob 相加等价于概率相乘）；代码会把每个旧 beam 的每个词表 token 都作为候选，再全局挑前两名。长度惩罚只在最后用于挑 best，不参与每一轮的 top-k 扩展排序。

**边界与复杂度（这段是简化版）：** 每轮候选数约为 beam 与 V 的乘积，挑选需要约 $`\mathcal{O}(bV\log b)`$，另加模型前向成本；序列缓存最多 $`\mathcal{O}(bL)`$。第一轮若词表大小 V 小于 beam，`topk(beam)` 会报错。已输出 EOS 的 beam 在这份代码中仍会继续被扩展，只有所有 beam 都以 EOS 结束才停；真实实现通常把完成序列冻结在完成池中。若一直没有 EOS，则跑满 `max_len`；length penalty 使用 `seqs.size(1)`，其中包含 BOS。另，`seqs` 和 `scores` 在 CPU 上初始化；若模型 logits 在 GPU，调用方需要处理设备一致性，否则会报 device mismatch。以上是现有实现的简化假设，不在此改写代码。

**问题（追问）：为什么需要 length penalty？**

回答：logprob 是负数、逐 token 累加，序列越长累计值越负，裸分数系统性偏好短回答。lp(Y)=((5+|Y|)/6)^α 随长度单调增，分数除以它（α 常取 0.6–1.0，分数为负所以除法抬升高长度序列的排名）抵消这个偏置；搜索过程中同一步所有 beam 等长、惩罚相同，真正起作用的是结束序列与未结束序列之间、以及最终多条完成序列之间的比较。

**问题（追问）：beam 是不是越大越好？**

回答：不是。beam 4–8 之后质量常不升反降——高概率序列趋向短、通用、复读，搜索越充分越暴露模型的模式坍缩；显存与耗时还随 beam 线性增长。工程口径：开放生成基本不用 beam（会出模板腔，改用采样），受限生成如翻译、结构化输出、工具参数用 beam 2–4。

**问题（追问）：已结束的 beam 正规做法怎么处理？**

回答：结束序列应冻结进完成池、不再参与扩展，每步把完成池与活跃 beam 按惩罚后分数统一排名，凑够 n-best 或活跃 beam 全灭即停；达到 min_length 前屏蔽 eos。上面的最简实现用"全部结束则停"近似，面试里主动指出这个差别即可。

### 16. AdamW 单步更新

出处：[AdamW](https://arxiv.org/abs/1711.05101)（Decoupled Weight Decay Regularization）。

核心思想：一阶、二阶动量做偏差校正后按自适应步长更新；weight decay 与梯度解耦，直接乘在参数上、不进动量。

**先看输入、输出和步骤：** `p` 是参数，`g` 是当前梯度，`m/v` 是与参数同形状的一阶、二阶动量状态，`t` 是从 1 开始的更新步数；它们应在相同设备上且形状一致。函数没有返回值，而是原地修改 `p,m,v`。顺序是更新两个动量、按步数做偏差校正、将参数乘上解耦的 weight decay 因子，再沿校正后的一阶动量方向更新参数。

实现代码：

```python
import torch

@torch.no_grad()
def adamw_step(p, g, m, v, t, lr=1e-3, betas=(0.9, 0.999), eps=1e-8, wd=0.01):
    # m、v 初始为 zeros_like(p)，t 从 1 计
    b1, b2 = betas
    m.mul_(b1).add_(g, alpha=1 - b1)             # 一阶动量
    v.mul_(b2).addcmul_(g, g, value=1 - b2)      # 二阶动量
    m_hat = m / (1 - b1 ** t)                    # 偏差校正
    v_hat = v / (1 - b2 ** t)
    p.mul_(1 - lr * wd)                          # 解耦 decay：不进 m/v
    p.addcdiv_(m_hat, v_hat.sqrt().add_(eps), value=-lr)
```

**看清单步的状态变化：** 起步时 `m=v=0`，第一步的原始动量会因从零开始而偏小，所以 `$`\hat m_t=m_t/(1-\beta_1^t)`$`、`$`\hat v_t=v_t/(1-\beta_2^t)`$` 把这种初始化偏差校正回来。`v_hat.sqrt()+eps` 是每个参数自己的步长分母；梯度平方的长期平均越大，该参数此次更新相对越小。随后参数按 `$`p\leftarrow(1-\mathrm{lr}\cdot\mathrm{wd})p`$` 单独收缩，这一步不把 `wd·p` 混进 g，因此不会让 weight decay 经过自适应分母缩放。

**边界与复杂度：** 每个参数元素做常数次运算，时间 $`\mathcal{O}(\operatorname{numel}(p))`$；m、v 是跨步保存的优化器状态，单步另有同阶临时张量。`t` 必须从 1 开始，t=0 会使偏差校正分母为 0；p/g/m/v 形状或设备不一致会报错。函数原地修改状态，若重复调用同一梯度也会继续累积动量；调用者还要按参数类型分组，避免对不应 decay 的参数应用同一 wd。

**问题（追问）：AdamW 与 Adam 加 L2 的差在哪？**

回答：L2 把 wd·p 加进梯度，随后被二阶动量 v 的平方根除掉——梯度大的参数等效 decay 被缩小，正则强度与损失景观耦合；AdamW 把衰减直接乘在参数上，wd 与 lr 可独立调，这是它成为 LLM 训练默认优化器的原因。量级口径：AdamW 论文用 lr 1e-3 演示，LLM 训练 wd 常取 0.01–0.1。

**问题（追问）：偏差校正去掉会怎样？**

回答：m、v 从零初始化，初期系统性低估真实矩——v 偏小使步长偏大，前几十步等效 lr 被放大；校正项 1/(1−β^t) 在 t=1 时把 m 放大 10 倍、v 放大 1000 倍，t 大后趋 1 可忽略。短训练或 warmup 前段必须保留校正。

**问题（追问）：哪些参数不做 weight decay？**

回答：归一化层的 gain、所有 bias、embedding——它们的尺度承载功能语义，decay 压向零会破坏归一化与查表作用；工程实现按参数名或 ndim 分组，一维参数与 embedding 设 wd=0。

### 17. cosine 学习率 schedule

核心思想：warmup 段线性升到峰值，随后按余弦半波从峰值衰减到下限，总步数需预先定死。

**先看输入、输出和步骤：** 输入是当前 step、总步数、峰值/最低学习率和 warmup 长度；输出是一个标量学习率。warmup 区间按 `$`\mathrm{step}/\mathrm{warmup}`$` 从 0 线性升到 peak；之后把当前进度归一到 0 到 1，再让余弦从 1 平滑降到 −1，使学习率从 peak 降到 min_lr。对应的衰减式为 `$`\eta(t)=\eta_{\min}+\frac{1}{2}(\eta_{\max}-\eta_{\min})[1+\cos(\pi\tau)]`$`，其中 `$`\tau`$` 是 warmup 后的归一化进度。该函数只算学习率，不更新模型参数。

实现代码：

```python
import math

def cosine_lr(step, total_steps, peak=1e-4, warmup=500, min_lr=0.0):
    if step < warmup:
        return peak * step / warmup              # 线性 warmup
    t = (step - warmup) / max(total_steps - warmup, 1)
    return min_lr + 0.5 * (peak - min_lr) * (1 + math.cos(math.pi * t))
```

**用 6 步的小日程检查：** 令 `total_steps=6,warmup=2,peak=1,min_lr=0.1`。step 0 返回 0，step 1 返回 0.5，step 2 到峰值 1；step 4 位于余弦中点，返回 0.55；step 6 到最低值 0.1。循环训练时通常在每次 optimizer update 前用当前 step 查询一次，并明确 step 是从 0 还是 1 开始，否则峰值和总步数会错一格。

**边界与复杂度：** 每次计算是常数时间、常数空间。应满足 `0≤step≤total_steps`、`0≤warmup<total_steps` 且 `peak≥min_lr`；超出总步数后，代码没有 clamp，余弦会继续变化而不是停在 min_lr；若 warmup 不小于总步数，衰减区间也不再是预期形状。warmup 设为 0 时，对非负 step 不进入线性分支；传入负 step 则不是有效训练进度。

**问题（追问）：warmup 为什么必须有？**

回答：训练初期参数随机、梯度方向噪声大，Adam 的二阶矩估计也未稳定，大 lr 直接把参数推进坏区域，表现为 loss 尖峰甚至发散；线性 warmup 让动量与 v 先积累可靠估计。LLM 训练 warmup 常取总步数的 0.1%–3%，几百到几千步。

**问题（追问）：cosine 与 WSD 怎么选？**

回答：cosine 的衰减段与总预算绑死，改预算就要重训；[WSD](https://arxiv.org/abs/2404.06395)（warmup-stable-decay）主体常数、只在末段 10%–20% 快速衰减，stable 段随时可续训、改预算、换数据配比，checkpoint 利用率高。多阶段续训与扩窗场景用 WSD，预算固定的一次性训练两者均可。

**问题（追问）：min_lr 设 0 还是留底？**

回答：预训练常衰减到接近 0（峰值的 0–10%），把模型送进盆地底部；SFT 常留峰值约 10% 的底，避免后段在小数据上过拟合出尖锐最小值。验证 schedule 是否合理的经验判据：decay 段 loss 应平滑下弯且无反弹，反弹说明 lr 过高或该阶段数据分布突变。

### 18. LoRA 前向与合并

出处：[LoRA](https://arxiv.org/abs/2106.09685)。

核心思想：冻结 W，增量 ΔW 用低秩乘积 BA 近似（r≪d），缩放 α/r；部署时把 BA 加回 W，推理零额外开销。

**先看输入、输出和步骤：** `x` 最后一维为 `d_in`，输出最后一维为 `d_out`。基座线性层权重 `W.weight` 形状 `(d_out,d_in)`；A 的权重是 `(r,d_in)`，B 的权重是 `(d_out,r)`，因此 `B.weight @ A.weight` 得到与 W 同形状的增量矩阵。前向是基座输出加上低秩支路输出，再乘缩放 `alpha/r`；只有 A、B 参与训练，基座 W 冻结。

实现代码：

```python
import torch, torch.nn as nn, math

class LoRALinear(nn.Module):
    def __init__(self, d_in, d_out, r=8, alpha=16):
        super().__init__()
        self.W = nn.Linear(d_in, d_out, bias=False)
        self.W.weight.requires_grad_(False)      # 冻结基座
        self.A = nn.Linear(d_in, r, bias=False)
        self.B = nn.Linear(r, d_out, bias=False)
        nn.init.kaiming_uniform_(self.A.weight, a=math.sqrt(5))
        nn.init.zeros_(self.B.weight)            # B 置零：初始 ΔW=0，从基座出发
        self.scale = alpha / r

    def forward(self, x):
        return self.W(x) + self.B(self.A(x)) * self.scale

    @torch.no_grad()
    def merge(self):
        # nn.Linear 算 x @ Wᵀ，故 ΔW 矩阵 = B.weight @ A.weight，形状 (d_out, d_in)
        self.W.weight += (self.B.weight @ self.A.weight) * self.scale
```

**用一个秩 1 例子看形状：** 设 `d_in=d_out=2,r=1`，A 权重是 `[1,0]`，B 权重是 `[[2],[0]]`，scale=1，则增量矩阵满足 `$`\Delta W=BA=[[2,0],[0,0]]`$`。输入 `[3,4]` 经低秩支路得到 `[6,0]`，再加到基座线性层的输出上。秩 r 是中间瓶颈宽度：输入先被压到 r 维，再投影回输出维，避免直接为一个完整的 `d_out×d_in` 增量学习所有自由参数。

**边界与现有实现疑点：** 每个输入向量新增计算量约为 $`\mathcal{O}(d_{\mathrm{in}}r+rd_{\mathrm{out}})`$，新增参数量为 `$`r(d_{\mathrm{in}}+d_{\mathrm{out}})`$`。r 必须大于 0，否则 `alpha/r` 无定义；输入最后一维必须等于 `d_in`。B 初始为零时，初始增量为零，但第一步 A 的梯度也为零（因为梯度要乘 Bᵀ），通常先由 B 获得梯度，B 更新后 A 才开始获得梯度；原文“两个因子才有梯度流”的说法容易误解。另，`merge()` 会原地把 BA 加入 W：重复调用会重复叠加；若 merge 后仍执行原 forward，低秩支路还会再加一次，造成双计。部署时应只 merge 一次并停用 adapter 分支。这些说明不改代码行为。

**问题（追问）：为什么 B 置零、A 随机初始化？**

回答：初始 ΔW=BA=0，训练从基座等效出发、不破坏预训练表示；A 随机打破对称，两个因子才有梯度流。惯例取 r 4–64、α 为 r 的 1–2 倍使 scale 在 1–2 之间。

**问题（追问）：α/r 这个缩放在解决什么？**

回答：BA 的输出量级随 r 增长，不缩放时调 r 就要重调 lr；除以 r 再乘 α 让更新幅度与秩解耦，r 变成纯粹的容量超参。可以理解为 α 是低秩支路的等效学习率。

**问题（追问）：合并零开销的前提与不能合的场景？**

回答：BA 是 (d_out, d_in) 稠密矩阵，加进 W 后推理图与基座完全一致，无任何额外算子。不能合的两种场景：多 adapter 热切换（每请求换 LoRA，必须保持分支结构）；QLoRA（W 是 4bit 量化态，合并要先反量化再加、重新量化掉精度且不可逆）。

### 19. FlashAttention 分块思想（伪代码）

出处：[FlashAttention](https://arxiv.org/abs/2205.14135)。

核心思想：Q/K/V 分块搬进 SRAM，用在线 softmax（运行最大值 + 归一因子）逐块累积输出，T×T 注意力矩阵从不落 HBM。

**先看输入、输出和状态：** Q 是 query 矩阵，K/V 是 key/value 矩阵，最后一维都是 head_dim；输出 O 与 Q 的 query 行数及 V 的特征宽度对应。对每个 query 行，`m` 保存目前见过的最大分数，`l` 保存相对于这个最大值缩放后的指数和，O 保存相同尺度下的加权 V 累积。由于 K/V 分块到达，不能先一次性拿到完整一行的 softmax 分母，所以要边读块、边重标定累计值。

伪代码：

```
输入 Q, K, V（T×d），K/V 按块大小 Bk 切块
O ← 0（T×d）；l ← 0（T）；m ← −inf（T）        # l 归一分母，m 运行最大值
for 每个 K/V 块 K_j, V_j:
    S ← Q @ K_jᵀ / √d                          # 只物化 (T, Bk)
    m_new ← max(m, rowmax(S))
    P ← exp(S − m_new)
    l ← l · exp(m − m_new) + rowsum(P)         # 旧累积换底 + 新块贡献
    O ← O · exp(m − m_new) + P @ V_j
    m ← m_new
O ← O / l                                       # 循环结束统一归一化
```

**看在线 softmax 如何接两块：** 第一块算出局部最大分数 `m_old`，并据此累积 l 和 O。第二块可能有更大的分数；若新最大值变成 `m_new`，旧累积必须乘 `$`e^{m_{\mathrm{old}}-m_{\mathrm{new}}}`$` 换到新尺度，再加上第二块的指数权重和加权 V。最后 `$`O/l`$` 才等于对所有 K 一起做完整 softmax 的结果。这个“小块之间改共同基准”的过程就是减最大值稳定 softmax 的流式版本；重点不是近似，而是用稳定的重标定得到同一个数学结果。

**复杂度、边界与伪代码限制：** 算术量仍是 $`\mathcal{O}(T_qT_kd)`$，没有消除注意力的二次计算；它避免保存完整 `T_q×T_k` 分数矩阵。当前伪代码一次使用所有 Q，只按 K/V 分块，最大临时分数块是 `(T_q,B_k)`；真实 FlashAttention 还会按 Q 分块，把片上临时矩阵压到 query 块乘 key 块大小。HBM 是显卡上的高带宽显存，SRAM 指更靠近计算单元的片上快速存储；FlashAttention 通过减少二者间反复搬运注意力矩阵来提速。伪代码也没显式写 causal/padding mask，因果语言模型实现必须在对应分数块上屏蔽不可见位置。若某个 query 的所有 key 都被 mask，`l` 会为 0，末尾除法无效；每行必须至少有一个合法 key。

**问题（追问）：省的是什么、没省什么？**

回答：显存从 O(T²) 降到 O(T)——注意力矩阵不写回 HBM；FLOPs 不变，仍是 O(T²d)。提速来源是 IO 感知：HBM 访存量从 O(T²) 降到 O(T²d/M)（M 为 SRAM 容量），注意力在 H100 上是访存受限算子，省访存就是省时间。反向传播靠重算——只存 O 与 (l, m)，用时重算 P，拿计算换显存。

**问题（追问）：exp(m − m_new) 这步在干什么？**

回答：新块的局部最大值可能比之前大，已按旧 m 缩放的累积值 O、l 与新块不在同一尺度，统一乘 e^{m_old−m_new} 换底，保证任意时刻所有指数项共用同一个减去的最大值——即 stable softmax 的流式版本。

**问题（追问）：decode 阶段为什么常用别的 kernel？**

回答：decode 每步只有一个 q，没有 T² 矩阵可省，瓶颈变成 KV cache 的读取带宽；flash-decoding 类实现沿 T 维切分并行、各部分结果做 log-sum-exp 合并，paged kernel 则配合分页 KV cache 做显存管理。FlashAttention 的主战场是 prefill 与训练的大块 Q。

### 20. MoE Router（top-k gating + 负载均衡 loss）

核心思想：router 对 token 打分过 softmax，只派给 top-k 个专家；aux loss 用负载与路由概率的乘积惩罚倾斜，防专家塌缩。

**先看输入、输出和步骤：** `x` 形状 `(N,d)`，N 个 token、每个 d 维；`W_gate` 形状 `(E,d)`，E 个专家各一行 router 权重。乘法得到 `(N,E)` logits，softmax 后是每个 token 对所有专家的概率。top-k 给出每个 token 的专家编号 `(N,k)` 和对应概率；代码把这些 k 个概率在 token 内重新归一化为 gate 权重。返回专家编号、混合权重和一个标量辅助负载均衡 loss；这里展示的是路由与统计，不包含把 token 真正分发给专家网络的代码。

实现代码：

```python
import torch
import torch.nn.functional as F

def moe_router(x, W_gate, k=2, aux_coeff=0.01):
    # x: (N, d)，W_gate: (E, d)
    logits = x @ W_gate.T                        # (N, E)
    probs = F.softmax(logits, dim=-1)
    topv, topi = probs.topk(k, dim=-1)           # (N, k)
    gates = topv / topv.sum(-1, keepdim=True)    # top-k 内重新归一
    f = torch.zeros_like(probs).scatter_(1, topi, 1.0).mean(0)   # 各专家实际负载比例
    P = probs.mean(0)                                            # 各专家平均路由概率
    aux = aux_coeff * probs.size(1) * (f * P).sum()              # Switch 式 E·Σf·P
    return topi, gates, aux
```

**用 2 个 token、3 个专家走一遍：** 假设两行概率分别为 `[0.8,0.15,0.05]` 和 `[0.1,0.7,0.2]`，k=1 时它们分别选专家 0 和 1，因此实际负载 `f=[0.5,0.5,0]`；平均路由概率 `P=[0.45,0.425,0.125]`。辅助项按 `$`L_{\mathrm{aux}}=\alpha E\sum_e f_eP_e`$` 逐专家相乘再求和。`f` 记录“实际派给谁”，来自离散 top-k；`P` 记录 router 概率的平均值，可微，所以辅助 loss 的梯度主要经 P 推动路由均衡。top-k 内重新归一化保证每个 token 的专家混合权重之和为 1。

**边界与代码疑点：** `$`1\le k\le E`$` 且 `$`N>0`$`；k 越界会报错，空 token batch 上 `.mean(0)` 会产生 NaN。代码没实现专家容量上限、溢出 token 处理或实际 dispatch，这些需要在完整 MoE 层补上。重要的是：这里 `f` 对 top-k 中每个专家都记 1，再对 N 个 token 求平均，因此 `$`\sum_e f_e=k`$`；而注释和后面的文字按 Switch 的 top-1 情形解释“均匀时 `$`f_e=1/E`$`、辅助值最小为 1”。当默认 k=2 且路由均衡时，实际 `$`f_e=k/E`$`，代入现有公式 `$`E\sum_e f_eP_e`$` 的基准值是 k 而不是 1。要让数学解释与实现完全一致，需要明确 top-k 负载的归一化约定；此处按要求保留原代码和原回答，并把不一致标出。

**问题（追问）：aux loss 为什么用 f 与 P 的乘积？**

回答：负载均衡的终点是 f 与 P 都接近 1/E，此时 E·Σf_e·P_e 取最小值 1。f 来自离散的 top-k 选择、不可微，梯度只能走 P 这条路，乘积项把"高概率又高负载"专家的 softmax 概率压下去，间接推匀实际派发。只罚 P 会让 router 输出均匀概率却不改派发结果，只罚 f 则没有梯度。

**问题（追问）：top-k 内为什么要重新归一？**

回答：专家输出按 gate 加权求和，不归一时每个 token 的有效更新尺度取决于 top-k 概率之和——分布尖锐的 token 更新被偷偷缩小；归一让混合权重和恒为 1、token 间尺度一致。Switch 系 k=1 时天然归一，无此问题。

**问题（追问）：aux loss 与 z-loss 的分工与量级？**

回答：aux loss 管派得均不均（token 分配均衡），z-loss 管 router logits 幅值大不大（防 softmax 饱和成 0/1 硬分配后负载失衡加剧），两者正交可同时挂。工程量级：aux 系数 1e-3–1e-2，z-loss 1e-4–1e-3；任何一侧调过头都会压平路由，专家学不出分化，主任务 loss 反而上升。
