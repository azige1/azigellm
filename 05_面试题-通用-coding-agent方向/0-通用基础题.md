# 通用基础题

## 一、RL / 后训练

**问题：GRPO 和 PPO 的区别？为什么 GRPO 去掉了 value 网络 / critic？**

回答：GRPO 用"同 prompt 组内相对比较"替代 critic 的优势估计，省掉一半参数量，同时把序列级稀疏 reward 的基线问题转化为组内统计问题。PPO 的优势来自 GAE——$`\delta_t = r_t + \gamma V(s_{t+1}) - V(s_t)`$，$`A_t = \sum_k (\gamma\lambda)^k \delta_{t+k}`$，需要学一个与 policy 同规模的 value 网络。这在 LLM 场景有两个结构性问题：①critic 与 policy 优化不同步，value 的过/欠估计直接偏移策略梯度方向，而语言任务的 reward 多为序列级稀疏标量（对/错/格式分），中间状态没有可学的稠密价值，critic 学到的本质是"这题大概率能不能对"——这与"同题多条采样的通过率"是同一信息，所以可以用组内均值直接替代：$`\hat A_i = \frac{r_i - \mathrm{mean}(\mathbf r_{1..G})}{\mathrm{std}(\mathbf r_{1..G})}`$；②资源开销——critic 与 policy 同参量级，训练显存与逐 token value 前向开销近双倍（rollout 生成不经过 critic）。GRPO 的代价不是没有而是转移了：需要每 prompt 采 $`G`$ 条（典型 8/16），rollout 算力 ×G，但 rollout 走 vLLM 很便宜；组内归一有两处偏置——损失函数按各回答 1/|o| 平均引入长度偏置（答错时长回答每 token 受到的惩罚被摊薄，模型倾向把错答案写长），除以组内 std 引入难度偏置（std 趋零的组优势被 1/std 放大，训练偏向难度极端的题），[Dr. GRPO](https://arxiv.org/abs/2503.20783) 的对策是优势只减均值不除 std、loss 按固定常数预算归一，同时消掉这两处缩放；组内归一抹掉 prompt 间难度差，需配难度分层采样。注意 GRPO 并没有去掉 KL（仍在 loss 里）也没有去掉 importance ratio（仍要 clip），它只去掉了 value 网络。

**问题（追问）：组内相关性怎么办？同 prompt 共享基线会让梯度方差变大吗？**

回答：会，同组样本的梯度相关。缓解靠加大 batch 内 prompt 数（多样性）而非单组加大 G——G 只降单组估计方差，超过 16 后边际收益小。追问"G 越大越好吗"：不是，有效信号密度由"非全对全错组占比"决定，而不是 G 本身。

**问题（追问）：第一遍 mini-batch 更新后还算 on-policy 吗？**

回答：名义 on-policy、实际是接近 on-policy 的乐观策略迭代——更新后 $`\pi_\theta \ne \pi_{old}`$，靠重要性比率修正并用 clip 截断大偏离；一轮 rollout 只做 1~2 个 epoch、clip 0.1~0.2 就是在控制偏离（详见 on-policy 一题与 [verl 文档](https://verl.readthedocs.io)）。

**问题：GRPO 的 group size 怎么定？组内全对/全错怎么办？**

回答：group size 在 8~16 区间权衡"单组优势估计方差"与"rollout 算力"。全对/全错组归一后优势恒为零、是纯算力浪费——[DAPO](https://arxiv.org/abs/2503.14476) 的 Dynamic Sampling 按 batch 目标持续补采直到非退化组凑满；配套难度分层采样，按历史通过率把 prompt 池分桶，维持 pass rate ∈ (0,1) 的可学习区间。要点：随训练推进 prompt 会从"可学"漂向"全对"（学会了），难度标签要按近期通过率滚动重标（带贝叶斯平滑），否则有效 prompt 池枯竭、训练看似平稳实际不学了。"全对组直接丢只对了一半"——还要监控全对率漂移，长期存在的全对组可能掩盖 hacking（全对可能意味着题被利用奖励缺陷）。

**问题：DAPO 的四条改进是什么？分别解决什么失效模式？**

回答：①Clip-Higher（entropy 塌缩）：标准 clip 上下界对称（1±0.2），低概率 token 即使拿到正优势，ratio 上行也被 1.2 封顶——探索性 token 永远得不到足够梯度，策略逐渐坍缩；改成非对称 $`\epsilon_{low}=0.2, \epsilon_{high}=0.28`$，给还没被充分采样的好模式上升通道。②Dynamic Sampling（算力浪费）：过滤全对/全错组并补采。③Token-Level Policy Gradient Loss（长序列降权）：序列级归一让长回答每个 token 的梯度被 1/L 稀释——代码/推理任务恰恰长回答承载更多推理步骤；改成对所有 token 统一归一（除以 batch 总 token 数）。④Overlong Reward Shaping（超长错杀）：超长被截断的样本按惯例 reward=0，与"答错"不可区分，模型学到"尽早停笔"；改成按剩余长度给软惩罚，或把超长样本剔除不进梯度。注意四条不是开关全开就好——Clip-Higher 放宽上界会增大方差，需与 KL 系数联动调。

**问题：GSPO 改了 GRPO 什么？为什么序列级比率更稳？**

回答：[GSPO](https://arxiv.org/abs/2507.18071) 把 GRPO 的 token 级重要性比率换成序列级（几何平均），让一条序列内所有 token 共享同一截断约束。GRPO 里每个 token 独立计算 ratio 并独立 clip，长序列上个别 token 的极端偏差（重复段、低概率 token 被放大）在各自被 clip 后仍会累积出很大的序列级偏移。GSPO 定义 $`R_{seq} = \exp(\frac1L\sum_t \log \mathrm{ratio}_t)`$（几何平均在 log 域取均值、天然抗极值，算术平均会被大 ratio 主导），对 $`R_{seq}`$ 整体 clip 后同一系数作用于全部 token。效果：多轮长轨迹（agent 场景 L 很大）稳定性显著更好。选型：token 级（GRPO/DAPO）适合短回答数学题，序列级（GSPO，Qwen3-2507 及之后版本的后训练采用，初版 Qwen3 为 GRPO）适合长轨迹 agent RL。

**问题：KL 约束：为什么加？GRPO 里 KL 怎么进 loss？系数怎么设？**

回答：KL 把策略约束在参考策略附近防止分布崩塌与 reward hacking。GRPO 的实现细节是 KL 不进 reward 而用 k3 无偏估计逐 token 直接加进 loss：$`\widehat{kl}_t = e^{\log\pi_{ref} - \log\pi_\theta} - (\log\pi_{ref} - \log\pi_\theta) - 1`$。为什么不进 reward：若把 $`-\beta KL`$ 加到 reward 再做组内归一化，KL 惩罚会被 mean/std 标准化污染（KL 的大小信息被抹掉、还改变组内排序）。k3 无偏的原因：对 $`E_{y\sim\pi_\theta}`$ 逐项取期望，指数项期望为 1、对数项期望即 −KL、常数 −1 补齐（[DeepSeekMath](https://arxiv.org/abs/2402.03300) 附录给了 k1/k2/k3 的偏-方差对比）。系数典型 0.001~0.05，从 0.04 起调：过大策略被冻住（entropy 掉但 reward 不涨）、过小漂移与 hacking；监控按 token 级聚合出序列级曲线，发散通常集中在高频模板 token 与重复段，先降 lr 或减 clip range 再压 KL。$`\pi_{ref}`$ 通常取 SFT 后的 checkpoint。

**问题：on-policy 和 off-policy 的区别？异步一步延迟怎么修？**

回答：on-policy 用当前策略采的数据立即更新（REINFORCE 系）；off-policy 复用旧数据（Q-learning 系）。PPO/GRPO 居中：靠 $`\mathrm{ratio} = \pi_\theta/\pi_{old}`$ 重加权修正、clip 截断大比率。异步架构（rollout 引擎与 trainer 分离，如 [verl](https://arxiv.org/abs/2409.19256) 的 rollout-worker/policy-worker）把问题放大：rollout 期间 trainer 又更新若干步，数据 staleness 超过阈值就相当于在很 off-policy 的数据上训练。修正三件：①缓存 rollout 时 $`\pi_{old}`$ 的 logprob（真实 ratio，不重算）；②staleness 控制在阈值内（超过丢弃该批）；③进一步做 off-policy 修正（V-trace 类裁剪重要性采样）。PPO/GRPO 的准确定位是名义 on-policy、实际乐观策略迭代——单步更新后策略已偏离采样分布，偏离由 importance ratio 的 clip 控制。

**问题：训推不一致（TIS）怎么产生、怎么解决？**

回答：三个来源——①模板/分词：训练侧 chat template、多轮上下文拼接与推理服务不一致，模型面对没见过的输入分布；②采样参数：RL rollout 常用 temperature 0.7~1.0 保探索，部署常用 0~0.3 保稳定，行为分布系统性漂移；③异步一步延迟（见上一题）。解决按来源对应：模板/分词做逐 token 对拍（同一输入两端 input_ids 完全一致）；训练后期把 rollout 温度退火到部署口径；异步侧用真实 ratio 修正 + staleness 控制。判别方法：训练评测与线上同分布小样本对测，差异复现即定位。三个来源与对应修正构成完整口径。

**问题：entropy 塌缩怎么识别、怎么救？**

回答：识别看三条曲线——entropy 曲线骤降、输出长度/重复率异常、pass rate 停滞。先区分健康与病态：RL 早期 entropy 下降是"探索收敛"（策略聚焦到可解模式，pass rate 同步上升）；后期"坍缩"是无新模式被发现、输出模式单一化，判别标准是 entropy 与 pass rate 是否同向（[The Entropy Mechanism of RL for Reasoning LLMs](https://arxiv.org/abs/2505.22617) 把机制归为协方差驱动：高概率且正优势的 token 概率被进一步推高，熵单调下降直至坍缩，并给出经验定律可外推熵耗尽时的性能上限，对策是限制高协方差 token 的更新）。处置按诱因：①clip 对称封顶压制低概率 token → Clip-Higher；②KL/约束过强冻住策略 → 降 β、降 lr；③难度失衡（全错组长期零梯度后突发更新）→ 难度重分层 + 动态采样；④极端情况加熵正则或 rollout 温度上调（分布变宽可能短暂掉点，小步调）。entropy 的算法：策略在每个生成位置输出分布，取该分布的熵再对 policy 生成的 token 平均（mask 掉 prompt/环境 token），不是序列长度熵。

**问题：reward hacking 怎么防？三层防线分别怎么做？**

回答：①信号设计层——能执行判定就不让模型打分：可验证任务（跑测试、规则校验、数值比对）优先执行判定；LLM-as-judge 的 rubric 要分维度独立打（多维一次打会互相抬分）。②训练层——KL 拴住策略、动态采样过滤可疑全对组、token-level loss 平滑梯度。③监控层——reward 升、eval 不涨是最强报警；固定人工/留出集按周校准；抽查 top-reward 样本。典型案例口径：模型篡改测试文件使单测通过（对策：测试文件只读 + 哈希校验）；检索到答案原文照抄（对策：环境断网 + 答案-检索重合度检测）；复述工具返回冒充作答（对策：completion_mask 把环境 token 掩出策略梯度）。自建可验证基准要防弱单测污染——[SWE-bench+](https://arxiv.org/abs/2410.06992) 审计出约 31% 的"通过"属弱单测可疑通过，入库前跑对抗补丁探针（空补丁/只改注释/硬编码返回值，任一通过即判弱单测）。

**问题（追问）：发现 hacking 后怎么办——直接改 reward 吗？**

回答：先定位漏洞形态再补对应规则（只修补单点症状会引入新漏洞），同时把 hacked 样本从历史数据中剔除或降权重训。reward model 也会被 hack（RM 泛化漏洞），关键任务以规则校验为最终判定、RM 只做辅助信号。

**问题：蒸馏选 forward KL 还是 reverse KL？OPD 是什么、解决什么？**

回答：forward KL $`D_{KL}(p_T\|q_S) = E_{y\sim p_T}[\log\frac{p_T}{q_S}]`$——期望在 teacher 分布上取，teacher 有而学生没有的模式受无穷惩罚，学生被迫铺开覆盖 → mean-seeking，缺点是容量小的学生被迫覆盖超出自身容量的支撑区间、在未覆盖区域产生幻觉质量。reverse KL $`D_{KL}(q_S\|p_T) = E_{y\sim q_S}[\log\frac{q_S}{p_T}]`$——期望在学生分布上取，学生多出的质量被罚、没采到的区域不受罚 → mode-seeking，适合弱学生，但梯度只能用学生自己的样本估计（REINFORCE 形式，reward = −log p_T），方差大——[MiniLLM](https://arxiv.org/abs/2306.08543) 用 policy gradient 优化 reverse KL 并做梯度修正。SFT 的 CE loss 等价于 forward KL 的 teacher 样本估计，所以 SFT 的 exposure bias 正是 forward KL 的缺陷。[OPD（On-Policy Distillation）](https://thinkingmachines.ai/blog/on-policy-distillation/)：学生在自己采样的轨迹上让 teacher 逐 token 打 logprob，蒸馏 loss 与 RL loss 联合 $`L = L_{RL} + \alpha L_{OPD}`$——分布是学生的（无 exposure bias）、监督是 dense 的（每 token 都有信号，比 outcome reward 密集几个量级）。与"带 KL 约束的 RL"的区别：KL-RL 的锚是冻结 ref（约束项，限制你去哪），OPD 的 teacher 是更强的可学习信号源（监督项，指引你去哪）。选型：学生≈teacher（自蒸馏压缩）可用 forward；学生显著弱（7B 学 72B）reverse/OPD 更稳。

## 二、训练诊断

**问题：训练 loss 震荡/发散怎么定位？**

回答：按数据、超参、工程三个方向排查按改动成本从低到高。①超参面：lr 过大最常见（降一个数量级试跑），其次 KL 系数过小（RL 阶段策略漂移）、clip 范围过大；②数据面：新混批次分布突变或脏样本——记录每个 batch 的样本 id，震荡 batch 的数据单独回放复现（能复现=数据问题），查新数据的长度分布/重复度/标签噪声；③工程面：并行 rollout 不同步（部分 worker 用旧权重）、梯度累积边界错误（loss 归一化口径不一致）、bf16 数值溢出（grad-norm 同步爆炸则查 attention score 的 -inf 处理）。工具化：loss / grad-norm / KL / entropy 四条曲线按 batch 粒度 + batch 级数据索引。loss spike 的标准处置是自动回滚到最近稳定 checkpoint 再离线归因，不带病训练。区分两类 spike：数值 spike 通常 grad-norm 同步爆炸、loss 面无先兆；数据 spike 前后 batch 正常、可定位到具体样本。

**问题：CPT/垂域继续预训练后通用能力掉点怎么办？**

回答：标准解法三条，外加一个激进方案。①replay：混入通用语料（垂域:通用从 3:7 到 7:3 按目标垂化强度扫描定，通用数据的作用是对抗遗忘而非凑比例——选"原预训练配比的缩小版"，指令/代码/数学按原比例缩）；②调度：[WSD](https://arxiv.org/abs/2404.06395)（warmup-stable-decay）的 decay 段提高通用高质量数据占比做"退火回正"（decay 段数据质量对最终能力影响极大）；③监控：固定通用回归集（MMLU/C-Eval/代码/数学抽样）每 N 步测，掉点超阈值（如 >3pp）触发回滚或加 replay。激进方案 [LLaMA Pro](https://arxiv.org/abs/2401.02415) 式 block expansion：冻结全部原层、插入恒等初始化的新层只训新参数——恒等初始化保证训练起点与原模型等价、旧层不受梯度直接破坏从而大幅缓解遗忘，可增量叠加，代价是总参上涨推理变慢。replay 比例不给固定单值、按方法定：垂域评测与通用回归双目标网格扫描（5:5/6:4/7:3 三档），选两目标都达标的边界点。

**问题：LoRA 的秩 r 是什么意思？α 呢？推理有开销吗？**

回答：[LoRA](https://arxiv.org/abs/2106.09685) 把权重更新约束为低秩分解 $`\Delta W = BA`$，$`A\in\mathbb R^{r\times d}`$ 初始化高斯、$`B\in\mathbb R^{d\times r}`$ 初始化为零（训练开始时 ΔW=0 不破坏原模型）。r 的语义是允许权重更新的子空间维度上界（$`\mathrm{rank}(\Delta W) \le r`$，即"允许模型改变多少个方向"），不是"中间那两个维度"这种模糊说法——r=8/16/32 覆盖大部分微调需求，任务与原分布差异越大（新语言、新模态）需要的 r 越大甚至全参。α 是缩放系数：前向 $`h = Wx + \frac{\alpha}{r}BAx`$，α/r 的意义是把更新幅度与 r 解耦（调 r 不用同步改 lr 的等效补偿），常用 α=2r 或 α=r。推理零开销：$`W' = W + \frac{\alpha}{r}BA`$ 合并后与原模型结构完全相同——这是相对 Adapter/P-tuning 的核心优势：不改结构、不加层、不占上下文，部署侧零感知。

## 三、模型结构

**问题：把一个 decoder-only Transformer 从 token id 到 logits 的完整流程按张量形状讲一遍？**

回答：前向按张量形状分五段。① embedding：token id 查表得 $`X\in\mathbb R^{B\times L\times d}`$（7B 档 d=4096），RoPE 模型不加任何绝对位置向量。② attention 子层：pre-norm 后 $`Q=XW_Q,\ K=XW_K,\ V=XW_V`$，reshape 为 $`B\times h\times L\times d_h`$（$`d_h=d/h`$，常取 128），Q/K 施加 RoPE 后算 $`\mathrm{softmax}(QK^\top/\sqrt{d_h}+M)V`$——$`QK^\top`$ 的形状是 $`B\times h\times L\times L`$，这是序列长度二次复杂度的来源；$`M`$ 为因果掩码（上三角 −∞）叠加 padding 掩码，加在 softmax 之前；输出 concat 回 $`B\times L\times d`$ 过 $`W_O`$，与输入残差相加。③ FFN 子层：第二个 pre-norm 后 SwiGLU 三投影 $`d\to d_{ff}\to d`$（$`d_{ff}\approx 8d/3`$，d=4096 对应 11008），再残差。④ 堆叠 N 层（7B 档 32 层）后过 final norm，LM head 出 logits $`B\times L\times V`$（常与 embedding 权重共享），交叉熵只算被监督的位置。实现级易错点四处：reshape 与 transpose 的顺序、transpose 后要 contiguous 才能再 view、残差不能丢、KV cache 场景 RoPE 施加在写 cache 之前。

**问题（追问）：注意力的时间和空间复杂度是多少？FlashAttention 改了什么？**

回答：标准实现时间复杂度 $`O(L^2 d)`$（$`QK^\top`$ 与 $`\mathrm{attn}\cdot V`$ 两个矩阵乘主导），显式落 $`L\times L`$ 注意力矩阵使空间 $`O(L^2)`$。[FlashAttention](https://arxiv.org/abs/2205.14135) 不改变复杂度的阶，把 Q/K/V 分块装入 SRAM、用 online softmax 单遍完成计算且不落完整注意力矩阵——空间降到 $`O(L)`$、实测 2~4 倍加速，收益来自 IO 感知（HBM 与 SRAM 之间的搬运量）而非 FLOPs 减少，反向靠重算注意力矩阵。它是精确 attention，数学结果与标准实现一致（浮点归约顺序差异除外），所以是现代训练的默认开关而不是可选优化。

**问题：Self-Attention 里为什么要除以 √d_k？为什么要多头，计算量变大了吗？**

回答：缩放是方差控制。设 q、k 各维独立、均值 0、方差 1，点积 $`q\cdot k=\sum_{i=1}^{d_k}q_i k_i`$ 的方差随 $`d_k`$ 线性增长；$`d_k`$ 大时点积量级大，softmax 被推到饱和区、输出接近 one-hot、梯度趋零，数值上也易溢出。除以 $`\sqrt{d_k}`$ 后点积方差回到 1，softmax 落在梯度敏感区间——注意除的是单头维度 $`d_h`$ 而不是模型维度 d。多头把 d 维拆成 h 个子空间各自算注意力再拼接，让不同头学不同关系模式（局部搭配、长程指代、位置模式）。计算账：单头注意力 $`O(L^2 d)`$，多头每头 $`O(L^2 d_h)`$、h 头合计仍 $`O(L^2 d)`$，投影矩阵也是同一组 $`d\times d`$ 按头切分——表达能力的提升基本免费。工程边界两条：实际开销略高（reshape/transpose 的内存布局操作、h 个小矩阵乘的并行效率低于一个大矩阵乘）；$`d_h`$ 过小单头表达不足，实践中 $`d_h`$ 取 64 或 128，头数由 d 反推。

**问题：RoPE 为什么能表达相对位置？为什么要用多组不同频率？**

回答：[RoPE](https://arxiv.org/abs/2104.09864) 把 d 维特征两两配对成 $`d/2`$ 个二维平面，位置 m 处第 i 个平面旋转角 $`m\theta_i`$、$`\theta_i=10000^{-2i/d}`$。相对性来自旋转矩阵的代数性质：$`\langle R_m q,\ R_n k\rangle=\langle q,\ R_{n-m}k\rangle`$——注意力分数只依赖位置差 $`n-m`$，不需要显式的相对位置偏置项。多组频率的必要性三层：① 唯一性——单一频率的周期是 $`2\pi/\theta`$，位置差为周期整数倍时编码重合，多频率的整体重复周期是各周期的最小公倍数、远超实际序列长；② 多尺度分辨——高频平面旋转快、对相邻位置敏感、编码局部顺序，低频平面在长距离上才产生显著相位差、编码全局位置，几何级数排布与傅里叶基同构；③ 外推基础——低频分量在训练长度内转不满一个周期、相位与位置近似线性，这是插值类外推方法的支点。边界：RoPE 只作用于 Q/K 不作用于 V；其"长距离衰减"是期望倾向而非严格单调，远程检索能力仍要靠训练数据建立。

**问题（追问）：4K 训练的模型怎么外推到 128K？NTK 插值和 YaRN 分别改了什么？ALiBi 那条路线呢？**

回答：RoPE 外推有三代做法。① 位置插值（PI）：位置索引等比压缩 $`m\to m/s`$（s 为外推倍数），所有频率被一起拉低，高频分量的局部分辨率被稀释，必须配少量长文续训才能用；② NTK-aware 插值：按频率分档，高频少插、低频多插，保住短距离分辨，把免训外推倍数从约 2 倍提到 4~8 倍；③ [YaRN](https://arxiv.org/abs/2309.00071)（NTK-by-parts）：按波长分 ramp——波长短于上下文的维度不插值、波长远长于上下文的纯插值、中间平滑过渡，再乘温度系数补偿注意力熵的漂移，配几百 M 到数 B token 的长文续训可稳定到 128K（Qwen2.5 系即此路线）。共同代价：扩窗只抬高上限，中段信息利用（lost in the middle）要靠数据与任务设计解决；验收看分档衰减曲线的断崖位置而非单点分，[RULER](https://arxiv.org/abs/2404.06654) 类检索分与真实长文理解存在差距。ALiBi 是另一条路线：Q/K 不加位置编码，注意力分数直接加线性距离惩罚 $`-r\cdot|i-j|`$（r 按头取几何级数），外推天然平滑，但偏置固定不可学、长程检索弱于 RoPE 系，现代基座主流仍是 RoPE 加插值续训。

**问题：KV cache 存的是什么、显存怎么算？GQA、MQA、MLA 分别怎么把它压下去？**

回答：KV cache 存每层每头每个已生成 token 的 K 与 V：显存 $`=2\times N_{layer}\times n_{kv}\times d_h\times T\times B\times`$ 字节数。以 7B 档（32 层、$`n_{kv}=32`$、$`d_h=128`$、bf16）计，单条 8K 序列约 4.3 GB——长序列与大 batch 下它是推理显存主因，[PagedAttention](https://arxiv.org/abs/2309.06180) 的分页块管理正是为治它的碎片与超额预留。只存 K/V 不存 Q：Q 只服务当前位置、下一 token 的 Q 重新算，K/V 参与所有后续位置的注意力。压缩三路：① [GQA](https://arxiv.org/abs/2305.13245) 把 Q 头分 g 组、组内共享一份 KV，cache 降为 $`1/g`$（32 Q 头配 8 KV 头即 1/4），LLaMA-2/3 与 Qwen 全系采用，是表达力与显存的常用折中；② MQA 全部头共享一份 KV，压缩最激进、表达损失最明显；③ [MLA](https://arxiv.org/abs/2405.04434)（DeepSeek-V2/V3）不共享而做低秩压缩：KV 联合投影为低维 latent 向量（$`d_c=512`$）外加 64 维解耦 RoPE 分量，只缓存这两者，注意力时上投影恢复各头 K/V——压缩率接近 MQA 而保留各头差异化表达。工程边界：GQA 的 KV 头数要能被 TP 度整除（不足则复制）；MLA 省的是推理 cache，训练侧前向仍是完整注意力。

**问题（追问）：MLA 说的"矩阵吸收"是什么意思？**

回答：naive 的 MLA decode 是 latent 先上投影还原完整 K/V 再算注意力，压缩省下的显存又在计算中还原。吸收利用线性结合律：注意力分数 $`q^\top(W_{UK}\,c)`$ 可改写为 $`(q^\top W_{UK})\,c`$——上投影矩阵 $`W_{UK}`$ 预先乘进 Q 侧，输出侧把 $`W_{UV}`$ 吸进 $`W_O`$，于是直接用 latent 向量做内积，全程不实例化完整 K/V，FLOPs 与显存双省。代价是 RoPE 无法施加在压缩后的 latent 上（旋转与上投影不对易），所以要单独保留一路不压缩的 64 维位置分量（decoupled RoPE）——这是 MLA 结构复杂度的来源，也是它相对 GQA 实现成本高的原因。

**问题（追问）：prefill 和 decode 的瓶颈分别是什么？**

回答：prefill 一次算完整个 prompt 的 QKV 与注意力，矩阵乘大、GPU 打满，是算力受限；decode 每步只算一个 token 的前向，却要读全部权重与历史 KV cache，算术强度极低，是显存带宽受限。工程推论三条：decode 提速靠压缩 KV 读取量（GQA/MLA、KV cache 量化）与增大并发（continuous batching 把富余带宽换成吞吐）；两阶段硬件画像不同是 PD 分离部署的依据；长 prompt 场景 prefill 的 $`L^2`$ 注意力会成为首 token 延迟主因，这是稀疏/滑窗 attention 的切入点。

**问题：RMSNorm 和 LayerNorm 有什么区别？Pre-norm 和 Post-norm 又差在哪？**

回答：LayerNorm 对激活做 $`\frac{x-\mu}{\sqrt{\sigma^2+\epsilon}}\gamma+\beta`$，减均值、除标准差、带平移参数；[RMSNorm](https://arxiv.org/abs/1910.07467) 去掉均值中心化，只做 $`\frac{x}{\sqrt{\mathrm{mean}(x^2)+\epsilon}}\gamma`$。三点差异：① 计算——RMSNorm 少一次均值归约与减均值广播，norm 本身占整网比例小，收益在零风险简化；② 动机——LayerNorm 的再中心化假设在 LLM 上不关键，再缩放不变性已够，LLaMA/Qwen/DeepSeek 全系 RMSNorm；③ 数值——RMSNorm 输出均值不为零、残差流带系统性偏置，深网下靠 pre-norm 结构与初始化消化。Pre-norm 与 Post-norm 的分歧是 norm 放子层内还是外：Post-norm（[Attention Is All You Need](https://arxiv.org/abs/1706.03762) 的原始结构，$`x+\mathrm{sublayer}(x)`$ 之后再 norm）深网训练不稳、依赖小心的 warmup 与初始化，但收敛后表达上限略高；Pre-norm（先 norm 再进子层、残差直通到底）梯度有恒等通道、上百层也稳，代价是残差流主导、各层贡献被稀释，超深网出现"深度浪费"，折中变体有 DeepNorm 式残差缩放。现代基座默认 Pre-norm 加 RMSNorm。

**问题：FFN 从 ReLU 到 SwiGLU 演进改了什么？SwiGLU 为什么中间维取 2/3 左右？**

回答：FFN 演进主线是 ReLU → GELU（BERT/GPT-2 起）→ [SwiGLU](https://arxiv.org/abs/2002.05202)（PaLM/LLaMA 起成主流）。SwiGLU 属门控线性单元：$`\mathrm{SiLU}(xW_g)\odot(xW_u)`$ 再过 $`W_d`$，其中 $`\mathrm{SiLU}(x)=x\sigma(x)`$——三个投影矩阵，一支经激活当门控、与另一线性支逐元素相乘，给逐位置信息流一个可学习的乘性开关；相对单激活 FFN 多了门控路径，经验上同参数量收敛更快、下游更好。2/3 是参数配平：标准 FFN 两矩阵参数量 $`2\cdot d\cdot d_{ff}`$（$`d_{ff}=4d`$），SwiGLU 三矩阵 $`3\cdot d\cdot d'_{ff}`$，令总量相等得 $`d'_{ff}=8d/3`$——LLaMA 在 d=4096 时取 11008（$`8d/3\approx10923`$ 向上对齐到 256 的倍数）。边界两条：门控乘法使激活分布更尖、低 bit 量化时门控支是敏感点；小模型或训练预算很短时 SwiGLU 的收益不一定盖过额外的调参成本。

**问题：7B 模型 bf16 推理要多少显存？全参训练的显存账又怎么算？**

回答：推理侧：权重 $`7\times10^9\times2\,\text{B}=14\,\text{GB}`$，加 KV cache（随 batch 与长度线性增长，口径见 KV cache 一题）与框架常驻开销，单卡 24 GB 紧张、32 GB 稳妥。训练侧按 bf16 混合精度加 [AdamW](https://arxiv.org/abs/1711.05101) 计字节/参数：bf16 权重 2 + bf16 梯度 2 + fp32 主权重 4 + fp32 一阶矩 4 + fp32 二阶矩 4 = 16 B/param，7B 约 112 GB——单卡 80 GB 放不下，这就是 ZeRO-3/FSDP 分片的动机；激活另计，与 batch、序列长、重算配置强相关，32K 序列下激活可超过参数侧。速记口径：1B 参数全参训练约 16~20 GB（含余量），14B 全参约 230 GB 必须分片。FLOPs 估算：前向约 $`2ND`$、含反向约 $`6ND`$（N 参数量、D token 数）。

**问题（追问）：用 6ND 怎么估一次训练要多久？**

回答：时间 $`=6ND/(N_{gpu}\times`$ 单卡有效算力 $`)`$，有效算力按 MFU 折算——H100 bf16 峰值 989 TFLOPS，成熟训练栈 MFU 常见 35~50%，即单卡有效 350~500 TFLOPS。算例：7B 训 1T token，$`6\times7\times10^9\times10^{12}=4.2\times10^{22}`$ FLOPs，512 卡按 400 TFLOPS/卡约 57 小时。边界三条：6ND 只算矩阵乘主干，embedding/大词表 softmax/通信另计；全开梯度检查点约多一遍前向，按 8ND 估；MoE 用激活参数量代入 N，但专家路由的通信与负载不均会压低实际 MFU。

**问题：BPE 分词的原理是什么？词表大小怎么权衡？**

回答：BPE 自底向上合并：从字符（或字节）级词表出发，统计语料中相邻 token 对的频率，反复合并最高频对为新 token 直到词表预算用完；编码时按合并顺序贪心应用同一张表。词表大小的权衡两端：词表大——序列变短（训练推理的序列成本下降、长程依赖的 token 距离缩短）、低频词不被切碎，代价是 embedding 与 LM head 参数上涨（152K 词表乘 4096 维约 6.2 亿参数，小模型上占比可观）、稀有 token 训练不充分（出现次数太少的嵌入学不好）；词表小——参数省、统计充分，但序列膨胀，中文与代码被切得过碎（字节级回退时一个汉字占 2~3 token）。公开锚点：GPT-2 约 50K（英文中心）、LLaMA 32K、Qwen2/3 约 152K（多语言与代码倾斜）、DeepSeek 约 100K——多语言模型普遍放大词表换 fertility（每词平均 token 数）下降。工程边界三条：词表大小要能被 TP 度整除（embedding 按词表维切分）；改词表等于换 embedding，续训中扩词表要配重初始化与额外预算；tokenizer 与 chat template 是训推不一致的高发源头，special token id 错位会静默掉点。

## 四、优化器与训练工程

**问题：AdamW 和 Adam 的区别是什么？β、ε、weight decay 的典型值是多少？**

回答：[AdamW](https://arxiv.org/abs/1711.05101) 把 weight decay 从梯度中解耦。Adam 里 L2 正则项进梯度后被自适应步长 $`\hat m/\sqrt{\hat v}`$ 缩放——梯度大的参数 decay 被压小，正则强度逐参数失真；AdamW 把衰减直接施加在权重上：$`\theta\leftarrow\theta-\eta\,\hat m/(\sqrt{\hat v}+\epsilon)-\eta\lambda\theta`$，衰减与梯度统计无关，正则强度全网络一致。典型值：LLM 预训练 β1=0.9、β2=0.95（大 batch 下二阶矩要快忘旧统计；小 batch 微调常用 0.999）、ε=1e-8、wd=0.1（LLaMA/Qwen 口径，SFT 常降到 0.01~0.1）；lr 量级：预训练峰值 1.5e-4~3e-4（7B 档）、SFT 1e-5~2e-5、RL 5e-7~1e-6。边界两条：wd 不施加在 norm 参数与 bias 上（一维参数衰减会破坏归一化尺度）；β2 与 batch 耦合，batch 翻倍时 β2 向 1 靠（0.95→0.98）二阶估计更稳。新进展可提一句：[Muon](https://arxiv.org/abs/2502.16982) 把动量做 Newton-Schulz 正交化后更新二维参数矩阵，Kimi/Moonshot 系已用于主训，样本效率优于 AdamW，但 embedding 与 norm 侧仍回退 AdamW。

**问题（追问）：weight decay 和 lr 是什么关系？调一个要不要动另一个？**

回答：解耦只是梯度上的解耦，有效正则强度是乘积 $`\eta\lambda`$——lr 减半而 wd 不动，实际衰减强度同样减半。两个推论：扫 lr 时 wd 要按比例联动，否则两组实验比较的不是同一个正则强度；cosine/WSD 的 decay 段 lr 趋零时衰减同步趋零，末期等价于无正则精修。部分工作直接报 $`\eta\lambda`$ 乘积就是为了这个可比性。

**问题：warmup 为什么需要？cosine 和 WSD 两种调度怎么选？**

回答：warmup 治训练初期的两类失稳：Adam 二阶矩从零起步、初期估计偏差大，大 lr 直接上会沿噪声方向大步走、表现为开局 loss 尖峰；深网（尤其 post-norm）的梯度尺度尚未建立。做法是线性升到峰值，步数占总预算约 1~3%（GPT-3 为 375M token 对应总 300B）。调度对比：cosine 一条曲线平滑到底，适合预算与数据一次性确定的一次性训练；[WSD](https://arxiv.org/abs/2404.06395) 主体段常数 lr、最后 10~20% 预算线性或余弦退火到近零。WSD 的工程优势三条：stable 段 checkpoint 可随时分叉续训加数据、不必重跑整条 cosine；decay 段集中注入最高质量数据做退火精修，该段数据质量对最终能力影响极大；多阶段 CPT 与扩窗天然衔接（稳定段末 checkpoint 连同优化器状态交付，一阶/二阶矩缺失会让自适应步长在接续初期失真）。代价：stable 段中途 snapshot 略逊于同期 cosine（尚未退火收敛）；退火终点要到近零（峰值的 0.3% 量级）而非 10%——AdamW 参数可视作历史更新的指数移动平均，末端 lr 降零压制梯度方差。

**问题（追问）：从已收敛模型做 CPT 续训，学习率怎么接？要重新 warmup 吗？**

回答：续训的 lr 比原预训练峰值低约一个数量级（1e-6~1e-5 量级），并配几百步的短 warmup（约总步数 1~2%）——直跳目标值会造成初期 loss 尖峰，续训初期模型处于"重建领域分布"的过程，各候选数据集的差异被整体漂移掩盖。WSD 体系下从 stable 段末 checkpoint 分叉则带优化器状态接续、不重 warmup。多档扩窗（8K→32K→128K）每档切换做一次小幅 rewarm（当前值的 1/3 量级）抵消窗口切换的分布突变，末档之后补一个短退火收尾；一步跳到目标长度会造成注意力分布骤变与 loss 尖峰。

**问题：梯度裁剪怎么做的？clip 阈值怎么定？**

回答：裁剪作用于全局梯度范数而非逐参数：所有参数的梯度拼起来算 L2 范数 g，超过阈值 c 就整体乘 c/g——方向不变、幅度封顶，防止个别大梯度样本把参数一步带飞。LLM 训练的事实标准是 clip=1.0（GPT-3/LLaMA 口径，SFT 与 RL 沿用）。注意两个 clip 别混：梯度裁剪管参数更新幅度，PPO/GRPO 的 ratio clip 管策略偏离幅度，两者正交。阈值标定：不裁剪先跑几百步记录 grad-norm 分布，取 P95~P99 附近；运行中 grad-norm 本身是诊断信号——持续贴顶说明 lr 偏大或有脏样本，突刺对应 loss spike，bf16 溢出时 grad-norm 先爆 NaN。边界：裁剪引入偏置（大梯度方向被系统性压短），噪声大的小 batch 训练裁太紧会拖慢收敛；逐参数裁剪会让更新方向失真，无特殊理由不用。

**问题：bf16 和 fp16 差在哪？混合精度为什么还要 master weights 和 loss scaling？**

回答：两种格式同为 2 字节：fp16 是 1 符号位 + 5 指数位 + 10 尾数位，动态范围约 ±65504、精度高；bf16 是 1+8+7，指数位与 fp32 相同、动态范围一致，尾数少、精度低（大数间隔约 0.8%）。训练默认 bf16 的原因：LLM 训练的主要数值风险是溢出而非精度——fp16 下激活与梯度易超 65504 出 NaN，必须配 loss scaling（loss 乘大系数 S 把梯度抬进可表示区间、更新前除回，S 动态调整：溢出减半、长期不溢出翻倍）；bf16 几乎不溢出、可免 loss scaling。master weights 不可省：单步更新量相对权重常在 $`10^{-3}`$ 以下，bf16 的 7 位尾数会把"权重加小更新"四舍五入回原值、更新被吞掉，所以优化器在 fp32 主权重上累加，前反向再转 bf16，一阶/二阶矩同样 fp32。配套口径：softmax、norm 的归约、跨卡 all-reduce 通常也留 fp32；bf16 的精度短板在长链累加（大词表 softmax 分母）上显形，kernel 内部用 fp32 累加器兜住。

**问题（追问）：推理侧为什么反而常见 fp16？**

回答：推理没有梯度、没有更新被吞的问题，动态范围需求也小（权重与激活有界、远低于 65504），fp16 多出的 3 位尾数换来更好的精度，所以推理部署 fp16 与 bf16 都可行、历史栈 fp16 更多；训练侧 bf16 是默认。再往下压（INT8/FP8）属量化路线，要配校准与 scale 管理，FP8 分 E4M3（精度优先，前向）与 E5M2（范围优先，梯度）两档，Hopper 起有原生支持。

**问题：梯度累积和梯度检查点分别拿什么换什么？**

回答：梯度累积：显存换等效大 batch。global batch 切成 N 个 micro batch 串行前反向、梯度原地累加、最后统一 step——激活显存按 micro batch 计、等效 batch 按 global 计，换算 $`N_{accum}=\text{global}/(\text{DP}\times\text{micro})`$。代价：kernel 启动与通信占比上升使吞吐略降，梯度同步间隔变长后 lr 要按大 batch 重调；LLM 无 BN 类跨样本统计，语义上与真大 batch 等价。梯度检查点：算力换显存。前向只存段边界激活、反向时从最近边界重算该段——全量重算把激活显存从 O(层数) 压到 O(√层数) 量级，代价约 +33% 前向 FLOPs（6ND 变 8ND）；选择性重算只重算 attention 核（$`L^2`$ 激活那段），激活大头消掉而代价只有几个百分点，是长序列标配。选型次序：显存够就不开；先开选择性重算，仍不够再全量；32K 以上序列基本必开其一，并与 FlashAttention 的原生重算配合。

**问题：ZeRO 三个阶段各切什么？通信代价是什么？**

回答：ZeRO 消除数据并行下"每卡一份完整状态"的冗余，三阶段递进。ZeRO-1 切优化器状态：每卡只持 $`1/N`$ 的 fp32 主权重与两个动量（显存最大头，约 12 B/param），step 时各卡更新自己的分片再 all-gather 参数，通信量与标准 DP 基本持平。ZeRO-2 加切梯度：反向用 reduce-scatter 替代 all-reduce，每卡只留自己分片的梯度，通信量仍与 DP 相当。ZeRO-3 加切参数：每卡常驻 $`1/N`$ 参数，前向与反向按层 all-gather 出完整参数、用完释放——显存随卡数近似线性下降，代价是通信量约为标准 DP 的 1.5 倍且对带宽敏感。实现上张量展平成一维等分切而非按语义维切：负载天然均衡、与模型结构解耦，代价是单张量可跨卡、通信要按参数组重组。边界：ZeRO-3 跨机 all-gather 走 IB 易成瓶颈，常配机内满切加机间 DP，或叠 TP；FSDP 是 PyTorch 对 ZeRO-3 思想的原生实现（full_shard 对应 ZeRO-3）。

**问题（追问）：ZeRO-3/FSDP 和 TP 的区别是什么？**

回答：ZeRO-3 切的是状态存储、不改计算图——前向要把完整参数 all-gather 出来再算，通信发生在参数同步层；TP 切的是矩阵乘本身（MLP 列切加行切、attention 按头切），每卡只算自己那片，通信发生在算子内部（每层两次 all-reduce）。三个推论：TP 降低单卡计算量、ZeRO 不降；TP 必须机内 NVLink，ZeRO-3 可跨机但吃带宽；两者可叠加，常见组合是机内 TP 乘机间 ZeRO 或 DP。

**问题：单机 8 卡训 70B 级模型，TP/PP/DP 怎么切？TP 为什么不跨机？**

回答：选择次序是 DP 优先（通信最少、只有梯度同步），显存放不下才引入 TP/PP：TP 只在机内（NVLink 数百 GB/s 级），PP 与 DP 跨机（通信频率低）。单机 8 卡 70B 的典型切法：TP8 机内（每卡权重 17.5 GB bf16 加分片优化器状态）或 TP4×PP2；多机如 64 卡扩为 TP8×PP4×DP2 形态。TP 不跨机的定量理由：TP 每层前向两次 all-reduce、反向再两次，通信量按 $`2D(TP-1)/TP`$ 增长且是每 micro step 的固定开销、不随 batch 摊薄——机间 IB 带宽只有 NVLink 的约十分之一，跨机 TP 会把训练变成等通信；PP 每个 stage 边界只传一次激活，气泡可用 1F1B 与 interleaved 调度压到个位数百分比，天然适合跨机。两个配套约束：GQA 模型 KV 头数要能被 TP 度整除（不足则复制 KV 头）；MoE 再叠 EP，EP 与 TP 正交、专家 all-to-all 尽量留在机内。

**问题（追问）：TP8 是不是比 TP4 算得更快？**

回答：不是。NVLink 带宽固定，TP 变大不提高链路带宽，只改变通信与计算的比值：通信量从 TP4 的 1.5D 涨到 TP8 的 1.75D（+17%）而单卡计算量减半，算术强度掉到约 43%，TP 越大越久在等通信；同时集合通信次数不变、参与卡数翻倍使环形算法的传播延迟更长。显存结构上两者分工不同：TP 只切参数与状态、层数不变，PP 把层数对半切、参数/梯度/状态/激活同时减半。对稠密小模型单机 8 卡，理论最优是纯 DP，TP/PP 是目标 batch 与序列长度下放不下时才引入的手段——"TP 拉满更快"是常见误判。

## 五、数据与评测

**问题：预训练数据的清洗漏斗分哪几级？为什么是这个顺序？**

回答：四级漏斗按单样本处理成本递增组织，每层只处理上层存活的样本。① 规则层：格式清理（HTML/PDF 抽取修复、去模板噪声）、字符集与长度规则、PII 与许可证过滤，成本近零、砍掉最明显的垃圾；② 去重层：文档级精确哈希加 MinHash-LSH 近重，必须在打分前做——重复样本会污染打分统计且浪费打分算力；③ 质量打分层：fastText 级分类器或小模型 PPL 过滤全库打分，PPL 用 0.5~1.5B 小模型承担、设上下双阈值（过高判乱码与多语混杂，过低判模板堆砌与机翻）；④ 精细分级层：LLM 评判器多维打分，或用下游退火实验标定的分类器分档，高档料留给 decay 段上采样。真实量级锚点：1.1T 原始语料四级过滤后留约 360B，逐层保留率 100%→80%→62%→55% 这类口径常见。边界：每层阈值先在"应留/应删"人工抽样集上标定、再用下游指标复核；过滤过狠伤长尾知识召回，规则层对代码与表格的误删高发。

**问题：去重分哪几级？MinHash 的原理是什么？阈值怎么定？**

回答：去重按粒度与成本分三级。① 精确去重：URL 或文档级哈希，去掉完全重复，成本近零；② 近重去重：MinHash-LSH 文档级——文档表示为 n-gram 集合，用 k 个哈希函数各取集合最小哈希值构成签名，利用 $`\Pr[h_{\min}(A)=h_{\min}(B)]=\mathrm{Jaccard}(A,B)`$ 把相似度估计转成签名比较，签名分 band 进 LSH 桶、同桶即候选近重对，把 O(N²) 两两比较压到近似线性；③ 语义去重：embedding 近邻（cosine 0.9 量级）抓换皮改写，成本高，只用于高价值子集（SFT 数据与评测防污染）。MinHash 阈值即 Jaccard 相似度，语料级常用 0.8 上下（实见 0.78~0.85）。标定方法：抽样标注一批"应判重/不应判重"的文档对，扫阈值看误删率与漏重率（或看 Jaccard 分布的双峰间隙），再结合下游指标复核——阈值过低误删同模板不同实例（商品详情页、boilerplate 重的代码），过高漏重导致训练冗余与评测泄漏。配套两条：评测集对训练集要跑同一套近重检测（n-gram 重合率）；去重粒度可分文档、段落、句子三级，语料级别越细越保数据量。

**问题：训练数据的配比怎么定？**

回答：三条方法按成本递增。① 参照系复用：沿用公开技术报告的域配比（网页/代码/数学/多语言）作先验，垂域 CPT 按"原预训练配比的缩小版"抽通用回放集——回放的作用是保能力不是凑比例；② 小规模网格扫描：1~3B proxy 模型上扫档位（垂域:通用取 3:7/5:5/7:3），以垂域评测与通用回归双目标选两目标都达标的边界点——proxy 的配比结论保排序不保绝对值；③ 退火探针：主训中段冻结基点分支出数 B token 的退火支路，实测各候选语料的边际增益排序，把增益当相对权重定 decay 段配比，成本最高、结论最硬。动态配比：WSD 主体段与 decay 段配比不同，decay 段上采样高质量料；去掉通用回放后通用退化可翻倍。监控口径两条：配比按 token 计不按条数（长度分布差异会让条数配比骗人）；训练中按域分桶盯验证 loss。

**问题（追问）：SFT 阶段多任务混合会不会跷跷板？怎么办？**

回答：会，任务间梯度冲突与难度不均让弱任务被强任务吃掉，而总 loss 平稳时跷跷板已在发生——所以监控必须看逐任务准确率曲线。处置四条：① 按能力缺口定向补数而非等比混——先跑 baseline 找短板任务，对短板类定向 1:1 补样本；② 分桶限量，防高频模式淹没长尾；③ 通道化——异构目标（长 CoT 推理与短直答）拆通道、system prompt 打标签、各通道独立 loss 权重，比硬混稳定；④ 两阶段——先混训打底，末期短退火段上采样弱任务。

**问题：评测集怎么构造才可信？**

回答：构造五要素。① 来源隔离：训练与评测按"源"划分而非按"条"——同仓库、同文档、同模板族的样本只出现在一侧，题面与参考解不进训练语料；② 难度标定：用 pass@k 或人工分层给难度先验，全对与全错的题不进统计（无区分度）；③ 判定可复现：能执行判定就不用模型打分，LLM-as-judge 要 rubric 分维度独立打、多次采样聚合、与人工标注校准系统性偏置；④ 规模按置信区间定：500 题 ±2pp 的口径比 100 题 ±5pp 有用，报告带置信区间；⑤ 防过拟合机制：held-out 集与公开 benchmark 互为校验，公开榜涨而 held-out 不涨即过拟合警报。边界两条：自建集测相对变化不测绝对水位，横向对比仍要公开基准；评测模板（prompt、few-shot、答案解析器）必须冻结并写进评测卡，否则前后分数差里混入模板差异。

**问题：训练数据与评测集之间的污染怎么查、怎么防？**

回答：查与防两条线。查两道：① n-gram 重合——评测样本对训练语料算 8~13-gram 重合率（GPT-3 用 13-gram，重合即删或标记），n 太小误伤常见短语、太大漏掉改写；② 语义级——embedding 近邻补抓换皮改写，高价值评测集必做。防三条：① 时间切分——评测集来源的发布时间晚于训练语料快照截止日，对新题类榜单有效、对沉淀多年的经典题无效；② 入库门禁——训练语料入库前对评测库全量跑去重，命中即删并记录；③ 变体探针——对疑似污染题做数值与实体改写重测，分数骤降说明记住的是原题而非能力。边界两条：污染检测只能证重合不能证因果，报告应同时给重合率与去重合后的分数；agent 时代还有轨迹级污染（工具返回与环境里带答案），要靠环境侧注入隔离（truth 只在判分阶段注入）。

**问题：perplexity 的口径是什么？为什么不能拿它当主指标？**

回答：$`\mathrm{PPL}=\exp(-\frac1N\sum_i\log p_\theta(x_i\mid x_{<i}))`$，逐 token 平均负对数似然的指数。可比性要钉死四个口径：同分词器（词表不同 PPL 不可比）、同语料与长度分布、同上下文窗口口径、同归一化分母（按 token 不按句）。正当用途三个：同一模型不同 checkpoint 的单调比较、数据质量的异常拦截（双向 PPL 设上下阈值）、领域分布拟合的趋势判断。局限三条：① 与下游准确率弱相关——PPL 对全部 token 等权，而下游表现由少量关键 token（答案实体、数值、代码符号）决定，垂域 PPL 降三成可能只换下游涨两点；② 对记忆与泛化不敏感——背下来的语料 PPL 同样低；③ 跨模型跨分词器不可比。落地口径：PPL 只做趋势判断与质量门禁，排名与验收用下游任务指标；对外报 PPL 必须附完整口径，否则数字无意义。

**问题：pass@k 和 majority vote 分别度量什么？k 怎么定？**

回答：pass@k 度量能力上界：同题独立采样 k 条、至少一条正确的比例，报告时用无偏估计 $`1-\binom{n-c}{k}/\binom{n}{k}`$（n 总采样数、c 其中正确数，n 大于 k 以压低估计方差）。majority vote（self-consistency）度量共识可靠性：k 条答案投票取多数，依据是正确推理路径殊途同归、错误路径各自分散的经验性质；不需要验证器，但只适用于答案可聚合的任务（数学、选择题），代码补丁这类结构化产物不能直接投票。k 按用途定：能力上界评估报多档（1/8/16，RL 后训练常用 16 档看可挖掘空间）；投票 8~16 条边际收益已递减。选优场景三个数要并列报：pass@k（上限）、TTS@k（经验证器或投票选优后的实际值）、归一化比值 $`(\text{TTS}-P_1)/(P_k-P_1)`$（选优机制吃下了多少理论收益）。边界两条：pass@k 高不等于可用——没有可靠选优机制时线上仍是 pass@1；模型有系统性偏置时投票会一致地错，温度过低则 k 条趋同、投票退化。

**问题（追问）：pass@k 低是不是就说明任务难？**

回答：不能直接等价。pass@k 低有三类归因：任务本身难（触到能力边界）、题目质量差（题面歧义、参考答案错）、环境缺陷（依赖装不上、测试 flaky）。分离靠三道闸：空转验证（不做题直接跑测试，基线应通过）、参考解验证（gold patch 必须通过全部测试）、异构模型复核（换一家旗舰模型仍 pass@k=0，更指向题或环境坏而非难）。可验证任务入库的完整口径是 F2P 成立（只打测试补丁须失败）、oracle 可达（打金标准须全过）、P2P 不破坏（回归用例不受影响）三闸全过——三类归因在真实项目里各占相当比例，单凭 pass@k 低就标"难"会把坏题喂进 RL。
